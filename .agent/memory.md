## Stack (M1 trusted core) — SOTA picks over human-popular defaults
- Runtime: `uv` src-layout single pkg `verifier` (+`py.typed`, `uv_build`), committed `uv.lock`. `requires-python = ">=3.13,<3.14"` AND committed `.python-version` = 3.13 both pin the 3.13.x line. Cap (not just a floor) for reproducibility: msgspec ships per-interpreter compiled wheels and stdlib behavior can drift across minors, so a bare `>=3.13` floor would silently admit an untested interpreter. The pin is necessary, NOT sufficient — determinism is ASSERTED by golden hex vectors (the actual canonical-form guard), which run under an INJECTED fixed TCB so every admitted 3.13.x patch reproduces them, while VCert stamps verifier/Z3 + full Python/msgspec/unidata + `canon_version` for provenance and separate wiring tests pin each stamp to its live source. Both layers (host `.venv-host`, container `.venv`) honor `.python-version`.
- Service: **Litestar** + **uvicorn** single-worker, 127.0.0.1 by default (`VERIFIER_HOST`/`PORT` configurable; no loopback enforcement) (over FastAPI: msgspec-native end-to-end — response structs render + OpenAPI-document natively, no second model stack, less glue; raw `request.body()` exists in FastAPI too, so the pick = ergonomics NOT a security property). Fail-closed invariant: POST bodies reach `decode_spec` as RAW BYTES via `await request.body()` ONLY — in Litestar 2.24.0 `data: bytes` is framework-PARSED (JSON-decoded first, dup keys silently collapse, then 400 "Expected bytes, got object") while `request.body()` stays byte-exact. CPU-bound work: async handler + `litestar.concurrency.sync_to_thread(fn, *args)` (ParamSpec-typed idiomatic wrapper, no direct anyio dep). `@post` defaults 201 → explicit `status_code=200`. Body cap = built-in `request_max_body_size` (app+handler param; 413 fires at the `request.body()` read — handler entered, content-type guard already run, NOT pre-dispatch — for content-length AND chunked; 2.24's `create_test_client` rejects the kwarg → build the app, wrap `TestClient(app=…)`). Error split: verification outcomes incl. decode failure (expected model failure mode; bench meters it) = 200 verdict envelope; ONLY transport misuse/server-config = RFC 9457 `application/problem+json`. Impl = two `exception_handlers` `{HTTPException → problem+json(exc.status_code, exc.detail); Exception → generic 500, cause LOGGED by the handler then WITHHELD from the untrusted caller}` (the `Exception` handler catches a pipeline raise even under `raise_server_exceptions=True`; Litestar does NOT log an exception a custom handler catches → the handler must `_LOGGER.error(..., exc_info=exc)` itself or the operator-config fault vanishes from EVERY log; test that log by attaching a capturing handler to the NAMED logger AFTER app startup, since Litestar's startup logging config swaps root's handlers so caplog/root-level capture misses it); content-type guard = `request.content_type[0]` (pre-lowercased media-type essence, params/charset stripped, `""` if absent) `== "application/json"` else 415.   - **msgspec pinned behaviors** (read + transcribe, never re-derive; `schema.py` cites these by finding number): (1) `frozen`/`forbid_unknown_fields` propagate to subclasses at RUNTIME but `kw_only` does NOT; and mypy's dataclass_transform reads each class's own kwargs — so EVERY concrete struct must repeat `frozen=True` (for `mypy --strict`, else "non-frozen dataclass cannot inherit from frozen") AND `kw_only=True` (runtime kw-only, since it does not inherit). A `__struct_config__` test backstops frozen+forbid_unknown_fields but does NOT expose `kw_only`, so a separate test asserts positional construction raises `TypeError`. (2) For the transform tagged union, set `tag_field="op"` + an explicit lowercase `tag` per member (else msgspec defaults the tag to the class name and the field name to `type`). (3) Strict mode rejects float→int and bool→int but ACCEPTS a JSON float→`Decimal` — so model spec numerics as `int | str` (NOT Decimal) to reject float/bool tokens at decode; decimals travel as strings, lifted per manifest at eval; the int is further bounded to signed int64 (`Meta(ge=-(2**63), le=2**63-1)`) — out-of-range or fractional numbers travel as the bounded string. (4) Duplicate object keys silently LAST-WINS, no switch — reject via a stdlib `json.loads(raw, object_pairs_hook=…)` pre-scan after the msgspec decode (input is already well-formed JSON). (5) `msgspec.json.schema()` emits NO `$schema` (stamp the Draft-2020-12 URI ourselves), is deterministic cross-process, sorts `Literal` enums alphabetically, renders a tagged union as `anyOf`+OpenAPI `discriminator`+single-element `enum`, maps `forbid_unknown_fields`→`additionalProperties:false`. The exported golden is ADVISORY, not the gate — JSON Schema `integer` admits `1.0`/`1e3` (zero-fraction floats) that strict decode rejects, so `decode_spec` stays authoritative; pop+re-add `$schema` so it sorts last even if a future msgspec emits one. (6) `msgspec.field(name=…)` renames in decode+encode+schema and rejects the un-renamed key (used for `type`→`kind`, `as`→`output`); when an attribute is itself named `field` (`Channel.field`, `Measure.field`, …) call it as `msgspec.field(…)` via the module — the bare `field:` annotation shadows the imported `field` for mypy ("str not callable"), though it still works at runtime (annotation-only names don't bind). Recurs wherever service tests stub a dep. SAME for a CLASS attr reached via an importing module (`cli.Settings.from_env` ⇒ `attr-defined`) → patch the directly-imported class (`from webui.settings import Settings`; `monkeypatch.setattr(Settings, "from_env", staticmethod(fn))`); a STRING `setattr(cli, "name", …)` is UNAFFECTED (no attribute-access expression to check).

## Subsystem gotchas (formal · DSSE · SQLite archive · render)
- Z3 contexts are NOT thread-safe → every worker invocation owns an explicit `Context`.
- DSSE rule: verify signature + payload type, then parse the SAME verified payload byte buffer; never re-parse the envelope.
- A cancelled request keeps its admission permit until the uncancellable worker exits, so it still occupies capacity. Canonical `workers=1` = one gate; extra processes multiply the policy instead of sharing it.
- SQLite migration shape: keep the `UPDATE meta … WHERE singleton = ?` parameter at `1`, validate the prior schema version separately, then advance both version fields. Archive schema is at v4 (v2 added the immutable `spec_id -> canonical_spec` index, v3 the partial `attempts_by_plot(plot_id, attempt_id)` index, v4 the formula-mode CHECK widening + `plots.source_kind` + the `plot_references_match_source` allowlist trigger). `_migrate_v3_to_v4`'s order is forced: validate v3 → `ADD COLUMN … NOT NULL DEFAULT 'dataset'` → explicit backfill `UPDATE` (ADD COLUMN writes no existing row) → stored-text rewrite that drops the DEFAULT → trigger → both version fields.
- Typed blob identity is `(sha256, kind)`: same-role bytes deduplicate, while equal bytes under two truthful roles stay separately representable and each count once against the logical quota.
- Artifact-route tests must set a per-test `state_dir`; the repo-default `.verifier-state` is operator data, never a test sink.
- Pinned Vega-Lite 5.21 compiles an explicit empty nominal color domain (`[]`, all-null data) and numeric ordinal domains — transcribe those forms without re-probing.
- Archive connection profile is `journal_mode=DELETE` + **`synchronous=EXTRA` (value 3, NOT `FULL`)** + `foreign_keys=ON` + `trusted_schema=OFF` + `busy_timeout=5000`, each forced then READ BACK (`archive.py:1564`); the exact-schema pin asserts `3`.
- `_validate_schema_version` compares live `sqlite_schema` rows against the exact DDL **TEXT** in `_SCHEMA_OBJECTS` → any constraint change must reach the STORED text, and SQLite cannot `ALTER` a `CHECK`. Two migration instruments, both probed at ~60 MB / ~2,000 blobs: `PRAGMA writable_schema` text rewrite = 0.30 s, zero file growth, moves no content byte, but needs defensive mode temporarily off + a physical backfill for any new NOT-NULL column + preserved physical column order; conventional table rebuild = 1.17 s, permanent 2.00× file growth (free pages retained), 3.00× peak with journal, and `PRAGMA foreign_keys=OFF` is a NO-OP inside an open transaction (needs `Connection.setconfig`) while `defer_foreign_keys` still fails at COMMIT. **Six** tables reference `blobs(digest, kind)`.
- `_insert_batch_rows` (`archive.py:2579`) inserts blobs → keys → **plots → specs → attempts → plot_references** → attempt_references, and `foreign_keys=ON` forces that order ⇒ a `BEFORE INSERT ON plot_references` trigger can always resolve its parent `plots` row.
- `Archive` keeps NO long-lived connection: `__init__` and every public op open one through `_connect()` (module global `_CONNECTION_FACTORY`) and close it in a `finally` ⇒ per-connection state (defensive config, `writable_schema`) is observable ONLY inside that lifetime. Monkeypatch `_CONNECTION_FACTORY` with a `sqlite3.Connection` subclass recording `execute` + snapshotting both settings in `close()` (snapshot via `super().execute`, else the probe pollutes its own record). That one seam pins migration STATEMENT ORDER and guard restoration on the success AND injected-failure paths — outcome assertions see neither.
- SQLite runs BEFORE INSERT triggers AHEAD of column CHECK constraints ⇒ where a trigger's admitted set ⊆ a CHECK domain (mode guard vs `plot_references.role`), the trigger message masks the CHECK for every unknown value → isolate the CHECK with `DROP TRIGGER` on a throwaway test connection.
- Archive migration differential (M9.7a): **UNRECOVERABLE — `wt/orc-m9u7a` no longer exists on any reachable ref.** The repo was re-cloned on CURRENT (`git reflog`: `4e9c7b8 clone: from github.com:eturkes/figure-verification.git`) and that branch was local-only on ORIGIN, never pushed (`git ls-remote --heads origin` = `main` + `poc`). Rebuilding it from the contract is the only route; polish `p3` owns the port and its source material is GONE. Historic recipe, retained for what the port must reproduce: `git show wt/orc-m9u7a:{differential,oracle_corpus,oracle_migrate_v4}.py` into a scratch dir, patch `oracle_corpus`'s `PlotRecord(...)` call to pass `PlotSourceKind.DATASET` (the oracle DEFAULTED that field, MAIN requires it), then `python oracle_corpus.py <out>` for the oracle's self-check, plus a ~30-line driver for MAIN-vs-oracle: `_build_archive` → `_downgrade_to_exact_v3` → copy the state dir twice → `open_archive` one (landed rewrite) / `oracle.migrate` the other (rebuild) → `differential.compare`. Read PER-SECTION equality, never the aggregate `equal`: `page_count` + `file_size` MUST diverge between rewrite and rebuild.
- **The attempt layer is already source-neutral in SQL, so formula attempts force no schema bump.** `attempts` stores address/envelope/key/nullable `plot_id`; route + outcome live ONLY inside the opaque signed `attempt_payload` blob ⇒ no SQL route/outcome domain exists to widen (`CHECK.*route|CHECK.*outcome` rc=1). ## Lessons (forward-binding)
Process / right-sizing (rule itself → roadmap; it binds every planning window):
- Overflow modes seen, with remedies: design-too-wide → split at a coverage-safe seam; re-derivation despite a complete recipe → TRANSCRIBE, don't re-derive (trust verified goldens); probing a native dep in the implementing window → isolate probes to scratch sessions and pre-bake a gate-validated recipe; TOO-MANY-modules/layers in one unit (a chart surface of 6 src + 6 test files spanning storage+production+serving, design derived from scratch, overflowed mid-tests) → the ~one-module rule binds cross-LAYER; split by layer (render-leaf / store-LRU / capture+serve), front-load the subtle module (the LRU) alone in its own window, and pre-bake each sub-unit's transcription recipe in the roadmap so the re-plan cost is paid once. A method seam per layer (e.g. a dedicated store `put_chart`) decouples the extension from its pipeline caller and makes that isolation clean.
- An investigation-heavy review pass can overflow while the fix stays small → capture the verified fix as a re-appliable patch/recipe + verdict, splitting investigation from application.
- A claim-narrowing fix must SWEEP every restatement of the phrase across src+tests+memory — one narrowed line beside stale twins reads fixed but isn't.
Test design:
- A diff-blind suite states a contract READING, not the contract: where a delivered red asserts MORE than the ratified predicate, the predicate wins and the SUITE is corrected. M9.11 R5 — two independent roles (`test`, blind by construction, and `rev2` B06) demanded that replay classify the occurrence's mode BEFORE the attempt read, a strictly stronger order than the ratified "mode established before any verdict is constructed"; implementing it flipped a pinned `ArchiveIntegrityError` to `ArchiveNotFoundError` and charged every replay a second connect. Independent agreement between blind roles measures the READING's plausibility, never its authority ⇒ diff a demanded strengthening against the contract text before implementing it, and expect the suite edit, not the code edit.
- A source-mutation probe must be PROVED to have applied before its exit code means anything: a `sed`/`replace` pattern that matches nothing yields a silent no-op whose green run reads as "mutant survived" (caught by echoing the mutated line — the literal was `frozenset({"501"})`, not `{"501"}`) ⇒ pair every mutation with a `cmp`/grep confirmation, and restore with a byte-identity check.
- An object-identity witness must RETAIN the objects through the assertion; recording only
  `id(obj)` lets CPython free wrappers and reuse addresses, producing a false same-object result.
- A green INTERNAL gate (lint/type/100%-branch/structural asserts) does NOT prove EXTERNAL-contract validity → test output artifacts against the real consumer (jsonschema; a full vl-convert COMPILE — now a standing gate over all good specs).
- 100% BRANCH coverage misses data-DOMAIN gaps (the prec-28 rounding bug) and cannot pin LOOKUP-TABLE entries → regression-test the real data path at hostile magnitudes; matrix-test an enumerable key-space against the spec restated in-test (non-circular oracle).
- 100% coverage EXECUTES a line without pinning its EFFECT: an LRU recency refresh (`move_to_end`) runs on every put/get yet stays UNPINNED unless a test re-puts an ALREADY-PRESENT key or asserts a READ reorders eviction — re-putting an already-EVICTED key is a fresh insert exercising no refresh. Pin recency with an `html_cap>=2` witness, and PROVE non-vacuous by deleting the refresh + confirming the test FAILS (mutation check), then reverting.
- A fail-closed ALLOWLIST/registry needs its REFUSAL pinned against NEAR-MISS inputs of the same family, not only a generic outsider. `make_result` refuses unregistered check IDs; a mutant falling back to a default method for any `formula.*`-prefixed ID passed all 2223 tests because the committed negative used an unrelated name. Only the coverage gate flinched, incidentally — a mutant whose fallback branch executes passes clean. Pin one near-miss per admitted family, plus every ID a later unit intends to add (a deferred ID asserted RED doubles as a scope guard).
- INDEPENDENT bounds need their JOINT corner pinned: per-axis boundary tests at ceilings A and B leave the compound `(A,B)` maximum untested, and a basis MEASURED on single-axis shapes understates the real worst case (a defect firing only at `(ast_depth 64, paren_depth 64)` passed all 108 parser tests at 100% branch; joint profiling gave 267/523 frames against a single-axis basis of 201/"~400", ~30% low). Same for a fail-fast guard: mutation-test its ORDERING (moving validation after the work it guards left every test green), not only its presence.
- A metered guard's CHARGE-BEFORE-GUARD ordering is invisible to presence/refusal tests → pin the EXACT cumulative work at each refusal and failure (literal integers, never a production cost helper); "refused ⇒ consumed unchanged" and "admitted-but-failing ⇒ full charge retained" are separate assertions, and the stage a failure came from is identified by its work count.
- Some guard sites admit NO isolating witness because their quantities are IDENTITY-COUPLED (a span equals the last offset; the first/last sample position equals the domain start/stop) → "only this quantity is over-limit while every later-checked one fits" is unsatisfiable, not merely hard. Discriminate those sites by stage-identifying exact-work/no-start witnesses (deleting the guard shifts the SAME failure to a different work count) rather than weakening the claim or dropping the test.
- Order-sensitivity as a Hypothesis property is HOLLOW (tautological) → one concrete anchor witness; a PYTHONHASHSEED-stability guard needs TIE-HEAVY rows + several seeds else it passes vacuously; "proves" overstates a bounded sample → "samples / finds no counterexample".
- Direct-helper test fixtures must be REALIZABLE pipeline states (not phantom ones); an acceptance criterion naming a multi-step scenario needs an END-TO-END pin through the public entry, not only the algorithm helper.
- cast-not-assert: narrow `X | None` via `cast` at a gated use site — an `assert`'s never-taken branch fails the 100% gate. msgspec `Meta` constraints enforce at DECODE only (`structs.replace`/direct construction skip them) → any security gate resting on a decoded-shape invariant must re-hold at the use site (path confinement = authoritative `resolve()`+`is_relative_to`). BUT when a model string enters a path only via `Path(name).stem` or a `fullmatch` id regex, confinement is BY CONSTRUCTION → NO runtime `is_relative_to` branch (unreachable → fails warn_unreachable + 100%-branch); the authoritative form is needed only where the WHOLE model string builds the path (checks.py CSV), never where `.stem` already confines it (pipeline.py manifest path) — plan such a confinement branch only after checking constructability.
- Per-element uniqueness ≠ global acyclicity: a backward walk over a schema-REBUILDING pipeline keys on (name, POSITION), never name alone — else non-terminating or unsound on reused output names.
- A green parity suite ≠ a correct oracle: a probe-validated draft re-parsed source through the banned forced-DECIMAL CAST and clean goldens hid it → verify the oracle INGESTS the shared coercer's cells, and feed adversarial synthetics beyond the golden shapes.
- An oracle that deliberately IGNORES one production concern (M9.3's oracle ignores the work meter) must state that boundary in the suite and CLASSIFY the resulting one-sided outcomes as expected — 11,513 of 64,480 cross-product points were production-only resource refusals; counting them as agreement or as divergence would both mislead. State the claim at its true scope: end-to-end public-entry outcome equality evidences NO individual internal admission site.
- An equivalence differential must compare FULL messages + the cross-product of independent failure modes — a check-tag-only diff missed a magnitude/precision precedence flip.
- A test embedding a symbol name as a substring → do renames via TARGETED edits, never `replace_all`.
- CALLER-SUPPLIED policy must be pinned as THREADED **at every public entry point separately**, not merely accepted: dropping `limits=limits` at a verify boundary (silently reverting to default policy) passed all 2263 tests; dropping `require_canonical_envelope` inside a shared two-caller helper passed all 2445, because the OLDER caller's tests killed that mutant at the shared seam and left the NEWER caller only INCIDENTALLY covered. A sibling wrapper's kill is not your wrapper's pin. Pin each wrapper's own forwarding with a policy STRICTER than default that must refuse — a default-equal policy proves nothing.
- EQUAL-VALUE arguments hide threading defects the same way, and no output assertion can catch them: both certificate MIMEs are 51 B, so hardcoding either one in the `envelope_byte_limit` call is byte-identical today and survived every test. Pin the relation with an argument SPY (record the value the callee actually received) plus a witness where the values DIVERGE — the equality must be provably incidental, not assumed.
- Exact-rational projections must never detour through `float`: `Fraction(Decimal(x))` → `Fraction(float(Decimal(x)))` survived every committed test because the witnesses were binary-exact. Include a non-binary decimal (0.2) in any exactness witness.
- ORDERING pins need CALL-COUNTING BOMBS on the downstream work, not outcome assertions: hoisting evidence hashing / evidence construction above a resource refusal, or sinking a row-limit guard below fact + solver work, leaves the returned verdict unchanged and every outcome test green. Monkeypatch the downstream callables to raise + assert zero calls (M9.4b's render-row test is the model).
- Those bombs must ride EVERY failure PATH, not one witness: M9.5 pinned zero template/hash/success work for the finite non-round-trip case only, so a mutant hashing on the non-finite/overflow path stayed green through the full suite. One bomb per distinct refusal reason.
- DECLARED-parameter AUTHORITY needs a DISAGREEMENT witness (companion to the caller-limits lesson): when a value carries metadata mirroring the declared parameter (a `Decimal`'s own exponent vs the declared scale, a table's own width vs a declared column count), every witness where the two agree lets a value-derived substitute pass. Pin with a forged case where declared and intrinsic DIFFER — `Decimal("0.1")` under declared scale 0 must fail.
- Closed-lookup dispatch needs the FULL near-miss matrix, not one probe: with only `bar` tested, a `_MARK_CALLS.get(mark, _MARK_CALLS["line"])` fallback admitting every other key survived the whole suite. Parametrize absent-key siblings incl. dunder-shaped names, each asserting refusal BEFORE downstream work.
- `Decimal(repr(f))` is an UNSOUND float-fidelity oracle: public endpoint `18014398509481990` spells itself back through `repr` while its exact binary64 value is `…92`. Recompute fidelity as `round(Fraction.from_float(f), declared_scale) == Fraction(d)` (exact HALF_EVEN, ambient-context-free), then emit `repr(f)` for its shortest round-trip property alone. Binds every future float projection (M11 `derive`).
- When splitting a SHARED message by mode, byte-pin the UNCHANGED mode's canonical report (SHA-256 of the report bytes). A dataset-side wording drift preserving statuses/methods passed the whole suite while breaking the promised output identity.
- Guarantee strings in `examples/index.json` + `examples/README.md` are part of the CLAIM surface — a new mode can falsify them silently (formula mode inherited "no expr/code/url field" and an SMT-"before native Vega" claim, both false). Sweep example/doc claims whenever a mode is added.
- Re-verifying a reviewer's mutation set after an intervening fix pass: exact anchors CAN vanish (a fix inserted a translation line between the guard and its re-insertion point). Rebuild the mutant at the equivalent CURRENT seam and re-run rather than recording it inapplicable — 8/9 applied verbatim, the 9th needed re-anchoring and still died.
- Before adding a REVIEWER-PROPOSED pin, re-apply its exact mutant against the CURRENT tests first: an existing behavioral test may already kill it, making the proposed test pure noise (M9.4b — 2 of 9 proposed pins were already covered by fix-pass-1 tests). A reviewer's acceptance check is a hypothesis about coverage, not a verified gap.
- SAME-SIZE mutate/restore leaves STALE `.pyc`: CPython invalidates on (mtime, size), so a restore that preserves both makes Python reuse the MUTANT code object — source SHA-256 verifies clean while the suite fails inexplicably. After any mutation cycle, clear `src/**/__pycache__` before trusting a gate run.
- MAIN's own mutation rerun is cheap and decisive: apply exact mutants to the landed tree, run the committed suite with `-x --no-cov` (~25s each vs ~72s full), require non-zero rc, restore bytes + verify SHA-256 in a `finally`. Prefer it over accepting a fixer's self-reported kills.
- A schema→grammar CONVERTER can fail OPEN, and a green-looking run hides it: `llama-cpp-python`'s JSON-schema helper raises `KeyError '#/$defs/Dataset'` on a Draft-2020-12 root `$ref`, after which its wrapper SILENTLY substitutes a generic JSON grammar — guided decoding reports active while enforcing almost nothing. Never credit a guidance path from a success return; prove enforcement by validating emitted output against the STRICT schema AND by feeding a construct the grammar must refuse. The same schema converted cleanly once the root `$ref` was inlined, so the defect is the silent fallback, not the schema. Binds every future guidance backend.
Refuted probes (do NOT re-investigate; evidence in git): DuckDB `executemany` does NOT route large in-domain Decimals through float64; whole-table + all-null-group aggregates agree with eval; native Decimal binds correctly across its full range EXCEPT positive-exponent literals (the oracle filter path coerces via `ingest._coerce_numeric`, exp≤0). "One spec per render (Vega element-id counter)" refuted — in-process SVG byte-determinism holds.

- msgspec `Literal` binds DECODE only, exactly like `Meta` — direct construction sets any value, and a bare `msgspec.json.Encoder` re-checks nothing, so a wrong-version/wrong-member struct EMITS canonical-looking bytes.
