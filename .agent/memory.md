## Stack (M1 trusted core) — SOTA picks over human-popular defaults
- Runtime: `uv` src-layout single pkg `verifier` (+`py.typed`, `uv_build`), committed `uv.lock`. `requires-python = ">=3.13,<3.14"` AND committed `.python-version` = 3.13 both pin the 3.13.x line. Cap (not just a floor) for reproducibility: msgspec ships per-interpreter compiled wheels and stdlib behavior can drift across minors, so a bare `>=3.13` floor would silently admit an untested interpreter. The pin is necessary, NOT sufficient — determinism is ASSERTED by golden hex vectors (the actual canonical-form guard), and VCert stamps verifier/Z3 + full Python/msgspec/unidata + `canon_version` for provenance. Both layers (host `.venv-host`, container `.venv`) honor `.python-version`.
- Service: **Litestar** + **uvicorn** single-worker, 127.0.0.1 by default (`VERIFIER_HOST`/`PORT` configurable; no loopback enforcement) (over FastAPI: msgspec-native end-to-end — response structs render + OpenAPI-document natively, no second model stack, less glue; raw `request.body()` exists in FastAPI too, so the pick = ergonomics NOT a security property). Fail-closed invariant: POST bodies reach `decode_spec` as RAW BYTES via `await request.body()` ONLY — in Litestar 2.24.0 `data: bytes` is framework-PARSED (JSON-decoded first, dup keys silently collapse, then 400 "Expected bytes, got object") while `request.body()` stays byte-exact. CPU-bound work: async handler + `litestar.concurrency.sync_to_thread(fn, *args)` (ParamSpec-typed idiomatic wrapper, no direct anyio dep). `@post` defaults 201 → explicit `status_code=200`. Body cap = built-in `request_max_body_size` (app+handler param; 413 fires at the `request.body()` read — handler entered, content-type guard already run, NOT pre-dispatch — for content-length AND chunked; 2.24's `create_test_client` rejects the kwarg → build the app, wrap `TestClient(app=…)`). Error split: verification outcomes incl. decode failure (expected model failure mode; bench meters it) = 200 verdict envelope; ONLY transport misuse/server-config = RFC 9457 `application/problem+json`. Impl = two `exception_handlers` `{HTTPException → problem+json(exc.status_code, exc.detail); Exception → generic 500, cause LOGGED by the handler then WITHHELD from the untrusted caller}` (the `Exception` handler catches a pipeline raise even under `raise_server_exceptions=True`; Litestar does NOT log an exception a custom handler catches → the handler must `_LOGGER.error(..., exc_info=exc)` itself or the operator-config fault vanishes from EVERY log; test that log by attaching a capturing handler to the NAMED logger AFTER app startup, since Litestar's startup logging config swaps root's handlers so caplog/root-level capture misses it); content-type guard = `request.content_type[0]` (pre-lowercased media-type essence, params/charset stripped, `""` if absent) `== "application/json"` else 415. OpenAPI: Litestar auto-gen stays OFF (`openapi_config=None`) — it introspects response models via msgspec, whose `RenderVerdict.verified: Literal[True]` arm is response-encode-only, so the document stays hand-authored. `openapi_document()` rebases VPlot `$defs`, imports msgspec schemas (including nested `CertifiedCheck`/disclosures/TCB), and derives RenderVerdict's 9 strings + ProposeResult; golden bytes + real-payload jsonschema tests pin it. Typed path/query params use `FromPath`/`FromQuery`.
- Schema: **msgspec** (NOT Pydantic) — strict/fail-closed, `forbid_unknown_fields` on every `Struct`, transform ops = tagged union (`tag_field="op"`), `Literal` enums, module-level `Decoder`, `json.schema` export golden-snapshotted. Formula v0.1 is a separate strict `FormulaPlotSpec`/decoder + internal `PlotSpec` union: model bytes carry only ASCII formula text, decimal-STRING domain endpoints (`start`/`stop`, never JSON floats) alongside bounded-INT `samples`/`x_scale`/`y_scale`, the closed rational profile, line/scatter, and fixed quantitative x/y — no points/Python; grammar + cross-field meaning remain M9.2–M9.4. Dataset decode + exported schema stay unchanged.
  - **msgspec pinned behaviors** (read + transcribe, never re-derive; `schema.py` cites these by finding number): (1) `frozen`/`forbid_unknown_fields` propagate to subclasses at RUNTIME but `kw_only` does NOT; and mypy's dataclass_transform reads each class's own kwargs — so EVERY concrete struct must repeat `frozen=True` (for `mypy --strict`, else "non-frozen dataclass cannot inherit from frozen") AND `kw_only=True` (runtime kw-only, since it does not inherit). A `__struct_config__` test backstops frozen+forbid_unknown_fields but does NOT expose `kw_only`, so a separate test asserts positional construction raises `TypeError`. (2) For the transform tagged union, set `tag_field="op"` + an explicit lowercase `tag` per member (else msgspec defaults the tag to the class name and the field name to `type`). (3) Strict mode rejects float→int and bool→int but ACCEPTS a JSON float→`Decimal` — so model spec numerics as `int | str` (NOT Decimal) to reject float/bool tokens at decode; decimals travel as strings, lifted per manifest at eval; the int is further bounded to signed int64 (`Meta(ge=-(2**63), le=2**63-1)`) — out-of-range or fractional numbers travel as the bounded string. (4) Duplicate object keys silently LAST-WINS, no switch — reject via a stdlib `json.loads(raw, object_pairs_hook=…)` pre-scan after the msgspec decode (input is already well-formed JSON). (5) `msgspec.json.schema()` emits NO `$schema` (stamp the Draft-2020-12 URI ourselves), is deterministic cross-process, sorts `Literal` enums alphabetically, renders a tagged union as `anyOf`+OpenAPI `discriminator`+single-element `enum`, maps `forbid_unknown_fields`→`additionalProperties:false`. The exported golden is ADVISORY, not the gate — JSON Schema `integer` admits `1.0`/`1e3` (zero-fraction floats) that strict decode rejects, so `decode_spec` stays authoritative; pop+re-add `$schema` so it sorts last even if a future msgspec emits one. (6) `msgspec.field(name=…)` renames in decode+encode+schema and rejects the un-renamed key (used for `type`→`kind`, `as`→`output`); when an attribute is itself named `field` (`Channel.field`, `Measure.field`, …) call it as `msgspec.field(…)` via the module — the bare `field:` annotation shadows the imported `field` for mypy ("str not callable"), though it still works at runtime (annotation-only names don't bind). (7) A frozen struct holding a `list` is only SHALLOWLY immutable (`spec.transform.append(…)` still mutates) and unhashable — so model every JSON array as a bounded `tuple[T, ...]` (`Annotated[..., Meta(min_length/max_length)]`; msgspec decodes JSON arrays to tuples and enforces the length), making specs DEEPLY immutable and fully hashable. Test immutability via an attribute set raising `AttributeError`. (8) `Encoder(order="deterministic")` keeps struct field order while sorting dict/set keys, renders Decimal→string, does NO Unicode normalization (→ the spec hash). (9) `msgspec.json.Decoder.decode` raises the BUILTIN `UnicodeDecodeError` (NOT `msgspec.DecodeError`/`ValidationError`) on invalid UTF-8 inside a JSON string → any `except (DecodeError, ValidationError)` guarding a decode of UNTRUSTED bytes must ALSO catch `UnicodeDecodeError`, or the fault escapes the intended mapping (e.g. an invalid-UTF-8 backend reply escaping `_extract_content`'s 502 upstream-fault path → generic 500).

## M5 (formal + provenance hardening) — gotchas that outlive the code
- Z3 contexts are NOT thread-safe → every worker invocation owns an explicit `Context`.
- DSSE rule: verify signature + payload type, then parse the SAME verified payload byte buffer; never re-parse the envelope.
- A cancelled request keeps its admission permit until the uncancellable worker exits, so it still occupies capacity. Canonical `workers=1` = one gate; extra processes multiply the policy instead of sharing it.
- SQLite migration shape: keep the `UPDATE meta … WHERE singleton = ?` parameter at `1`, validate the prior schema version separately, then advance both version fields. Archive schema is at v4 (v2 added the immutable `spec_id -> canonical_spec` index, v3 the partial `attempts_by_plot(plot_id, attempt_id)` index, v4 the formula-mode CHECK widening + `plots.source_kind` + the `plot_references_match_source` allowlist trigger). `_migrate_v3_to_v4`'s order is forced: validate v3 → `ADD COLUMN … NOT NULL DEFAULT 'dataset'` → explicit backfill `UPDATE` (ADD COLUMN writes no existing row) → stored-text rewrite that drops the DEFAULT → trigger → both version fields.
- Typed blob identity is `(sha256, kind)`: same-role bytes deduplicate, while equal bytes under two truthful roles stay separately representable and each count once against the logical quota.
- Artifact-route tests must set a per-test `state_dir`; the repo-default `.verifier-state` is operator data, never a test sink.
- Pinned Vega-Lite 5.21 compiles an explicit empty nominal color domain (`[]`, all-null data) and numeric ordinal domains — transcribe those forms without re-probing.
- Archive connection profile is `journal_mode=DELETE` + **`synchronous=EXTRA` (value 3, NOT `FULL`)** + `foreign_keys=ON` + `trusted_schema=OFF` + `busy_timeout=5000`, each forced then READ BACK (`archive.py:1564`); the exact-schema pin asserts `3`.
- `_validate_schema_version` compares live `sqlite_schema` rows against the exact DDL **TEXT** in `_SCHEMA_OBJECTS` → any constraint change must reach the STORED text, and SQLite cannot `ALTER` a `CHECK`. Two migration instruments, both probed at ~60 MB / ~2,000 blobs: `PRAGMA writable_schema` text rewrite = 0.30 s, zero file growth, moves no content byte, but needs defensive mode temporarily off + a physical backfill for any new NOT-NULL column + preserved physical column order; conventional table rebuild = 1.17 s, permanent 2.00× file growth (free pages retained), 3.00× peak with journal, and `PRAGMA foreign_keys=OFF` is a NO-OP inside an open transaction (needs `Connection.setconfig`) while `defer_foreign_keys` still fails at COMMIT. **Six** tables reference `blobs(digest, kind)`.
- `_insert_batch_rows` (`archive.py:2579`) inserts blobs → keys → **plots → specs → attempts → plot_references** → attempt_references, and `foreign_keys=ON` forces that order ⇒ a `BEFORE INSERT ON plot_references` trigger can always resolve its parent `plots` row.
- `Archive` keeps NO long-lived connection: `__init__` and every public op open one through `_connect()` (module global `_CONNECTION_FACTORY`) and close it in a `finally` ⇒ per-connection state (defensive config, `writable_schema`) is observable ONLY inside that lifetime. Monkeypatch `_CONNECTION_FACTORY` with a `sqlite3.Connection` subclass recording `execute` + snapshotting both settings in `close()` (snapshot via `super().execute`, else the probe pollutes its own record). That one seam pins migration STATEMENT ORDER and guard restoration on the success AND injected-failure paths — outcome assertions see neither.
- SQLite runs BEFORE INSERT triggers AHEAD of column CHECK constraints ⇒ where a trigger's admitted set ⊆ a CHECK domain (mode guard vs `plot_references.role`), the trigger message masks the CHECK for every unknown value → isolate the CHECK with `DROP TRIGGER` on a throwaway test connection.
- `tests/test_service_archive.py::_complete_batch` publishes SYNTHETIC envelopes (`b"signed-vcert-envelope"`) ⇒ signature-verifying readers (`read_plot`, `read_certificate`, `read_attempt`) cannot consume it; use byte readers (`read_plot_envelope`/`read_plot_blob`/`read_attempt_envelope`) + `stats()`. `tests/schema_downgrade.py::downgrade_to_v3` is the EXACT v4→v3 fixture (drop trigger + column, rewrite all three stored table texts to `_CREATE_*_V3`, bump the cookie, reset both version fields) — a partial downgrade leaves a fixture that keeps passing while testing nothing.

## Lessons (forward-binding)
Process / right-sizing (rule itself → roadmap; it binds every planning window):
- Overflow modes seen, with remedies: design-too-wide → split at a coverage-safe seam; re-derivation despite a complete recipe → TRANSCRIBE, don't re-derive (trust verified goldens); probing a native dep in the implementing window → isolate probes to scratch sessions and pre-bake a gate-validated recipe; TOO-MANY-modules/layers in one unit (a chart surface of 6 src + 6 test files spanning storage+production+serving, design derived from scratch, overflowed mid-tests) → the ~one-module rule binds cross-LAYER; split by layer (render-leaf / store-LRU / capture+serve), front-load the subtle module (the LRU) alone in its own window, and pre-bake each sub-unit's transcription recipe in the roadmap so the re-plan cost is paid once. A method seam per layer (e.g. a dedicated store `put_chart`) decouples the extension from its pipeline caller and makes that isolation clean.
- An investigation-heavy review pass can overflow while the fix stays small → capture the verified fix as a re-appliable patch/recipe + verdict, splitting investigation from application.
- A claim-narrowing fix must SWEEP every restatement of the phrase across src+tests+memory — one narrowed line beside stale twins reads fixed but isn't.
Test design:
- An object-identity witness must RETAIN the objects through the assertion; recording only
  `id(obj)` lets CPython free wrappers and reuse addresses, producing a false same-object result.
- A green INTERNAL gate (lint/type/100%-branch/structural asserts) does NOT prove EXTERNAL-contract validity → test output artifacts against the real consumer (jsonschema; a full vl-convert COMPILE — now a standing gate over all good specs).
- 100% BRANCH coverage misses data-DOMAIN gaps (the prec-28 rounding bug) and cannot pin LOOKUP-TABLE entries → regression-test the real data path at hostile magnitudes; matrix-test an enumerable key-space against the spec restated in-test (non-circular oracle).
- 100% coverage EXECUTES a line without pinning its EFFECT: an LRU recency refresh (`move_to_end`) runs on every put/get yet stays UNPINNED unless a test re-puts an ALREADY-PRESENT key or asserts a READ reorders eviction — re-putting an already-EVICTED key is a fresh insert exercising no refresh. Pin recency with an `html_cap>=2` witness, and PROVE non-vacuous by deleting the refresh + confirming the test FAILS (mutation check), then reverting.
- A fail-closed ALLOWLIST/registry needs its REFUSAL pinned against NEAR-MISS inputs of the same family, not only a generic outsider. `make_result` refuses unregistered check IDs; a mutant falling back to a default method for any `formula.*`-prefixed ID passed all 2223 tests because the committed negative used an unrelated name. Only the coverage gate flinched, incidentally — a mutant whose fallback branch executes passes clean.
