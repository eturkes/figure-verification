## Stack — SOTA picks over human-popular defaults
- Runtime: `uv` src-layout single package `verifier` (+`py.typed`, `uv_build`), committed `uv.lock`. `requires-python = ">=3.13,<3.14"` + committed `.python-version` = 3.13 both pin the line; the CAP is deliberate (msgspec ships per-interpreter compiled wheels; stdlib behavior drifts across minors). Necessary, NOT sufficient — determinism is ASSERTED by golden hex vectors under an INJECTED fixed TCB, while VCert stamps live versions for provenance + separate wiring tests pin each stamp to its source.
- Schema: **msgspec** (NOT Pydantic) — strict/fail-closed, `forbid_unknown_fields` everywhere, transform ops = tagged union, `Literal` enums, module-level `Decoder`, `json.schema` export golden-snapshotted.
- **msgspec pinned behaviours = 9 numbered findings, full text → `.agent/reference.md`; `schema.py` cites them BY NUMBER** ⇒ read them there before touching decode, the tagged Transform union (M11 adds `Derive`), the exported schema, or any guard over untrusted bytes. The two that bite hardest: strict mode ACCEPTS a JSON float→`Decimal` (so spec numerics are `int | str`), and duplicate object keys silently LAST-WIN with no switch (rejected by a stdlib `object_pairs_hook` pre-scan).
- **msgspec `Literal` + `Meta` bind DECODE only.** Direct construction sets any value + a bare `Encoder` re-checks nothing ⇒ a wrong-version or wrong-member struct EMITS canonical-looking bytes. A version literal, an enum-ish field + a tagged-union member each need a `__post_init__` guard plus an exact-type gate at the public encode seam. Typed signatures alone are runtime decoration.
- Evaluator: **hand-rolled pure-Python** (NOT pandas/polars) — total control of row/column order, nulls, Decimal-exact accumulation (Fraction Σ, one HALF_EVEN quantize).
- Hashing — canon's six SHA-256 identities avoid Parquet/Arrow: dataset = raw CSV; table = typed-NDJSON; spec = msgspec canonical re-encode; manifest = raw manifest; formula = resolved canonical source; matplotlib-script = exact verifier-authored bytes. Dataset stays tag-free source identity, the other five domain-tagged. Only TABLE is permutation-invariant. Spec strings stay byte-faithful (NO NFC — folding can collide different filters). VCert v0.2 separately adds raw SHA-256 over exact emitted Vega-Lite bytes.
- Oracle (dev/test only): **DuckDB** `threads=1`, columns as matching `DECIMAL(38,scale)`; outside its DECIMAL(38)/HUGEINT domain it raises LOUDLY at pinned sites, never silently diverges. Mechanics + settled edge cases → `tests/oracle.py` docstrings.
- Lint/format **ruff** (incl. S/T20/DTZ). Types **mypy --strict** — NOT `ty`, whose silent unimplemented-check gaps are unsafe for a soundness core (`ty`/pyright editor-only). Tests **pytest** + **Hypothesis** (CI `derandomize=True`, `deadline=None`; shared row strategies in `tests/corpus.py`).

## Ops (dev loop)
- venv is per-layer (uv bakes absolute paths): container `.venv`, host `.venv-host`, both gitignored. In non-interactive shells `export UV_PROJECT_ENVIRONMENT=.venv` (+ `UV_LINK_MODE=copy`) before any `uv` call.
- **Run the gate AS DEFINED + record the command actually run — the recorded command IS the claim.** Gate = bare `mypy` (`mypy_path=["src","tests"]`; 132 files at `4059dcf` — a snapshot that grows, never a pin), NEVER `mypy src/`: a unit once closed on the narrowed form and shipped 3 `attr-defined` errors in its own test file, indistinguishable from green in a commit body.
- **`uv pip check` and `uv sync --project <nested>` both target the WRONG environment by default** — bare `uv pip check` checked the root `.venv` (49 pkgs, py3.13.14) while the CUDA runtime sat in `.venv-model`, and a RELATIVE `UV_PROJECT_ENVIRONMENT` resolves against the NESTED project, not the repo root. Any claim about a non-default venv names its interpreter absolutely: `uv pip check --python "$PWD/.venv-model/bin/python"`, `UV_PROJECT_ENVIRONMENT="$PWD/.venv-model" uv sync --locked --project <dir>`. A sync + metadata check still proves NO native import ⇒ pair it with an import/CUDA/capability/matmul probe.
- **`get_args()` on a PEP-695 `type X = Literal[...]` alias returns `()`, not the members** — reach them through `get_args(X.__value__)`. A closure test written the obvious way passes vacuously against an EMPTY tuple.
- **`git check-ignore` suppresses TRACKED files by default**, so a committed negative ignore-test is vacuous ⇒ pass `--no-index`, and prove tracking separately with `git ls-files --error-unmatch`.
- Run `--locked` + invoke every tool THROUGH `uv run` (or `.venv/bin/<tool>`). A bare name resolves on PATH, which a fresh non-interactive shell leaves WITHOUT `.venv/bin`, and the two tools fail in OPPOSITE directions: `mypy` dies loudly (rc 127) while `ruff` SILENTLY runs the host build + reports its newer rule set, reading like a regression the unit caused. Host-vs-pin skew is `.agent/polish.md` upgrade debt, never a gate result.
- Worktree gate recipe (teammate isolation): from `<wt>` = `.scratch/worktrees/<name>`, `export UV_PROJECT_ENVIRONMENT=<primary>/.venv UV_LINK_MODE=copy PYTHONPATH=<wt>/src COVERAGE_FILE=<wt>/.coverage`, then the four gate commands under `uv run --no-sync --locked …` (`pytest -p no:cacheprovider`). `--no-sync` leaves the shared venv unmutated ⇒ every worktree gates concurrently off one environment. LANDMINE — `PYTHONPATH=<wt>/src` is LOAD-BEARING: the shared venv's `verifier.pth` hard-codes the PRIMARY `src` + pytest's `pythonpath` omits `src`, so without it a teammate's ENTIRE gate exercises MAIN's code and reports green over edits it never ran. ruff/mypy need nothing extra.
- Coverage gate = 100% branch (`fail_under=100`, `--cov` in `addopts`) ⇒ a partial run trips it, add `--no-cov` for subsets. `exclude_also` covers TYPE_CHECKING/`__main__`/`@abstractmethod` only — NOT `...`/`raise NotImplementedError` (an unimplemented stub fails the gate); exclude real overload/Protocol bodies precisely, never with a blanket `...`. Coverage source = `verifier` ONLY ⇒ `bench/`, `model_backend/`, `webui/`, `demo/` + tests-local modules sit outside, their own tests their only coverage.
- Coverage scope is package-NAME based ⇒ a test loading a MUTATED module copy must register it under a name OUTSIDE that package, else every unexecuted mutant statement enters the 100% gate.
- Editing a covered source WHILE a run is in flight invalidates THAT run's coverage report (line data shifts under the collector) though pass/fail stays valid ⇒ run the decisive gate edit-free; never cite a coverage figure from a run you edited through.
- Hypothesis profiles in `tests/conftest.py`: default `ci` (derandomize, no deadline), `HYPOTHESIS_PROFILE=dev` for randomized exploration. Property tests pass `mypy --strict` as written — import `DrawFn`/`SearchStrategy` from `hypothesis.strategies`, type each `@composite` fn `(draw: DrawFn) -> T`. `st.characters(codec="utf-8")` = always-encodable text; plain `st.text()`/`st.binary()` feed decode-or-raise fuzz. `msgspec.json.encode(float)` always emits a JSON float token ⇒ float-injection tests encode floats directly. Vary `PYTHONHASHSEED` only via a subprocess.
- Monkeypatching under `mypy --strict` (`no_implicit_reexport`): reaching an imported module THROUGH another errors `attr-defined` ⇒ patch the SHARED module object directly (`import uvicorn` in the test + `monkeypatch.setattr(uvicorn, "run", …)`); same for a CLASS attribute reached via an importing module ⇒ patch the directly-imported class. A STRING `setattr` is unaffected.
- **Module-level dispatch maps defeat `monkeypatch.setattr`**: a `dict`-of-callables binds function OBJECTS at import ⇒ patching the module attribute no-ops SILENTLY, the bomb never fires + the test passes for the wrong reason. Spy the map ENTRY with `monkeypatch.setitem` (stronger evidence anyway — it proves the map is the seam) and annotate such maps `dict[...]`, not `Mapping[...]`, so `setitem` type-checks.
- Artifact-route tests must set a per-test `state_dir`; the repo-default `.verifier-state` is operator data, never a test sink.
- SAME-SIZE mutate/restore leaves STALE `.pyc` — CPython invalidates on (mtime, size), so a restore preserving both reuses the MUTANT code object while the source SHA-256 verifies clean ⇒ clear `src/**/__pycache__` after any mutation cycle before trusting a gate run.

## Lessons (forward-binding)
Process:
- Overflow modes → remedies: design-too-wide → split at a coverage-safe seam; re-derivation despite a complete recipe → TRANSCRIBE; native-dep probing in the implementing window → isolate probes to scratch sessions; too many modules/layers → the ~one-module rule binds cross-LAYER, so split by layer + front-load the subtle module alone. Sizing cost drivers (prep wave, attached state, duplicated twins, compaction) → `roadmap.md` "Unit sizing rule".
- An investigation-heavy review pass can overflow while the fix stays small ⇒ capture the verified fix as a re-appliable patch + verdict, splitting investigation from application.
- A claim-narrowing fix must SWEEP every restatement across src + tests + docs + memory — one narrowed line beside stale twins reads fixed but isn't. **Shipping a correct NEW test alongside the narrowed line is what makes an incomplete sweep read finished**: the green suite now contains a test that demonstrably uses the right authority, so the stale twins draw no attention. Enumerate the restatements by SEARCH before fixing, and re-run that search after — a twin whose NAME already claims the narrowed property (`..._match_certified_digest` comparing against an unsigned field) is the shape that survives longest.
- **A "NO edit needed" list is an ASSERTION, not evidence** ⇒ re-verify every no-edit claim with a named search + rc + a POSITIVE CONTROL. The RULING under check decays the same way: attached-state rulings outlive the symbols and byte-states they name — one kept naming a map split away two units earlier, another asserted a byte-difference between copies when one copy did not exist ⇒ re-derive a ruling's factual core before restating, relocating or acting on it.
- **A one-KEYWORD source fix is invisible to a 100%-coverage suite** ⇒ credit EVERY applied fix by its own mutation, keyword flips included, and never let coverage stand in for a pin. `replay.py`'s `require_canonical_envelope=True` survived reversion against all 2925 tests at 100% branch, so it shipped UNPINNED beside 15 mutation-credited siblings. The pin is a test reaching a DIFFERENT verdict under the mutant (`exact` vs `integrity_failed`), never one that merely re-executes the line.
- **A prep wave DELETES scope, not only prices it.** A unit's planned text was written when its PREDECESSOR was unbuilt ⇒ re-derive "what is already true" before "what must change". Planned text also over-names VOCABULARY: before adding an enum member, demand a distinct fault with a distinct artifact/status shape.
- **PREP-PHASE review is the cheapest defect site found** ⇒ dispatch `rev` against the CONTRACT in the SAME wave as `test`, not after the code. A contract reviewer running concurrently with MAIN's implementation caught two reachability defects no post-hoc diff review would have reached in time. Every prep brief RESTATES the rulings that constrain its own answers ⇒ the agent measures ALREADY-SHIPPED code against them for free and reports the divergence as a row; that is how the M9.13a walkthrough was caught authenticating archived bytes against the unsigned POST verdict.
- **A prep wave's decisive section needs TWO independent owners**; opposite verdicts are the rule working. Poll the DELIVERABLE, not the gauge — a report byte-static across polls while its gauge climbs is unflushed work living only in a transcript. A flush directive lands EXACTLY ONCE per agent; a saturated agent is replaced, not steered.
- **A scope ruling silently CLOSES input paths other predicates assume** ⇒ after any scope ruling, re-derive reachability for every predicate whose input path it touches. A green-looking predicate can describe a state the supported API can no longer produce; reaching it then needs guard FORGERY, which pins forgery mechanics rather than contract behavior ⇒ pin type closure + choke POSITION separately instead. Keep the guard when a later milestone reopens the path — defense ahead of a known change is not an active bypass.
- **A diff-blind suite states a contract READING, not the contract**: where a delivered red asserts MORE than the ratified predicate, the predicate wins + the SUITE is corrected. Independent agreement between blind roles measures PLAUSIBILITY, never authority ⇒ diff a demanded strengthening against the contract text before implementing it.
- Teammate-name PREFIX collision: `context-gauge -p <name>` resolves a successor to its retired predecessor's transcript ⇒ resolve by exact filename before binding a watcher.
- **A stopped agent's LAST commit may never have executed, and `git worktree remove --force` then destroys the only copy** (`TaskStop` cuts mid-tool-call) ⇒ before pruning ANY worktree run `git -C <wt> status --porcelain` as its OWN call + treat non-empty as content to commit on the `wt/` branch. RECOVERY when already gone: replay the transcript's `Edit` calls (they carry exact `old_string`/`new_string`) onto the last real commit, then VALIDATE against an outcome the rebuild never consulted — never against the replay's own success count. Recovered reviewer checks are worth RERUNNING against the finished tree, not merely preserving: the passes are independent corroboration, the failures split into contract-reading disputes (predicate wins, suite is not chased) and genuine gaps — and a gap is only real once its mutant is re-applied and SURVIVES.
- Worktree-breach residue is silent until the gate runs (duplicate definitions, double-applied renames, dead near-duplicates — none visible in a reading pass) ⇒ after ANY breach run the static gate before trusting the file + diff for duplicate `def`s specifically. A brief must require the absolute `cd` prefix on EVERY command.
- Claim discipline: cite only RETAINED-log numbers; capture a log for every claim; frame unproven root causes as hypotheses; scope determinism to `(device, config)`.

Test design:
- A green INTERNAL gate (lint/type/100%-branch/structural asserts) does NOT prove EXTERNAL-contract validity ⇒ test output artifacts against the real consumer (jsonschema; a full vl-convert COMPILE).
- **100% branch coverage answers "did the line execute", never "does a red exist".** It misses data-DOMAIN gaps, cannot pin LOOKUP-TABLE entries, EXECUTES a line without pinning its EFFECT (an LRU recency refresh runs on every put/get yet stays unpinned), and does not pin each CONJUNCT of a compound guard when the only reachable input makes all conjuncts true at once. Mutation surfaces these; coverage never would.
- **An accepted finding closes on its ACCEPTANCE CHECK, never on a green gate.** Two recurring causes: a guard whose only reachable witness is FORGED gets no test for free; a DUPLICATED predicate hides its own earlier copy from every exception-based test (deleting the pre-sign call still raises, just after the signer ran) ⇒ only a call-counting bomb decides ordering. A fix adding a predicate some other layer already states ships its bomb test in the SAME edit.
- **A FAKE must match the real API's strictness, or it silently un-pins the finding it was built for.** Two measured shapes: a fake that TOLERATES a wrong spelling (a 1-D tensor stand-in also accepting the 2-D `(0, -1)` index) makes a reverted HIGH fix green in tests and red on every live call; a fake that IGNORES a keyword argument leaves that argument unpinned at 100% branch, because the canned return value is identical either way (`skip_special_tokens=True→False` survived a whole suite). Fakes inherited from a pre-review suite are the likeliest carriers — the tolerance was often added to make the WRONG pre-review spelling work. Assert on the RECORDED call, and reject in the fake whatever the real object rejects.
- **A test that reads a production constant to build its own expectation pins NOTHING about that constant** — three consecutive units lost HIGH findings to this shape ⇒ hand-state closed maps as LITERALS; derive only when the assertion IS the derivation (a topology test asserting the derivation itself is legitimate).
- **An exact KEY-SET assertion pins shape, never values** ⇒ it is not evidence that a forbidden carrier is absent, since bytes smuggle through any free-text field. Name the surface that scans raw bytes, or scan them.
- **A fail-closed ALLOWLIST/registry needs its REFUSAL pinned against NEAR-MISS inputs of the same family**, not only a generic outsider, plus every ID a later unit intends to add (a deferred ID asserted RED doubles as a scope guard).
- **CLOSED dispatch must enumerate every admitted variant.** An `if isinstance(A) … else: <B>` tail or a `.get(k, default)` on a variant/key space is a CATCH-ALL — this repo's most-repeated defect class, surviving a full green suite every time. Treat any such tail as a defect until a near-miss refusal pins it; parametrize absent-key siblings including dunder-shaped names.
- **INDEPENDENT bounds need their JOINT corner pinned**: per-axis boundary tests leave the compound maximum untested + a basis MEASURED on single-axis shapes understates the real worst case. Same for a fail-fast guard — mutation-test its ORDERING, not only its presence.
- **ORDERING pins need CALL-COUNTING BOMBS on the downstream work, not outcome assertions**, one bomb per distinct refusal REASON: hoisting hashing above a resource refusal, or sinking a row-limit guard below solver work, leaves the returned verdict unchanged + every outcome test green.
- **CALLER-SUPPLIED policy must be pinned as THREADED at every public entry SEPARATELY** — a sibling wrapper's kill is not your wrapper's pin. Pin with a policy STRICTER than default that must refuse; a default-equal policy proves nothing. **EQUAL-VALUE arguments hide the same defect + no output assertion catches them** ⇒ use an argument SPY plus a witness where the values DIVERGE, so the equality is provably incidental.
- **DECLARED-parameter AUTHORITY needs a DISAGREEMENT witness**: where a value carries metadata mirroring the declared parameter (a `Decimal`'s own exponent vs the declared scale), every agreeing witness lets a value-derived substitute pass.
- **Threading is not pinned by value equality, nor by patching the collector one call deeper** ⇒ patch the SEAM ITSELF, arm the layer beneath it as a bomb, assert IDENTITY (`is`), and make the witness disagree in every freely variable field with the equal-by-necessity fields named as an exact set difference.
- **Split canonical FORM from provenance WIRING wherever a byte pin swallows a live-collected field** — one comparison failing for two unrelated reasons is undiagnosable. FORM = byte-exact under an INJECTED fixed value, carrying across the MEASURED interpreter patches alone (never the whole admitted band); WIRING = each field equals its live source, loading NO vector. A wiring assertion goes circular the moment its expected side calls the collector under test ⇒ compare against ORIGINAL sources + pin `__struct_fields__` as an exact set so a new field cannot enter unwired.
- **A vector/oracle that REGENERATES the producer it pins is co-derived** — true even under fixed injected inputs, so injection buys portability, never independent authority ⇒ pair it with a HAND-AUTHORED fixed-value vector so field order + every tag discriminator are pinned independently of the builder.
- **A new caller-supplied seam inherits the validation of the VERSION it feeds, not the project's strictest version** ⇒ guard at the builder wherever the encoder does not.
- Guard witnesses must be MIXED, not uniform: a not-all-pass pin whose every result fails leaves `any`→`all` alive, and the survivor mints a certificate stamping a FAILED check `status:"pass"`.
- **Reachability asymmetry pins need SPLIT inputs, not paired ones**: where materialization derives two values from ONE drafted object, no test ever disagrees them independently ⇒ reach that cell through an externally re-signed input, which is also where the adversary lives.
- A metered guard's CHARGE-BEFORE-GUARD ordering is invisible to presence/refusal tests ⇒ pin the EXACT cumulative work at each refusal + failure (literal integers, never a production cost helper); "refused ⇒ consumed unchanged" and "admitted-but-failing ⇒ full charge retained" are separate assertions.
- Some guard sites admit NO isolating witness because their quantities are IDENTITY-COUPLED (a span equals the last offset; the first/last sample position equals the domain start/stop) ⇒ discriminate by stage-identifying exact-work/no-start witnesses rather than weakening the claim or dropping the test.
- **Exact-rational projections must never detour through `float`** + a binary-exact witness set hides it ⇒ include a non-binary decimal (0.2) in any exactness witness. **`Decimal(repr(f))` is an UNSOUND float-fidelity oracle**: recompute as `round(Fraction.from_float(f), declared_scale) == Fraction(d)` (exact HALF_EVEN, ambient-context-free), then emit `repr(f)` for its shortest round-trip property alone. Binds every future float projection incl. M11 `derive`.
- An oracle that deliberately IGNORES one production concern must STATE that boundary in the suite + CLASSIFY the one-sided outcomes as expected; counting them as agreement or as divergence both mislead. State the claim at true scope: end-to-end public-entry outcome equality evidences NO individual internal admission site. A green parity suite ≠ a correct oracle — verify the oracle INGESTS the shared coercer's cells + feed adversarial synthetics beyond the golden shapes.
- An equivalence differential must compare FULL messages + the cross-product of independent failure modes. **A differential that sets no `PYTHONPATH` can compare a tree against ITSELF** (an editable install's `.pth` resolves the package to the primary src from any cwd) ⇒ every differential ships a loud VACUITY GUARD; where whole-document equality is false by construction, compare a PROJECTION with added keys hand-stated.
- **A source-mutation probe must be PROVED to have applied before its exit code means anything** — a pattern matching nothing yields a silent no-op whose green run reads as "mutant survived" ⇒ pair every mutation with a `cmp`/grep confirmation + restore with a byte-identity check.
- Before adding a REVIEWER-PROPOSED pin, re-apply its exact mutant against the CURRENT tests — an existing test may already kill it; a reviewer's acceptance check is a hypothesis about coverage, not a verified gap. When re-verifying after an intervening fix pass, exact anchors CAN vanish ⇒ rebuild the mutant at the equivalent CURRENT seam rather than recording it inapplicable.
- MAIN's own mutation rerun is cheap + decisive (`-x --no-cov`, require non-zero rc, restore bytes + verify SHA-256 in a `finally`) ⇒ prefer it over accepting a fixer's self-reported kills.
- Order-sensitivity as a Hypothesis property is HOLLOW ⇒ one concrete anchor witness; a `PYTHONHASHSEED`-stability guard needs TIE-HEAVY rows + several seeds else it passes vacuously; "proves" overstates a bounded sample ⇒ "samples / finds no counterexample".
- An object-identity witness must RETAIN the objects through the assertion; recording only `id(obj)` lets CPython free wrappers + reuse addresses.
- Direct-helper fixtures must be REALIZABLE pipeline states; an acceptance criterion naming a multi-step scenario needs an END-TO-END pin through the public entry, not only the algorithm helper.
- A test embedding a symbol name as a substring ⇒ do renames via TARGETED edits, never `replace_all`.

Design:
- cast-not-assert: narrow `X | None` via `cast` at a gated use site — an `assert`'s never-taken branch fails the 100% gate. Any security gate resting on a decoded-shape invariant must RE-HOLD at the use site (path confinement = authoritative `resolve()` + `is_relative_to`) — BUT where a model string enters a path only via `Path(name).stem` or a `fullmatch` id regex, confinement is BY CONSTRUCTION + a runtime branch is unreachable (failing `warn_unreachable` + the 100% gate) ⇒ check constructability before planning such a branch.
- Per-element uniqueness ≠ global acyclicity: a backward walk over a schema-REBUILDING pipeline keys on (name, POSITION), never name alone.
- **Exception family must match what is actually wrong**: a bundle that just passed full authentication + content validation but hits an unimplemented path raises `NotImplementedError` naming the follow-on unit, never an integrity family, which would assert the data is corrupt.
- A stored-TEXT differential between two independent implementations of one DDL contract surfaces FORM noise ⇒ rule such a divergence on the admitted/refused SETS + treat exact text as binding only against the validator that consumes it.
