# M10.9 — held-out acceptance, measured ONCE

Two tiers, one unit. **kernel** = the scorer `capture/score.py` + the EXACTLY-ONCE guard (a scorer defect — a sentinel inside a denominator, a dead backend scored BLOCKED — is re-checked nowhere downstream). **data** = the capture `corpus/python/captures/m10-heldout/` + its `score.json`, re-validated at use by `python -m capture stats` (R1-R11 + S1-S4) and by the gate's byte re-derivation. Gate identity UNCHANGED: `bash tools/gate.sh`, 8 stages; probes 34/34. Rulings bound: `Intent` bar; IMPLEMENT-close ruling 2 (EXACTLY-ONCE guard); M10 ruling 4 (channel = capture run + verifier, no browser); phase-close ruling 2 (a miss commits, stays IMPLEMENT, hands back); ruling 7 of pysrc law (held-out unread until the run).

## Why the scorer is new code, not `w1_width.py`

`w1_width.py` turns an absent `content` into an empty source, which the verifier REFUSES — a dead backend would score complicated-BLOCKED 20/20 (consultant-1 P4, `w1_width.py` `defence(record["content"] or "")`). It is also outside the gate and design-only by assertion. The held-out number needs a scorer whose transport arm is distinct and whose output the gate re-derives.

## Predicates — S (scorer, kernel)

- **S1 — three outcomes.** Per record: `http_status != 200` ⇒ `transport_error`, verifier NOT called; else `source = capture.harness.defence(content)[1]` → `verify_python_source(source, declared_target=DatasetTarget(path=f"/mnt/uploads/{dataset_name}", content=<tracked data/<dataset_name> bytes>))` → `verified` | `refused` + its code. Accept: a call-counting bomb on the verifier stays at 0 for a transport row; one witness per outcome.
- **S2 — the target comes from the RECORD.** The declared target is the record's `dataset_name` over the tracked CSV bytes, never a path the program names. Accept: a program reading `/mnt/uploads/weather.csv` on a `sales.csv` record scores `refused`.
- **S3 — denominators.** `simple.total` = held-out simple rows (20), `complicated.total` = held-out complicated rows (20); sentinel rows enter NEITHER; a transport row stays in its category denominator and enters neither numerator. `simple.verified` counts `verified`; `complicated.blocked` counts `refused` only. Accept: a planted third sentinel record moves no denominator; a complicated transport row lowers `blocked`.
- **S4 — acceptance.** `acceptance_met` ⇔ `complete` ∧ `transport_errors == 0` ∧ `10·simple.verified ≥ 7·simple.total` ∧ `10·complicated.blocked ≥ 7·complicated.total` ∧ `sentinel-simple` = `verified` ∧ `sentinel-complicated` = `refused`. `complete` ⇔ the record id set equals held-out ids ∪ sentinel ids exactly. Accept: boundary witnesses 14/20 true · 13/20 false per category; each sentinel flip alone false; one transport row alone false; a missing row alone false.
- **S5 — per-row table.** One row per record, sorted by `prompt_id`: `{prompt_id, kind, category, idiom, dataset_name, outcome, code, mark, x, y, reduction}`; `code` non-null iff `refused`; `mark/x/y/reduction` non-null iff `verified` (from the `DatasetPlot`: `mark`, `x.name`, `y.name`, `group`). Accept: exact key set + both iff-conjuncts over a mixed run.
- **S6 — deterministic bytes.** `score.json` = msgspec JSON, indent 2, trailing newline, declaration order: `{version: "python-score-1", run, summary: {simple: {total, verified}, complicated: {total, blocked}, transport_errors, sentinels: {<id>: <outcome>}, complete, acceptance_met}, rows}`. No clock, commit, host or path field. Accept: two derivations byte-identical; the committed file decodes strictly (`forbid_unknown_fields`).
- **S7 — CLI.** `python -m capture score [<run-dir>…] [--write]`: `--write` writes `score.json`; bare = re-derive + compare, rc 1 naming each drifted directory, rc 0 otherwise; rc NEVER depends on `acceptance_met` (a recorded miss must gate green — consultant-1 P4, phase-close ruling 2). A run with no `score.json` under bare mode = rc 1. Accept: CLI tests over tmp runs, a met and an unmet score both rc 0.
- **S8 — EXACTLY-ONCE guard.** `heldout_guard(root) -> list[str]`: empty ⇔ exactly one run under `root` has `manifest.kind == "heldout"`, it is named `m10-heldout`, its record ids are complete (S4), and `score.json` exists. Accept: tmp roots with 0 · 1 · 2 held-out runs → 1 · 0 · 1 failures; wrong name, a missing row, an absent `score.json` → each 1 failure.
