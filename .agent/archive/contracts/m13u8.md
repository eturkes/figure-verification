## Blockers a naive pass walks into

Named because each ships green.

1. **Unwrapping ANY trailing call instead of `reset_index` alone.** `_admit_aggregation` admits one
   trailing no-arg non-underscore call, so `.sort_values()` is already ADMITTED and is refused only
   at projection. A `_aggregate` that unwraps whatever trailing call it finds therefore silently
   admits `.sort_values()` — which REORDERS the rows, so the plotted x-order stops being the group
   key order. G9's monotonic/unique-category reasoning and G8's row-coverage reasoning both assume
   that order. Nothing in the suite fails; the figure just stops matching the ledger. R3 is the only
   thing that catches it, and it has to be written as an exact-set assertion rather than as a single
   `.sort_values()` case, because the next trailing call added would slip through a one-case test.
2. **Projecting the accessor without entering the mark-counting seam.** A parallel route that builds
   a `DatasetPlot` directly leaves `multiple_marks` unfired, so `g.plot(kind="bar")` beside
   `plt.bar(...)` publishes ONE of two figures with no refusal. P6 catches it. The same seam carries
   `_mark_shape`'s keyword routing, which is what keeps `color=` out of the series label.
3. **Reading `kind` at projection instead of admission.** If admission accepts any `kind` string and
   projection maps it, then an unmapped `kind` reaches a `.get(kind, default)` — this repo's
   most-repeated defect class — or an `else:` tail that picks a mark nobody asked for. The kind map
   must be a closed dispatch with refusal as the tail, and P2's four refusals are one per shape
   rather than one representative case.
4. **Re-capturing before the code lands, or after it in a second commit.** The capture is the
   measurement's input and the code is what grades it; M1's number is meaningless if the two come
   from different tips. Land admission + projection first, then re-capture, then measure, then
   commit once. The M13.4 oracle lesson is the same shape: an artifact seeded from a skeleton commit
   proved nothing until it was re-based onto the code it graded.
5. **The mutation catalogues.** A widening silently invalidates anchors in catalogues this unit does
   not touch: M13.6 edited four lines that M13.3 and M13.4 mutants anchored on, and the driver
   reported ANCHOR-MISS rather than a kill. Rerun ALL THREE of `tools/mutants/{project,aggregate,
   csvread}.toml`, not just the one whose module changed, and add mutants for every predicate this
   unit ships — coverage alone credits nothing at kernel tier.
6. **`data/sales.csv`'s region column.** M13.7b's closed law binds here: a demo dataset may never
   spell a group key with a pandas NA spelling. The accessor rows group on `region`, so any fixture
   this unit adds must keep every region value outside `csvread.NA_SPELLINGS`.
