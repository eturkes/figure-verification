## What this unit decides

`Intent` wants ≥70% of simple prompts to verify. The width `pysrc.md` ruled for this unit
(`groupby` + `plt.barh` + a SECOND mark) was chosen against an idiom-coverage ceiling over the
held-out manifest, never against proposer output. Measured against proposer output it is aimed
past the bottleneck, and two of its three parts are wrong:

- Today's verifier verifies **0/25** simple design captures. **17/25** refuse `name_not_bound`
  because the proposer calls `pd.read_csv` without `import pandas as pd` — the program really would
  raise `NameError`, so the refusal is correct and no width repairs it. That defect is M13.7's, and
  its lever is the capture prompt.
- Repair that import hypothetically and it is **still 0/25**. The next blockers carry NO data
  effect: `plt.figure(figsize=)` in **16/25** prompts, `plt.tight_layout()` **6**,
  `plt.xticks(rotation=)` **6**, literal `color=`/`marker=`/`linestyle=` on marks **~20 uses**.
  `groupby` appears in **7**.
- The SECOND mark converts **zero** held-out prompts. It existed for heldout simple 06 and 14
  ("separate city lines"), but `weather.csv` is LONG — 8 rows = 4 dates × 2 cities — so two marks
  over two columns cannot draw two city lines. Those prompts need ROW SELECTION, and the design
  capture for that idiom writes `for city in set(...): df[df['city'] == city]`: a loop plus a
  boolean mask, neither admitted.

**User rulings that set this unit's width.** Admit the data-effect-free cosmetic cluster,
`groupby` aggregation, and `plt.barh`. Admit NO second mark: `CorePlotSpec` stays a two-member
union holding ONE mark each, the seven `assert_never(spec)` sites do NOT move, `PlottedTable` stays
one series, and G2 stays true by construction. Leave heldout 06/14 refused — the held-out simple
ceiling is **16/20 = 80%**, clearing ≥70% with ten points of headroom, which is more headroom than
`pysrc.md`'s own 75% path carried. G7 and G8 therefore stay UNCONDITIONAL rather than moving to
"a `Filter` projected AND published": with no filter admitted, the plotted column is still the
whole column.

Every ceiling assumes the proposer writes the admitted idiom. The measured rate lands below it;
M13.7 measures it and the held-out run scores it.

### R — the reduction engine, measured against pandas

Every number here is measured by spike-groupby-1 against pandas 2.3.1 on the host and both Pyodide
builds. The recomputation must reproduce what the executed program plots, not what is arithmetically
nicest — the more precise engine is the less faithful one, exactly as in M13.5's `expr.py` ruling.

| id | predicate | acceptance check |
|---|---|---|
| R1 | A float64 `sum` is an ordered per-group **binary64 Kahan** summation in file-row order: `s = c = +0.0`; per value in file order `y = float(v) - c`, `t = s + y`, `c = (t - s) - y`, `s = t`; return `s`. NOT naive left-to-right, NOT `math.fsum`, NOT Neumaier. MEASURED: Kahan 0/16,062 group differences; naive differs on 2,761/4,000 admitted-profile CSV groups; `fsum` differs on 1,483. | **The witness is four cells, every one inside C10's fixed-point profile:** `[1000000000.0, 0.000001, 0.000001, -1000000000.0]` gives Kahan (= pandas) `0x1.1000000000000p-19`, naive `0x1.0000000000000p-19`, `fsum`/Neumaier `0x1.0c6f7a0b5ed8dp-19` — three distinct values, so one four-row CSV separates every competing algorithm. Hex-float literals hand-stated. Plus the full differential against pandas over the committed reduction corpus, bit patterns, zero disagreements. A naive mutant and an `fsum` mutant each go red; both are catalogued. The 8,192-ulp figure quoted elsewhere is the random-cohort maximum, NOT a domain bound. |
| R2 | A float64 `mean` is R1's Kahan sum divided by the count of non-NaN values, in that order. Not a running mean, not a compensated divide. | Differential, bit patterns, zero disagreements. Witness where sum-then-divide and a running mean differ in the last bit. |
| R3 | An int64 `sum` stays int64 and is exact. An int64 `mean` is NOT the exact integer sum divided by the count: pandas casts each value to float64 first, then Kahan-sums, then divides. MEASURED witness `[2**53, 1, 0]`: pandas `mean` = `0x1.5555555555555p+51`, exact-then-divide = `0x1.5555555555556p+51`, a 1-ulp split. | Hex-float literal pin on both values; the implementation must return pandas'. A mutant computing the exact integer mean goes red on this witness alone. |
| R4 | `min` and `max` update on STRICT `<` and `>`, so a tie keeps the FIRST value's bits. Never a last-tie replacement. | MEASURED witness: `[-0.0, +0.0]` gives `-0.0` for both `min` and `max`; reversed gives `+0.0`. Compared as bit patterns, since `-0.0 == +0.0`. Unreachable under today's profile (C10 refuses sign-bearing zero) and pinned anyway, because the profile is what makes it unreachable and the profile is what a later unit widens. |
| R5 | Int64 `sum` overflow WRAPS in pandas (`[2**63-1, 1]` → `-2**63`). It is UNREACHABLE under C10: every cell is bounded to int32 and `max_table_rows` cannot supply the ~2**32 rows needed. The implementation does not emulate wrapping; it asserts the bound instead. | The unreachability is proven from C10's range and `max_table_rows`, as a test that computes the worst-case magnitude and asserts it below 2**63. A mutant raising `max_table_rows` past that point makes the test go red. |
| R6 | NaN cannot reach a reduction: C9 refuses every NA spelling per cell before any column-level question. So the NaN-skipping arm of pandas' reductions, and the compensation reset the measurement observed, are BOTH unreachable, and neither is implemented — an unreachable branch would fail the 100% branch gate. | A test asserts every NA spelling refuses `value_not_in_profile` ahead of the reduction, with a call-counting bomb on the reduction proving it never runs. The contract records that a profile widening admitting NaN must add both arms. |
| R7 | The group key order IS the plotted x-order and is pandas' `sort=True` default: keys sorted ASCENDING, by **Unicode code point** for strings and numerically for numbers. MEASURED locale-independent — identical under `C`, `C.utf8` and `en_US.utf8`, while an `en_US` collation control orders differently, which is what proves the test discriminates. | Sorted-order differential against pandas over a key corpus built to separate the candidates: mixed case, digits vs letters, embedded spaces, non-ASCII, and strings differing only past a common prefix. A mutant sorting with a locale collator, and a mutant preserving file order, each go red. |
| R8 | A key column read by `pd.read_csv` types as STRING whenever any cell is non-numeric, so `['2', 'a', '10', '2']` groups to `['10', '2', 'a']` — code-point order, not numeric. The verifier reproduces the dtype decision before the ordering decision. | Witness pair: a key column of numeric-looking strings beside one with a letter, asserting the two order differently. |
| R9 | Each group's member rows keep FILE order inside the group, which is what makes R1's ordered Kahan well-defined. | A CSV whose rows for one key are not in value order sums in file order; a mutant sorting within the group goes red. |
| R10 | `max_groups` bounds the number of groups; exceeding it refuses `work_budget_exceeded`. The reduction charges the work budget per row read and per group emitted. | Boundary witnesses at `max_groups` and `max_groups + 1`. A budget bomb asserts the charge happens. |

## Blockers the map found that a naive implementation walks into

Each is a real defect, not a style note. Recorded here because the contract is what the `test` and
`orc` teammates read.

- **`_uses_grid` runs BEFORE any statement and calls `_call_target` on every `ast.Call` in the
  tree** (`project.py:75`, `:119`). `_call_target` delegates to `_dotted`, which refuses whenever
  the attribute's receiver is not an `ast.Name`. The outer `.sum` of an aggregation chain has a
  `Subscript` receiver, so arm selection refuses `expression_not_projected` before `_assign` ever
  runs. The grid selector must recognize genuine `np.` grid calls without pushing every call
  through the Name-only path.
- **`_mark_shape` assigns `self._series` for every keyword** (`project.py:443`-`:453`) — W6b.
- **`_WRONG_ARM_MARKS` and `_MARKS` must gain `plt.barh` together** (`project.py:64`, `:84`). The
  formula path indexes `_MARKS[target]` directly, so a `barh` admitted into `_DATASET_MARKS` alone
  raises `KeyError` on the formula arm instead of refusing `mark_not_valid_for_arm`.
- **`tests/test_pysrc_integrity.py:33` currently pins G2 by refusing EVERY `plt.figure`.** Admitting
  it breaks that test by design; the replacement is W3's lifecycle witnesses, not a deletion.
- **Both differential suites normalize `Labels` explicitly**, so widening it breaks
  `oracle_project`'s and `oracle_dataset`'s field maps even for programs that did not change. Per
  `pysrc.md`, the map raises on a name it does not cover — update it deliberately.
- **The dormant G11 case in `tests/test_pysrc_dataset_differential.py` binds an UNUSED `groupby`.**
  Under A6 that program still refuses `statement_not_projected`. Do not convert it into a verified
  positive.
- **`errors.py:17` claims a stage never raises another stage's code, but `admit.py:192` raises
  `column_not_literal`, which the same file groups under project.** Pre-existing, outside this
  unit's contract, recorded as a register entry for `.agent/review.md`.
