## What this unit decides

The dataset arm is the clinical spine and the demo's whole acceptance surface: both committed
sentinels are `sales.csv` prompts, so no simple sentinel can pass until `read_csv` is admitted.

Width is RULED (user): **column pairs only** — `read_csv` → column selection → bar/line/scatter over
two columns. No `groupby`, no `sum`/`mean`, no derived expressions over columns. G11 stays dormant.
Aggregation is a later unit, and the width caps the first release rather than the ceiling.

`CorePlotSpec` stops being a one-member alias here. That break is deliberate: this repo has shipped
a defect where a union grew while a total map over it stayed green, so every consumer added at this
point needs its own exact-set pin.

## Declared rulings (settle the census's contract blockers)

- **G7/G8 are NOT decided by this unit.** Projection carries the facts they need — source path, the
  two column bindings, the mark — and deciding them requires recomputation against the user's bytes,
  which is M13.5. The projection gap for those two rules is therefore DECLARED OPEN here rather than
  claimed closed. Nothing in this unit's certificate text may imply a row-count or range guarantee.
- **G8's eligibility rule, ruled for when M13.5 implements it:** a row is eligible iff EVERY channel
  the mark encodes is non-null; the compared count is post-selection, pre-render. Under
  column-pairs-only there is no filter or aggregate stage, so "post-selection" is unambiguous.
- **G11 stays dormant** — the width admits no aggregate.
- **Provenance binding needs no new spec field.** `DatasetPlot.source.path` is the EXACT string
  literal the program passes to `read_csv`. M13.5 binds it to the user's uploaded bytes by comparing
  that projected path against a caller-supplied `declared_target`; the spec stays a description of
  the program, and the binding stays a check. This is what keeps a path-only `DatasetPlot` from
  becoming the trap the census warned about.
