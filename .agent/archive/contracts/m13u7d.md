# M13.7d — two security tests decide on the caller's umask rather than on the tree

Tier: **kernel**. The artifacts are two permission REJECTION tests, and the failure mode a fix can
introduce here is the worst one available: a test that no longer fires. `chmod` makes the fixture
deterministic, and a deterministic fixture that is also SAFE would pass vacuously forever. Rigor
therefore buys an explicit non-vacuity control per test, run under both umasks, on top of the
gate-level acceptance.

Gate identity: `bash tools/gate.sh`, eight stages, green at 8/8 on a clean tree at the closing
commit. No new stage, no threshold moved, no production source touched.

## What this unit decides

`bash tools/gate.sh` returns a different rc depending on the umask of the shell that invoked it.
Two tests build an UNSAFE fixture — a directory that grants group or world access — and assert that
the loader rejects it. Both build it with `Path.mkdir(mode=...)`, and `mkdir`'s mode argument is
masked by the process umask. Under `umask 0077` the requested group/world bits are stripped before
the directory exists, the directory comes out owner-private, the rejection correctly declines to
fire, and each test fails `DID NOT RAISE`.

Measured on one tree at one commit, before any fix: both fail under `umask 0077`, both pass under
`umask 022`. `mkdir(mode=0o755)` yields `0o700` under `umask 0077`.

The failure is LOUD, not a false green, so this was never a hole in the guarantee — the shipped
rejection works and the tests prove it whenever they run at all. What is broken is that one recorded
gate result stops being one claim: CI passes only because its umask happens to be `022`, and a
contributor on a hardened shell sees two red tests that describe nothing about their change.

CENSUS, and it is what bounds this unit: exactly TWO call sites in the tree pass an EXPLICIT
non-owner-only mode to a creation call. `tests/test_service_archive.py:621` (`mkdir(mode=0o750)`)
and `tests/test_service_identity.py:132` (`mkdir(mode=0o755)`). Every other EXPLICIT `mkdir`/`touch`
mode in the tree is `0o700` or `0o600`, which a umask can only leave intact, since a umask removes
bits and never adds them. The two production `os.open(..., 0o600)` sites are likewise unmaskable in
the direction that matters.

The word EXPLICIT is load-bearing and the census is worthless without it. `Path.mkdir()` defaults
its `mode` to `0o777`, so a call that passes no mode at all is the MOST umask-exposed shape in the
tree, not an exempt one: measured, a default `mkdir()` lands `0o755` under `umask 022` and `0o700`
under `umask 0077`. Tracked Python holds 77 such bare `mkdir`/`makedirs` calls — `bench/__main__.py`
line 286 among them — and the umask-removes-bits argument says NOTHING about any of them, because
there are no restrictive bits to preserve. What covers that class is the gate-level acceptance
below, not this census: `bash tools/gate.sh` returning rc=0 under both umasks re-decides every
default-mode site empirically. The hazard is real in the mirror direction: the archive loader's
`S_IMODE` checks in `src/verifier/service/archive.py` reject a state directory that is not
owner-private, so a default-mode directory reaching that loader would pass under `umask 0077` and
fail under `022` — the inverse of the failure this unit fixed. It is absent only because every
state-dir fixture passes an explicit `0o700`.

## Fix

`chmod` after `mkdir`. `chmod` sets the mode absolutely and is NOT masked; `mkdir`'s mode argument
is. With `parents=True` the intermediate directories keep their default mode and `chmod` moves only
the final component, which is the component both tests are about.

A umask fixture was rejected: it makes the test's meaning depend on a fixture running, leaves the
masked `mkdir` in place as a trap for the next reader, and would have to be applied per test rather
than once.

## Predicates

**D1 — the fixture has the mode the test intends, whatever the caller's umask.** Accept: in both
tests the directory's `stat().st_mode & 0o777` equals the intended group/world mode under `umask
0077` AND under `umask 022`. Firing input: reverting either `chmod` reproduces `0o700` under `umask
0077`.

**D2 — NON-VACUITY, per test, under both umasks.** A deterministic fixture that is safe would pass
forever. Accept: replacing the group/world mode with an owner-private `0o700` makes that test go RED
with `DID NOT RAISE` under BOTH umasks, and the shipped group/world mode makes it GREEN under BOTH.
Both halves are required — the red half proves the assertion still reads the mode, the green half
proves the fix works. This CORRECTS the acceptance check written at deferral time, which said a
planted `0o700` fixture "still fires the rejection"; that is backwards, since an owner-private
directory is exactly what the loader must ACCEPT, and a test that rejected it would be wrong.

**D3 — the gate's rc no longer depends on the invoking shell.** Accept: `bash tools/gate.sh` returns
the SAME rc on the same clean tree under `umask 0077` and under `umask 022`, both runs recorded.
This is the unit's acceptance, and it is broader than D1/D2 because it re-decides every other
mode-taking call site the census classified as safe.

**D4 — no rejection is weakened.** Accept: no assertion deleted, loosened, skipped, xfailed or
tier-demoted; the diff touches test fixture construction only, and no file under `src/` changes.

**D5 — the queue row retires.** Accept: `.agent/deferred.md` drops the umask row, its count in
`.agent/spec.md` moves with it, and `.agent/review.md` R34's status is amended to name this unit as
the fix rather than leaving the defect filed as open.

## What this unit does NOT do

- It does not touch the `0o700`/`0o600` call sites. The census shows a umask cannot strip a bit that
  is not requested, and D3 re-decides them empirically anyway.
- It does not add a umask fixture, a conftest hook, or a gate-level umask pin. Pinning the umask
  inside the gate would HIDE this class rather than fix it, and would make the next masked `mkdir`
  invisible.
- It does not change any production permission rule.
