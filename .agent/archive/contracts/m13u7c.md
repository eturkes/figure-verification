## What this unit decides

User ruling: spell the region code `US` rather than `NAM` in `data/sales.csv`, accepting that `US`
names a country while the column holds what was continent-scoped revenue. The data is MOCK and the
user has ruled the inaccuracy acceptable, so this unit changes a label and nothing else.

This is a REPLAY, not a new procedure. The predecessor demo-data unit renamed the same three cells
for a semantic reason — `NA` is one of the 19 default pandas NA spellings, so every
`groupby("region")` program over `sales.csv` refused `value_not_in_profile` — and built the
machinery this unit reuses: the idempotent re-derivation script, the repo-wide digest sweep, and a
classified change list. The risk profile here is STRICTLY LOWER, because the property that forced
the predecessor is already satisfied by both the old and the new spelling.

Three premises, each verified before any byte moved, because a replay that assumes its predecessor's
hazards still bind is how a cheap rename acquires an expensive surprise:

1. **`US` is not a pandas NA spelling**, so the refusal the predecessor removed does not return.
2. **`US` occurs nowhere in the tree as a word** — `git ls-files -z | xargs -0 /usr/bin/rg -nw -F
   'US'` returns no match (positive control: `EU` = 33 word hits) — so no rename can collide.
3. **The region code is a SORT KEY and this rename does not move it.** `EU` < `NAM` and `EU` < `US`
   both hold by code point (`E` = 0x45 < `U` = 0x55), so every expected table keeps its row order
   and a preserved ordering is not an accident this unit has to re-prove case by case.

The captures are LABEL-AGNOSTIC: no corpus file carries the region code as a word and none carries a
`sha256:` citation. Verification therefore cannot move, which turns the width re-measurement from a
tuning figure into a NEGATIVE control — see R8.
