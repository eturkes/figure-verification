# Q45 — computed values (kernel)

Tier **kernel**: the value vocabulary decides `value_not_found`; a widened vocabulary passes figures nothing re-checks.

## Row

A drawn value that is a fixed transform of the CSV's or the request's numbers (squares of `1 to 10`, a cumulative sum, a share of total, a ratio of two columns) blocks, since the value vocabulary is raw values + one group-and-reduce. Accept: a closed transform list, no transform reading the request wording (no inference); each transform ships with its chance-match rate measured over `data/*.csv` + random made-up series of 1-10 points and recorded beside it; a value no listed transform explains still blocks; per transform ≥1 honest twin passes + ≥1 wrong-value program blocks.

## Rulings (user, session 10, AskUserQuestion)

- **U1** admitted: CSV one-column math (running total, share + percent of total, change from the previous point, square — of one vocabulary series), CSV two-column math (ratio, difference, product, sum of two numeric columns, per row or per group), math on typed numbers (squares, running total, differences, shares + percents of the request's numbers).
- **U2** no minimum series length (the user accepted X1's one-point chance, up to 10.5% for typed numbers on a short range).
- **U3** MAIN replaces `Intent`'s data sentence with the approved bytes, the `[at least N points]` clause dropped (U2): "The data is an attached CSV's raw values or one group-and-reduce of them, or the numbers typed in the request, with ranges such as `1 through 10` or `1から10まで` expanded, or one admitted computation of that data (a running total, a share or percent of the total, the change from the previous point or the square of one series; the ratio, difference, product or sum of two columns, per row or per group)."

## Evidence before the ruling (X1, `.agent/measurements/x1_transforms.py`, `expected/X1.json`)

Nine candidates: of one vocabulary series (raw, index, group sum/mean/min/max, count) — `square`, `cumsum`, `share` (v/Σ), `percent` (100·v/Σ), `diff` (consecutive); of two numeric columns per row and per group sum — `ratio`, `difference`, `product`, `total`. The request leg applies the five one-series transforms to `1 to m` (m = 3, 5, 10) and m random integers in [1, 100]. ## Design (MAIN; revised after consultant-1, verdicts below)

- **D1 two passes.** The judge's values + columns stages run once as today (pass 1). A figure pass 1 passes keeps that verdict + interpretation byte for byte. A figure pass 1 blocks with `value_not_found`, `label_not_in_request`, `column_not_requested`, `column_not_named` or `label_not_consistent` runs them again (pass 2, a fresh `MAX_WORK` budget) with the vocabulary AND the computed candidates competing per series (R7 ties as today), then the typed transforms for a series still unexplained; pass 2 passing publishes its choices; pass 2 explaining every value but blocking on a column (pass 1 blocked on a value) shows pass 2's column reason, the one that tells the user what to fix; else pass 1's blocked verdict stands (its reason, its site). ⇒ widening is monotone, legacy reasons unchanged, a computed value can rescue a series whose coincident raw column failed anchoring (consultant Q2 witness `shadow`).
- **D2 CSV one-series transforms**, over every vocabulary explanation `E` (raw, index, raw(K,K), group sum/mean/min/max, count; R6 filters as today) in E's pair order (pandas order; no key-sorted reorder): `square` v·v, `cumsum` sequential running total, `diff` v[i] − v[i−1] keyed by pair i (pair 0 has none), `share` v / T, `percent` (100·v)/T | (v/T)·100 | v·(100/T). T = one whole-series total per variant: numpy pairwise (`Series.sum`, `np.sum`; stdlib replica, 0/20,000 host mismatches), sequential (`sum` over numpy scalars, a loop), Neumaier (`sum` over Python floats, CPython ≥ 3.12), Kahan (`groupby().sum()`), `math.fsum`. Keys, rows + columns = E's; G11 counts = E's.
- **D3 CSV two-column**, numeric columns a ≠ b, op ∈ `ratio` a/b, `difference` a−b, `product` a·b, `total` a+b, one IEEE operation: per row keyed by any column K (a and b included) or by row position (`index`); per group by K ∉ {a, b} over both columns' Kahan group sums (pandas `groupby().sum()`), G11 counts published. Ordered pairs for ratio + difference; product + total once per pair.
- **D4 typed transforms.** `request.py::Request.sequence` = the request's numbers in typed order: each number's whole reading (`1,200` = 1200; `1, 200` = two numbers), a range expanded in place in its typed direction, ends alone past `MAX_RANGE`, repeats kept, no number dropped (a year typed in the request is an operand). Transforms over it as D2 (one sequence, every total + percent variant). One typed transform explains a series when every point's value is in its set (exact membership, as typed numbers are) and every key passes R4. Publication names the operands (first 8, then `…`).
- **D5 exact matching per variant.** Every candidate = one whole-series variant, matched exactly in binary64 as every explanation is (the existing injective matcher, unchanged); no tolerance. A pair whose value is not finite, or whose denominator is zero, has no candidate. Supported spellings = the variants above; another spelling (`pow` off by an ulp, a pairwise group sum through `apply`, a rounded value) adds no candidate and blocks unless its bits coincide.
- **D6 one explanation per series.** Pass 2 competition: same columns ⇒ canonical = the vocabulary explanation, then the first of `square cumsum diff share percent ratio difference product total`, then a computation drawn whole before one drawn in part (a running total over rows equals the running total of group sums at each group's last row), then base family order, then generation order (table, filter, variant); different columns ⇒ R7. Typed transforms: first in the same order.
- **D7 G10.** A computed explanation's columns count as drawn. Summary words: a one-series computation keeps its base's reduction (`Median` over the square of a group sum blocks); a two-column group computation contributes `mean` for ratio (a ratio of sums is an average per unit: `Average revenue per order`) and `sum` for difference, product, total; a per-row computation contributes none.
- **D8 marks.** Every mark that carries drawn values takes computed candidates: series, histogram inputs, pie values, and scatter channels (R8: a channel takes D2 + D3 per-row candidates over its main explanation's rows or groups, each value bound to its own point's row or group, computed main explanations included). Reference marks keep their closed sources (zero, a typed number, a cell, a whole-column reduction): one number has no series to compute over. Scaling by a constant (`s=df.x * 3`) is no admitted computation. These operations add no candidate; a program's output that coincides with an admitted explanation still matches it (the verifier reads the figure, never the program).
- **D9 publication.** `interpret.py` names the computation (EN + JA), operand order included: `the running total of <base>`, `<a> divided by <b> by <K> from <file>`, `the sum of <a> divided by the sum of <b> per <K>`, `the squares of the numbers typed in the request (1, 2, 3, …)`.

## Predicates

- **C1 closed list** — exactly D2 + D3 + D4 under D5; a value no listed variant explains blocks; nothing reads request words.
- **C2 legacy invariance** — every corpus case that PASSED as of `ab88b57` returns the identical verdict + interpretations (EN, JA); a figure pass 1 passes never runs pass 2 (call-count witness). A legacy block may pass only through an admitted computation: over the 201-case legacy corpus exactly one did — `tied-columns` (`twins.csv` 1, 2 by name), whose values equal the running count of rows per name, the one explanation whose columns the request names (R7). That fixture moved to 3, 7 to keep its R7 witness; `running-count-dissolves-a-tie` pins the new reading (`twins12.csv`).
- **C3 variants** — each D2 total + percent variant reproduces numpy 2.2.5 / pandas 2.3.1 / CPython bits on the host AND in the installed Pyodide bundle (measurement C1 over the new corpus cases); a value one ulp off blocks.
- **C4 corpus** — per transform (9 CSV + 5 typed) ≥ 1 honest twin passes + ≥ 1 wrong-value program blocks `value_not_found`; pass-2 rescue (`shadow`), operand keys, a computed channel, G10 (D7) witnessed.
- **C5 rates recorded** — X1 measures the SHIPPED candidate generator + matcher (pass 2 explains, pass 1 does not), per transform and combined, unsupported lengths `null`; each rate published beside its transform in `docs/verification.md` (EN + JA) + `.claude/rules/figure.md`.
- **C6 budget** — pass 2 charges its own `MAX_WORK` for candidate generation + typed computations (matching stays uncharged in both passes, as in pass 1: a charge there would move legacy budget verdicts); exhaustion leaves pass 1's verdict; the outlet judges in a worker thread. Cost (host, a made-up 3-bar figure over a random CSV, both passes): 1k rows × 4 numeric 0.6 s (pass 1 alone before Q45: 0.2 s), 10k × 4 2.2 s (1.0 s), 10k × 8 3.3 s (3.0 s); 100k rows exhaust `MAX_WORK` in pass 1 (0.3 s). Key forms are cached, a candidate sharing no value with the series is skipped, a value sequence's computations are memoised.
- **C7 law + claims** — `Intent` (U3), Decisions ruling, `claims.md`, `figure.md` § Values, R8 sentence, reference + admin guide EN + JA, "Show checks" values row EN + JA.
