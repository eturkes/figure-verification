# M17.1 — Japanese text in a sandbox chart: CJK fallback font

Tier **kernel**: `webui/paste_in/filter.py` is the sole publication path and `wrapper_code` = the bytes the sandbox executes around the model's program; a defect here (a moved verdict, an escaping exception, a font read before the verdict, a prelude that alters stdout) has no downstream re-check.

## Facts (measured, this request)

- Any CJK glyph in a figure — title, axis label, legend label, a Japanese category tick, a Japanese header pandas uses as a default axis label — makes matplotlib write `UserWarning: Glyph <n> (…) missing from current font.` to stderr; the installed Pyodide 0.28.3 bundle carries DejaVu/STIX/cm fonts alone. stderr non-empty ⇒ `_reply_fault` → `sandbox_error` ⇒ every Japanese-text figure FAILS today, demo + production (Kimi writes Japanese labels for Japanese users). Witness: `.scratch/ja/glyph.mjs` over the installed bundle (`ja_title`, `ja_ticks` stderr non-empty; `ascii` null).
- Open WebUI 0.10.2 ships `static/fonts/NotoSansJP-Regular.ttf` (5,732,824 B, family `Noto Sans JP`) under `open_webui.env.FONTS_DIR` (default `OPEN_WEBUI_DIR/static/fonts`), loaded by OWUI's own chat-PDF export (`utils/pdf_generator.py`) ⇒ inside `Intent`'s dependency envelope, network-less, no rebuild.
- Base64 font in the RPC source (7.64 MB), written to the sandbox FS, `font_manager.fontManager.addfont` + `rcParams['font.family'] = ['DejaVu Sans', 'Noto Sans JP']`: Japanese title + ticks render, stderr null, Latin text stays DejaVu (bundle under Node: 7.8 s first run, 2.1 s second). Live, real-model stack + a throwaway filter hack: a `clinic_ja.csv` line chart with Japanese title/labels/ticks → `Figure verification passed`, 1 PNG, stable over reload, 108 s incl. generation ⇒ the payload survives OWUI's socket path + sandbox host.
- Mathtext is outside the fallback (consultant-1, `.scratch/consultant-1/text-routes.json`): `title('$年$')` and a text marker `marker='$年$'` (admitted; `project.py` discards marker strings, so `Labels` stays empty) render through the mathtext fontset, which `font.family` does not reach ⇒ `Font 'rm' does not have a glyph for '\u5e74' … substituting with a dummy symbol` on stderr with OR without the font. A repeat in the SAME runtime may stay silent (cache), so "a missing glyph always writes stderr" holds per fresh runtime only.
- `/static` is NOT a sandbox source: plain `StaticFiles` behind `CORSMiddleware(allow_origins=CORS_ALLOW_ORIGIN)` (only `/pyodide` forces `Access-Control-Allow-Origin: *`), and the sandbox iframe's origin is `null` ⇒ an admin-restricted `CORS_ALLOW_ORIGIN` would block a fetch. Bytes travel inside the RPC instead.

## Rulings

- **U1 (user).** Ship a CJK fallback font: the filter reads OWUI's bundled Noto Sans JP in-process; the wrapper registers it as matplotlib's fallback after DejaVu Sans. Both pairs (one `filter.py`, two generated artifacts).
- **U2 (MAIN, advisor-confirmed).** Whole font, no subsetting: fontTools subsetting measured 0.50 s / 11,572 B per typical chart in OWUI's env (fontTools 4.63.0 via `fpdf2==2.8.7`) but adds a runtime import, a dev dependency + a glyph-collection predicate; reversal is cheap ⇒ `.agent/deferred.md` row.
- **U3 (MAIN).** Font only when the figure can draw a non-ASCII character; every other RPC stays byte-identical to the pre-unit wrapper (F7/O8/M15/M16 evidence untouched).
- Unchanged: `PASS_TEXT`, `FAIL_TEXT`, the publication gate (F2-F6), `observe.py`'s comparator, `REASONS`/`CHECK_OF` (no new reason), the tool's model-facing strings, the receipt.
- **U4 scope (MAIN, consultant-1 C2).** The repair covers ORDINARY matplotlib text (title, axis labels, legend text, tick labels). CJK inside mathtext (`$…$` in any string) or a text-shaped marker stays unrepaired — declared limit, fail-safe (stderr ⇒ `sandbox_error`); `_needs_font` is not widened for it, because no trigger can fix the mathtext fontset.
- Trust (consultant-1 C3): font handling runs after the static `Verified` verdict + the `no_browser` arm and cannot bypass admission, recomputation or the observation comparator; font correctness + the pixels are renderer trust (`.claude/rules/claims.md`). A font changes glyph choice, layout, stderr + render time: a corrupt font or extra latency can turn a passing chart into a FAIL, never a FAIL into a false PASS. The repair intentionally turns today's Japanese-text `sandbox_error` FAILs into PASSes.
