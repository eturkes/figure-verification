# Q44 — subset the CJK font per figure

Tier **kernel**: the font decides which glyphs the sandbox can draw, and the reader's glyph count decides `glyph_missing`; no downstream check re-reads the font.

## Row

The filter sends the whole 5,732,824 B `NotoSansJP-Regular.ttf` (7.64 MB RPC source) on every Japanese-text render; fontTools 4.63.0 ships in the Open WebUI 0.10.2 image via `fpdf2==2.8.7` and subsets a typical chart's glyphs in 0.50 s to 11,572 B. Accept: a Japanese-label + Japanese-tick figure's RPC source < 100 KB, F7 `ja-font` stays clean with every glyph drawn (PNG inspected), a glyph-collection miss can only FAIL (witness), and the fontTools import degrades to the whole font when absent.

## Found at orientation (MAIN, ee9518e)

- OWUI 0.10.2 caches ONE Pyodide worker per tab (`nodes/0.VsCm_E_x.js` `ue()`: `$() || Ra()` stored in `Ut`; terminated only on the 60 s limit) ⇒ matplotlib state persists across replies.
- Host (matplotlib 3.9.4, test font cut to `患者` then `診療科`, `.scratch/q44/hazard.py`): the second `reader.run` in one interpreter counts 6 missing glyphs, same path AND distinct paths: `addfont` appends a second `Noto Sans JP` entry and `findfont` keeps the first; a reused path also keeps the cached `FT2Font` (`_get_font`, keyed by path). Distinct path + same-name entry replacement ⇒ 0. A naive subset would block every later Japanese chart in a tab whose characters differ.

## Predicates

- **F1 collection** — `_needs_font` (W2) unchanged. The filter cuts the font to every non-ASCII character of the program text and of each owned file decoded as UTF-8 (undecodable bytes dropped). Family name kept (`Noto Sans JP`): a program that sets `font.family` to it still draws.
- **F2 degrade** — fontTools absent, or any fault while cutting ⇒ the whole font (today's bytes). The cut runs off the event loop; a cancelled await propagates. An absent font file ⇒ `None`, as today.
- **F3 miss = FAIL** — a drawn character outside the collection (a `\uXXXX` escape, a character the program builds at run time) has no glyph in the cut ⇒ matplotlib warns ⇒ the reader counts it ⇒ `glyph_missing`. Host test + F7 bundle leg `ja-miss`.
- **F4 one runtime, many replies** — each distinct font gets its own path (`/tmp/figure-verification-cjk-<sha256[:16]>.ttf`); the reader's registration drops earlier registrations of the same family name first ⇒ a later reply whose cut holds glyphs an earlier one lacked draws them all. Red on ee9518e (host); F7 bundle leg `ja-second` (two cuts, one runtime).
- **F5 size** — F7 `ja-font` (Japanese title + y label + Japanese category ticks over `data/clinic_ja.csv`, cut by the installed image's fontTools) RPC source ≤ 99,999 B; its PNG inspected: every glyph drawn. `ja-whole` (the degrade bytes) stays clean too.
- **F6 envelope** — the generated artifacts may import `fontTools` (image: `open-webui==0.10.2` → `fpdf2==2.8.7` → `fonttools>=4.34.0`), function-local and guarded; nothing else widens.
