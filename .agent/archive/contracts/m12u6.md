# M12.6 — capture record format + capture driver (contract)

M12.6 as planned was ONE unit. WORK-UNIT entry re-split it (prep waves hold sizing authority):
bottom-up ≈ 220K raw × 1.24 (kernel band) clears the ~190K split trigger, and the scope is two
instruments with a clean seam.

| unit | scope | seam |
|---|---|---|
| **M12.6a** (this contract) | `capture/record.py` — versioned record + run schema, canonical encodings, the outbound-body builder, provenance collection, run writer/loader, structural validator R1–R11, hand-authored golden run | everything the committed EVIDENCE format is, plus the request bytes it must prove |
| **M12.6b** | `capture/harness.py` + `capture/__main__.py` — live HTTP driver over `POST /v1/chat/completions`, per-row record emission through 6a's writer, offline replay + derived stats (fence rate, `ast.parse`-after-defence rate, truncation rate) | everything that TALKS to the backend or DERIVES a statistic |

The safety-critical byte (`guided_schema` never on the wire) lands in **6a**, not 6b: 6a owns
`build_request_body`, so 6b cannot spell a body 6a did not build, and R2 + R11 grade every
committed record against that one builder.

## Tier + gate

`tier=kernel` (the validator is judgment-bearing; M12.7's committed artifacts are graded by it).
DONE gate = the roadmap's quality gate rc 0 ×4 under `uv run --locked` + the golden byte-pin +
`python -m capture.record` rc 0 on the golden run.

`capture/` sits outside `[tool.coverage.run] source = ["verifier"]` ⇒ the 100%-branch gate does NOT
reach this module. Its tests are its only coverage, so a predicate without a near-miss refusal test
ships unpinned. That is the standing risk this contract prices.

## Rulings this unit is implemented under

- **R-mode.** Captures are UNGUIDED (active-track ruling 5). The outbound body carries exactly
  `{max_tokens, messages, model, temperature}`; `guided_schema` is ABSENT, never `null`. Backend
  `structured_output=true` stays on — M12.3's `guided_schema=None` ⇒ 0 logits processors pin proves
  omission suffices, so the capture never needs the operator to disarm the backend.
- **R-label.** Every record and every run manifest carries `mode="python_raw_unconstrained"`. The
  validator refuses any other value, so a python capture and a `vplot_json_guided` bench run can
  never be aggregated by a later reader.
- **R-keyorder.** Canonical key order is msgspec struct DECLARATION order at every level — records,
  manifest, request body and its message objects alike — never sorted. `REQUEST_KEYS` restates the
  body's top level (which happens to read alphabetical) and binds nothing below it, so the one user
  message emits `{"role", "content"}`. `build_request_body` stays the sole speller, so no reader
  ever needs the order to be guessable from outside the module.
- **R-canonical.** Raw model bytes are the artifact. The record stores the model's exact content
  string plus its UTF-8 sha256 and byte length; NO de-fencing, NO normalization, NO re-emission.
  De-fence is a DERIVED statistic and belongs to 6b.
- **R-provenance-split.** Provenance is three blocks that never merge: `repo` (committed-state
  facts, authoritative given `git_commit` + `git_dirty`), `service` (observed over `GET /health`),
  `host` (observed via `nvidia-smi`, best-effort, `None` when the tool is absent). A merged block
  would report an observed fact for a declared one.
- **R-recapture.** A capture set is evidence for ONE model at ONE dtype. `model_repo_id`,
  `model_revision` and `engine_dtype` are graded against the LIVE pins, so changing the model or
  the dtype INVALIDATES every committed run and forces a re-capture rather than silently
  re-labelling old bytes. `runtime_lock_sha256` is format-graded only — a dependency bump is
  routine and moves neither the model nor the calibration lever.
- **R-freshness.** `prompt_sha256` is graded by re-rendering the corpus row through
  `render_capture_prompt`, so editing a prompt or the capture template invalidates every capture
  taken before it (the `.claude/rules/python-corpus.md` semantics, extended to records).
- **R-no-clock.** No wall-clock field anywhere. A run must re-encode byte-identically from its own
  decoded contents (R9), and a timestamp would make every committed run undiffable.
- **R-heldout.** Ruling 7 discipline is enforced structurally at run scope: a run's records come
  from `{manifest.kind} ∪ {"sentinels"}` alone, so a `design` run cannot smuggle a held-out row.

## Public API (the surface the red suite is written against)

```python
RECORD_VERSION: Final = "python-capture-1"
CAPTURE_MODE: Final = "python_raw_unconstrained"
REQUEST_KEYS: Final[tuple[str, ...]]          # ("max_tokens", "messages", "model", "temperature")
BANNED_REQUEST_KEYS: Final[frozenset[str]]    # guided_schema, guided_json, response_format, grammar
FINISH_REASONS: Final[tuple[str, ...]]        # ("length", "stop")
CAPTURES_ROOT: Final[Path]                    # corpus/python/captures
RUN_NAME: Final = "run.json"
RECORDS_NAME: Final = "records.ndjson"

class Usage:             prompt_tokens, completion_tokens, total_tokens
class HostProvenance:    driver_version, compute_cap, gpu_name, memory_total_mib
class ServiceProvenance: model_name, device, structured_output
class RepoProvenance:    git_commit, git_dirty, model_repo_id, model_revision, engine_dtype,
                         runtime_lock_sha256, capture_prompt_sha256
class Provenance:        repo, service, host
class CaptureRecord:     version, mode, run, prompt_id, kind, category, idiom, dataset_name,
                         prompt_sha256, request_sha256, request_keys, http_status,
                         content, content_sha256, content_bytes, finish_reason, usage, error
class RunManifest:       version, mode, run, kind, model, model_base_url, max_tokens,
                         temperature, record_count, provenance
class Run:               directory, manifest, records, run_bytes, records_bytes

def build_request_body(*, prompt: str, model: str, max_tokens: int, temperature: float) -> bytes
def build_record(*, run: str, prompt: Prompt, kind: Kind, request_body: bytes, http_status: int,
                 content: str | None, finish_reason: str | None, usage: Usage | None,
                 error: str | None) -> CaptureRecord
def collect_repo_provenance(root: Path = REPO_ROOT, *, runner: CommandRunner = ...) -> RepoProvenance
def collect_host_provenance(*, runner: CommandRunner = ...) -> HostProvenance | None
def encode_run(manifest: RunManifest) -> bytes
def encode_records(records: Sequence[CaptureRecord]) -> bytes
def decode_run(raw: bytes) -> RunManifest
def decode_records(raw: bytes) -> tuple[CaptureRecord, ...]
def write_run(directory: Path, manifest: RunManifest, records: Sequence[CaptureRecord]) -> None
def load_run(directory: Path) -> Run
PREDICATES: dict[str, Callable[[Run], list[str]]]
def validate(directory: Path) -> list[str]
def main(argv: Sequence[str] | None = None) -> int
```

Every struct is `msgspec.Struct, frozen=True, kw_only=True, forbid_unknown_fields=True`. Every
predicate returns a list of human-readable failure lines and never raises on well-typed input.
`validate` prefixes each line with its predicate id, exactly as `capture/corpus.py` does.

## Predicates (R1–R11 — implemented ONCE in `capture/record.py`, called by the suite)

| id | name | claim |
|---|---|---|
| R1 | `check_versions` | manifest + every record declare `RECORD_VERSION` and `CAPTURE_MODE`; a foreign mode or version is refused, so cross-mode aggregation is structurally impossible |
| R2 | `check_unguided` | every record's `request_keys` equals `REQUEST_KEYS` exactly, and its intersection with `BANNED_REQUEST_KEYS` is empty |
| R3 | `check_run_identity` | `manifest.run` = directory name = every `record.run`; `record_count` = len(records); `prompt_id` unique across the run |
| R4 | `check_corpus_binding` | every `prompt_id` resolves in the committed corpus with equal `kind`/`category`/`idiom`/`dataset_name`, and `prompt_sha256` = sha256 of `render_capture_prompt(row)` |
| R5 | `check_run_scope` | every `record.kind` ∈ `{manifest.kind, "sentinels"}` |
| R6 | `check_outcome_shape` | 200 ⇒ `content`, `content_sha256`, `content_bytes`, `finish_reason`, `usage` all PRESENT and `error is None`; non-200 ⇒ all five ABSENT and `error` a non-empty string. Disjoint, never one boolean |
| R7 | `check_content_integrity` | `content_sha256` = sha256 of `content.encode("utf-8")`; `content_bytes` = its length |
| R8 | `check_usage` | `usage.total_tokens` = `prompt_tokens + completion_tokens`; all three ≥ 0; `finish_reason` ∈ `FINISH_REASONS` |
| R9 | `check_canonical_bytes` | the on-disk `run.json` equals `encode_run(manifest)` and `records.ndjson` equals `encode_records(records)` — the file IS its canonical form |
| R10 | `check_provenance` | `git_commit` is `None` or 40 lowercase hex; `runtime_lock_sha256` and `capture_prompt_sha256` are 64 lowercase hex; `capture_prompt_sha256` = `CAPTURE_PROMPT_SHA256`; `model_repo_id`, `model_revision`, `engine_dtype` equal the live pins (R-recapture) |
| R11 | `check_request_reproduces` | `sha256(build_request_body(prompt=rendered, model=manifest.model, max_tokens=manifest.max_tokens, temperature=manifest.temperature))` = `record.request_sha256` for every record |

## Invariant surfaces (what the validator cannot check about ITSELF — the suite owns these)

| id | surface | acceptance check |
|---|---|---|
| I1 | closed predicate set | `PREDICATES` keys are exactly `R1..R11`, hand-stated as a literal, never derived from the dict |
| I2 | strict decode | `decode_run`/`decode_records` refuse near-miss inputs of the SAME family: unknown field, absent field, wrong `version`, wrong `mode`, float where int is declared, a `records.ndjson` line that is not an object, a blank trailing line beyond the canonical one |
| I3 | golden byte-pin | `tests/golden/capture-golden-v1/` re-encodes byte-identically from HAND-AUTHORED structs, and `validate` returns `[]` on it (positive control) |
| I4 | near-miss refusal | each of R1–R11 fails on a one-field mutation of the golden and on nothing else — a mutation kills exactly its own predicate |
| I5 | no wall clock | no struct field and no encoded byte carries a timestamp; `__struct_fields__` pinned as exact tuples so a new field cannot enter unnoticed |
| I6 | body shape | `build_request_body` emits exactly `REQUEST_KEYS`, one user message holding the rendered prompt verbatim, and is byte-stable across calls |
| I7 | subprocess seam | `collect_repo_provenance` / `collect_host_provenance` take an injected runner; a missing tool, a non-zero rc and unparseable output each degrade as contracted (`git` → `(None, False)`; `nvidia-smi` → `None`), never raise |
| I8 | CLI | `main` returns 1 with failure lines on stderr for a bad run, 0 for the golden, and grades every directory under `CAPTURES_ROOT` when given no argument |
