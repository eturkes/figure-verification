- V1 Admin surface: production tool `Valves.column_aliases` (text, one line per column: `<column> = <alias>, <alias>`; blank lines ignored). OWUI builds `Valves(**form)` on save, so a malformed line, an empty alias or an alias repeated in one line fails the save. Default empty ⇒ every verdict as today. The demo pair inherits the field, default empty.
- V2 Trust: aliases are admin configuration, never model- or user-supplied. The tool records the parsed aliases in its backend receipt (tag `/2`); the filter's publishing verdict reads them from that receipt alone.
- V3 Semantics (core `DatasetTarget.aliases`, stdlib): an alias is another name of its column wherever a header name counts — exact naming, the one-edit tier, Q38 stop/negation, Q41/Q42 short words, G10 labels — under both anchoring rules. An alias of a column absent from the file's header is ignored. An alias two columns share, or equal to another column's name, is a tie (names nothing; naming it refuses `column_not_requested`, as fold twins do). A column with an anchoring-length alias becomes nameable under strict.
- V4 The core stays stdlib; `pydantic` appears only in the paste-in wrapper (part of the OWUI image).
