# M20.4 — reader + excerpts: a tick-style call (`plt.xticks(rotation=45)`) appeared in no row

Tier **kernel**: `src/verifier/figure/reader.py` hooks wrap matplotlib calls the program makes, so a hook defect changes the program run and with it the verdict; `webui/paste_in/excerpts.py` quotes model bytes into the user's chat with no downstream re-check.

## Finding

`docs/verification.md` § "How to read Show checks" promises that the Honest axes row lists "the calls that set limits, scales, inversion or ticks". `plt.xticks(rotation=45)` passes no ticks + no labels ⇒ pyplot calls `Axes.get_xticks` + `get_xticklabels` and updates each label: no recorded setter runs ⇒ banner arm `simple` line 16 appears in no row but `program`. Same gap: `ax.tick_params(…)`, `plt.tick_params(…)`, `ax.xaxis.set_tick_params(…)`.

## Rulings

- **Y1 (user, session 9 follow-up)** "You can add `plt.xticks(rotation=45)` if it would be beneficial to have it as part of the recorded set."
- **Y2 (MAIN, advisor)** a display-only slot `style` on the `Axis` object the call styles, never a failure site: the `xticks`/`yticks` slots decide `tick_label_mismatch`'s mark, and a later rotation call there would take it from the line that set the labels. Listed in the axes row alone (a tick style changes no glyph, so the figure row keeps the tick-label calls only). Per-label forms (`plt.setp(ax.get_xticklabels(), …)`, a label loop, `fig.autofmt_xdate()`) stay unrecorded + stated.

## Predicates

- **T1** `plt.xticks(…)` / `plt.yticks(…)` called by the program with any argument other than `minor` ⇒ the current axes' x / y `Axis` records `style` = the call line; a query (`plt.xticks()`, `plt.xticks(minor=True)`) records no `style`; a call matplotlib refuses (`labels` without `ticks`) records nothing; the return value = the original's; the ticks + labels form keeps its `xticks` / `yticks` record (a setter's line walk crosses the reader's own pyplot hook).
- **T2** `Axes.tick_params(axis=a, …)` called by the program, directly or through `plt.tick_params` ⇒ `style` on the x axis iff a ∈ {`x`, `both`}, on the y axis iff a ∈ {`y`, `both`}; a call matplotlib refuses (an unknown `a`, an unknown keyword) raises matplotlib's own error and records nothing.
- **T3** `Axis.set_tick_params(…)` called by the program ⇒ `style` on that axis; called from library code (`Axes.tick_params`, pandas' `boxplot`) ⇒ no record of its own.
- **T4** `style` never decides a site: `set_xticks(ticks, wrong labels)` at L, then `plt.xticks(rotation=45)` + `tick_params` ⇒ `tick_label_mismatch` marks L; `plt.xticks(ticks, wrong labels, rotation=45)` at L ⇒ marks L.
- **T5** the axes row lists every `style` line; the figure row lists none.
