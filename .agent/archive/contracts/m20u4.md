# M20.4 — reader + excerpts: a tick-style call (`plt.xticks(rotation=45)`) appeared in no row

Tier **kernel**: `src/verifier/figure/reader.py` hooks wrap matplotlib calls the program makes, so a hook defect changes the program run and with it the verdict; `webui/paste_in/excerpts.py` quotes model bytes into the user's chat with no downstream re-check.

## Finding

`docs/verification.md` § "How to read Show checks" promises that the Honest axes row lists "the calls that set limits, scales, inversion or ticks". `plt.xticks(rotation=45)` passes no ticks + no labels ⇒ pyplot calls `Axes.get_xticks` + `get_xticklabels` and updates each label: no recorded setter runs ⇒ banner arm `simple` line 16 appears in no row but `program`. Same gap: `ax.tick_params(…)`, `plt.tick_params(…)`, `ax.xaxis.set_tick_params(…)`.

## Rulings

- **Y1 (user, session 9 follow-up)** "You can add `plt.xticks(rotation=45)` if it would be beneficial to have it as part of the recorded set."
- **Y2 (MAIN, advisor; amended by R180)** a display-only slot `style` on the `Axis` object the call styles, never a failure site: the `xticks`/`yticks` slots decide `tick_label_mismatch`'s mark, and a later rotation call there would take it from the line that set the labels. Listed in the figure row (a tick style can change the tick font, and `plt.xticks(fontfamily='cmr10')` drops the minus glyph ⇒ `glyph_missing`) + the axes row. Per-label forms (`plt.setp(ax.get_xticklabels(), …)`, a label loop, `fig.autofmt_xdate()`) stay unrecorded + stated.
- **Y3 (MAIN, closing review R178 + re-review R183)** every recorded call — every slot, not `style` alone — records once matplotlib accepts it: a refused call the program catches sets nothing, so it takes no line and no mark. Reviewers 6 + 8 proposed the style hook alone; the older slots carry the same defect (`plt.ylim(0, nan)` caught after `plt.ylim(0, 5)` took the `point_clipped` mark). The call's clock is taken as it starts and a slot keeps the accepted call that started last: a setter a `ylim_changed` callback runs inside the program's `set_ylim` decides the limits, and a record taken after return gave the mark to the outer call (re-review, reviewers 6 + 7 + 8).

## Predicates

- **T1** `plt.xticks(…)` / `plt.yticks(…)` called by the program with any argument other than `minor` ⇒ the x / y `Axis` of the axes pyplot looks up first (`gca()` before the call: a callback can switch the current axes or close the figure during it) records `style` = the call line; a query (`plt.xticks()`, `plt.xticks(minor=True)`) records no `style`; a call matplotlib refuses (`labels` without `ticks`) records nothing; a call Python refuses at its arguments looks up no axes; no call opens a figure pyplot itself would not; the return value = the original's; the ticks + labels form keeps its `xticks` / `yticks` record (a setter's line walk crosses the reader's own pyplot hook).
- **T2** `Axes.tick_params(axis=a, …)` called by the program, directly or through `plt.tick_params` ⇒ `style` on the x axis iff a ∈ {`x`, `both`}, on the y axis iff a ∈ {`y`, `both`}; a call matplotlib refuses (an unknown `a`, an unknown keyword) raises matplotlib's own error and records nothing.
- **T3** `Axis.set_tick_params(…)` called by the program ⇒ `style` on that axis once matplotlib accepts it (Y3); called from library code (`Axes.tick_params`, pandas' `boxplot`) ⇒ no record of its own.
- **T4** `style` never decides a site: `set_xticks(ticks, wrong labels)` at L, then `plt.xticks(rotation=45)` + `tick_params` ⇒ `tick_label_mismatch` marks L; `plt.xticks(ticks, wrong labels, rotation=45)` at L ⇒ marks L.
- **T5** the figure + axes rows list every `style` line.
