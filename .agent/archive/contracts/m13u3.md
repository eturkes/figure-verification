# M13.3 — projection (formula arm) + by-construction integrity pins

Tier **kernel**. Dispatch: MAIN authors the core spec representation + `project.py` (judgment-bearing
— projection IS what the verifier claims a program plots); `test` teammate builds the diff-blind red
suite from the predicates below; `orc` teammate writes an independent projection against this
contract alone as a differential oracle.

## What this unit decides

Admitted AST → core plot spec. Admission answers "may these bytes run"; projection answers "what do
they draw". It is the surface where THE PROJECTION GAP is closed: *what the projection says the
script plots* ≡ *what the script plots when executed*. Closed BY CONSTRUCTION here via P11 (total
statement coverage), so no admitted statement can carry an effect the spec omits.

Scope is the formula arm alone — the one the current allowlist already admits. The spec
representation is a tagged union carrying BOTH arms from the start; the dataset variant is declared
and refused-as-unimplemented, so M13.4 widens the allowlist without reshaping the core.

Evaluation policy is NOT this unit. Projection represents faithfully — an `np.pi` endpoint and an
`np.sin` call project to structure, and M13.5 rules how each is compared.

`ADMITTED_CALL_TARGETS`/`ADMITTED_KEYWORDS`, AND a concrete program using it is refused. Widening the
allowlist must BREAK these, never silently delete the rule.

### Rulings this unit produced

- **P4 grid identity is STRUCTURAL** (supersedes the original lexical wording): any reference to a
  grid equal by value to the mark's x grid IS the grid variable, bound name or repeated call alike.
- **P5 `arange` admits INTEGER bounds only** (`|value| <= 2**52`): numpy sizes and accumulates
  `arange` in float64, so a non-integer step makes the executed array disagree by a whole step.
  Measured 5/15 non-integer cases disagree; 115/115 integer cases faithful.
- **Refusal precedence: LOCAL before GLOBAL.** A fault local to one statement refuses before a fault
  global to the program, so `plt.plot(...)` then `plt.bar(...)` refuses `mark_not_valid_for_arm`,
  not `multiple_marks`. Structural in the formula arm rather than ordering-dependent: `plt.bar` is
  in `_WRONG_ARM_MARKS`, never in `_MARKS`, so it cannot become a second mark. The contract stated
  P2 and P10 independently and gave no precedence; this settles it.
- **Differential form noise is translated, never absorbed.** ONE named translation maps both sides
  onto a canonical tuple through an EXPLICIT node-name and field-name map in fixed field order, and
  RAISES on a name it does not cover. 23 of 25 first-run disagreements were form (class names, field
  names, field order, the deleted `kind`/`step`); the 2 semantic ones were escalated to MAIN and
  both resolved in production's favour — the oracle's stale `10_000` sample cap against the
  contract's `100_000`, and the precedence ruling above.
