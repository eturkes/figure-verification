# Q78 — the model's note: a request that the chart rules override is stated in the reply

Tier **kernel** for the outlet (it shows model-authored text in a verified reply, and nothing downstream re-checks how that text renders or that it never moves a verdict); **data** for the model-facing sentences (the verifier judges every figure whatever the model wrote, ruling 8; live runs measure the effect).

## Request + rulings (user, this session)

Request: "the system needs to report when any kind of filter overrides what the initial request was … mentioned to the user as part of the response." Rulings (AskUserQuestion rounds):
1. Mechanism = the model states it: model guidance keeps the chart rules; when the request, taken verbatim, asks for something the rules do not allow, the model must say so in its response (user's own option text). Second draft, rules-yield and setting comparison not chosen.
2. Placement = a line under the verdict: a short speaker label + the note (`Model note:` / `モデルの注記:`; the user dropped the drafted disclaimer label, then chose the speaker label over none). No length limit (user: the model's own output limit bounds it, as with the request-length + attachment rulings).
3. Pass AND fail replies show it.
4. A silent model is accepted: documented + measured live; no fixed-rule backstop.
5. Unprompted corrections (a sound request the model "would have" drawn wrong) are not reported: the model cannot know what it would have drawn, and a counterfactual draft was not chosen.
6. Scope = admin Valve: on in production (+ `--codex`, which runs the production pair), off in the demo.

## Predicates

- **N1 tool** — `draw_figure(program, note="")`: `note` is optional in the model-facing schema (Open WebUI builds it from the signature default + `:param note:`); the receipt records a `str` note verbatim, any other value as `""`.
- **N2 receipt** — tag `figure-verification-receipt/3`, six fields (+ `note: str`); a `/2` value or any field of another type decodes to no receipt (fail closed).
- **N3 inlet** — Valve on ⇒ the rendered message = today's template bytes + `NOTE_REQUEST`; Valve off ⇒ byte-identical to today. Template digests (T2, T3) unchanged.
- **N4 outlet shows** — Valve on + a receipt whose note holds a non-space character ⇒ the reply `content` (and its one `output` item, the same text) = the verdict text as today + `\n\n` + label + ` ` + `inert.code(note.strip())`, no length limit; label EN or JA by the existing kana rule. On PASS and on every FAIL that read a receipt.
- **N5 independence** — the note never reaches `Sources`, `judge`, `wrapper_code`, the status line, the log record or the "Show checks" embed: for any receipt, the verdict, the files event, the status + embed events are identical with and without a note (differential test over every outlet arm).
- **N6 Valve off** — the reply bytes equal today's for every arm, note or none.
- **N7 inert** — the shown note is exactly one code span: no markdown, HTML, link, image or math construct outside it, line breaks shown as symbols (`inert.code` law, M21.1 F1); hostile notes (`![x](http://…)`, `<img src=x>`, `\(x\)`, `$x$`, backtick runs, U+202E, a 10,000-character note) pinned.
- **N8 defaults** — `paste-in/` filter Valve default on; `webui/demo-paste-in/` default off; the Valve is admin-only (a function valve, `routers/functions.py`).
- **N9 docs** — admin guide (EN + JA): the Valve, what the note is, that the verifier never checks it, that the model can leave a conflict unstated; reference (EN + JA): the note in "what the verifier does not check"; register + parity tests green.
- **N10 live (observation, never the acceptance)** — `--codex`, banner prompts 1-6 × 3 through the browser: per run the verdict, the note's presence + its text; misleading prompts (2, 4, 6) expected to carry a note, honest (1, 3, 5) none; one screenshot of a pass with a note, EN + JA.

- Valve: `model_note` · title `Model Note` · "Ask the model to say when the request conflicts with the chart rules, and show that statement under the verdict. The verifier does not check the statement."
