## Layering

`capture/harness.py` imports `capture/record.py`, never the reverse. 6a owns the record format and
R1–R11; 6b owns the wire, the fault mapping, the derived statistics and their predicates S1–S4.
6b spells NO outbound JSON: `build_request_body` is the sole speller (6a's R2 + R11 grade every
committed record against it), and 6b emits no record except through `build_record` + `write_run`.

`capture/__main__.py` is a shim over `harness.main`, so `python -m capture` is the package entry
beside the two shipped validator entries (`python -m capture.corpus`, `python -m capture.record`).

## Rulings this unit is implemented under

- **R-wire.** One route, one shape: `POST {base_url}/v1/chat/completions` with
  `build_request_body`'s exact bytes and `Content-Type: application/json`. Provenance reads
  `GET {base_url}/health`. No other request is issued, ever. Ruling 5 binds the body: an unguided
  capture names no guidance key, and 6a's builder is what makes that unfalsifiable.
- **R-status.** `record.http_status == 200` is RESERVED for a complete, decoded reply. Every other
  outcome records `http_status = NO_STATUS` (`0`) with `error` naming what happened, INCLUDING any
  observed HTTP status. Three outcomes take that arm besides a real non-200: a body that does not
  decode, an envelope with no usable choice, and a `finish_reason` outside `FINISH_REASONS`. This
  is forced by 6a's R6 (200 ⇒ all five reply fields present) and keeps every committed run
  gradeable — a run that fails R6 after ninety minutes of dGPU time is not recoverable.
  A genuine non-200 records the server's own status, because that status IS the outcome.
- **R-flush.** The run directory is a valid, complete, gradeable capture at EVERY instant: after
  each row the driver rewrites `run.json`, `records.ndjson` and `stats.json` through 6a's
  `write_run` plus 6b's stats writer. A 50-row run against a 0.5B model on the MX150 costs over an
  hour, so an interrupt must cost one row, never the run.
- **R-resume.** An existing non-empty run directory REFUSES by default. `--resume` keeps the
  already-captured `prompt_id`s and drives only the rest, but ONLY when the freshly built manifest
  equals the committed one field for field except `record_count`; a disagreeing commit, model,
  dtype, cap or temperature refuses loudly rather than mixing two tree states into one evidence
  set. A committed `prompt_id` OUTSIDE the freshly selected rows refuses too: prompt ids are not
  manifest fields, so the field-for-field check cannot see them, and neither resolution is sound —
  keeping the row widens the run past its own scope, dropping it breaks the preservation promise.
  `--overwrite` discards and restarts.
- **R-heldout.** Ruling 7 discipline gets its one mechanical guard at the one place it can be
  breached: `--kind heldout` refuses unless `--heldout-acknowledged` is passed. The flag exists so
  the M13 acceptance read stays possible, not to make held-out capture convenient.
- **R-defence.** De-fencing has ONE authority. `fenced` is DEFINED as "the de-fencer extracted an
  inner block", so the fence rate and the parse rate can never disagree about what a fence is.
  The de-fencer must handle an UNTERMINATED fence, because truncation is one of the three
  statistics and the two interact: a reply cut at the token cap mid-block has an opening fence and
  no closing one, and a closing-fence-required regex (bench's `_FENCE_RE`) silently scores every
  such reply unparseable.
- **R-parse.** `parsed` is true only when the de-fenced text parses AND the module carries at least
  one statement. `ast.parse("")` succeeds on an empty module, so a blank or comment-only body would
  otherwise inflate the headline number. The statistic is TOTAL over adversarial bytes: a byte cap
  precedes `ast.parse`, and `SyntaxError`, `ValueError` (null bytes), `MemoryError` and
  `RecursionError` all score not-parsed instead of propagating. `ast.parse` on model bytes is a
  TCB addition for `capture/` only — it executes nothing, and `src/verifier/expr.py` keeps its
  no-`ast` property untouched.
- **R-denominator.** Rates are over REPLIES (`http_status == 200`), not over records: a transport
  fault is not a model behaviour. A category with zero replies reports `None`, never `0.0` —
  bench's `_rate` returns `0.0` at `n=0` and that reads as a measured zero.
- **R-sentinel.** Sentinels are reported as PER-ROW facts and never as a rate. There is one
  sentinel per category, and a rate over `n=1` is a category error. They are excluded from every
  category denominator (roadmap: the sentinels are public, outside both corpora and both
  denominators, scored separately).
- **R-no-clock.** Inherited from 6a and extended to `stats.json`: no wall-clock field anywhere, so
  a committed run re-encodes byte-identically. Elapsed time may be written to stdout as progress;
  it may not enter an artifact.
- **R-loose-decode.** Response bodies decode into 6b's OWN loose structs, never
  `model_backend.models`: the service models carry `Literal` fields that reject real payloads, and
  an out-of-tree observer that imports the server's types stops being an observer. `/health`
  decodes the same way, and `ServiceProvenance` is constructed from exactly three of its fields
  (6a's docstring mandates this).

## Operator facts the contract records

- `MODEL_BACKEND_MAX_TOKENS` defaults to **512** and the backend CLAMPS a larger request to it
  silently (`app.py`: `max(1, min(requested, settings.max_tokens))`). The manifest records what was
  SENT; `usage.completion_tokens` at `finish_reason == "length"` reveals the effective cap. Raising
  the cap past 512 (ruling 5's truncation lever) is a SERVER-side env change, not a client flag.
- The engine is greedy at `temperature == 0` (`do_sample=False`, `num_beams` pinned), so the
  default `--temperature 0.0` is what makes a run reproducible for one `(device, config)`.

## Public API (the surface the red suite is written against)

```python
STATS_VERSION: Final = "python-capture-stats-1"
STATS_NAME: Final = "stats.json"
NO_STATUS: Final = 0                       # R-status: no usable HTTP outcome
CHAT_PATH: Final = "/v1/chat/completions"
HEALTH_PATH: Final = "/health"
DEFAULT_BASE_URL: Final = "http://127.0.0.1:8001"
DEFAULT_MAX_TOKENS: Final = 512
DEFAULT_TIMEOUT: Final = 300.0
MAX_PARSE_BYTES: Final = 1 << 20

class StatBlock:    records, replies, fenced, parsed, truncated,
                    fence_rate, parse_rate, truncation_rate      # rates float | None
class SentinelStat: prompt_id, category, http_status, fenced, parsed, truncated  # bool | None
class CaptureStats: version, mode, run, kind, record_count, by_category, sentinels
class StatsRun:     run, stats, stats_bytes

def defence(content: str) -> tuple[bool, str]       # (fenced, inner)
def parses(content: str) -> bool                    # R-parse
def derive_stats(run: Run) -> CaptureStats
def encode_stats(stats: CaptureStats) -> bytes
def decode_stats(raw: bytes) -> CaptureStats
def write_stats(directory: Path, stats: CaptureStats) -> None
def load_stats_run(directory: Path) -> StatsRun
STATS_PREDICATES: dict[str, Callable[[StatsRun], list[str]]]
def validate_stats(directory: Path) -> list[str]    # S1-S4 only; the CLI also runs R1-R11

class CaptureConfig: base_url, model, max_tokens, temperature   # the four the manifest records
class Outcome:      request_body, http_status, content, finish_reason, usage, error
                    # ONE exchange = request AND response, which is what lets capture_one keep the
                    # signature below: the caller never re-spells the bytes it must hash
def capture_one(client, *, base_url, prompt, model, max_tokens, temperature) -> Outcome
def fetch_service_provenance(client, base_url) -> ServiceProvenance | None
def select_rows(corpus, kind, *, sentinels: bool) -> tuple[tuple[Kind, Prompt], ...]
def run_capture(client, directory, *, rows, kind, config, provenance, keep=(), progress=True
                ) -> tuple[CaptureRecord, ...]
def main(argv: Sequence[str] | None = None) -> int
```

Every struct is `msgspec.Struct, frozen=True, kw_only=True, forbid_unknown_fields=True`. Every
predicate returns human-readable failure lines and never raises on well-typed input.

### Divergences MAIN ruled (do not re-litigate at MILESTONE-REVIEW)

- **S4 narrowed to the PARTITION property** (predicate row + `check_stats_scope` docstring). One
  mutation must yield one diagnosis: `record_count` is S2's field, key ORDER is S3's bytes, and
  membership + arithmetic-against-the-run is what is left that is genuinely S4's.
- **`Outcome.request_body` is contract text, not a suite defect.** The sketch was incomplete.
- **`--resume` scope refusal is a NEW shipped behaviour**, added to R-resume and H14 because the
  teammate's diff-blind reading exposed a real hole: prompt ids are not manifest fields, so the
  field-for-field conflict check could not see a foreign committed row.
- The teammate's four reported DISPUTES all independently AGREED with the shipped implementation
  (transport-error naming, end-of-string fence termination, three `None`s for a non-reply sentinel,
  `null` vs measured `0.0` for an undefined rate) — corroboration, no action.
