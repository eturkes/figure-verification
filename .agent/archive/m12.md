### MAIN rulings taken during implementation

- **P21 is NOT a committed test (reverses §8 M11's shape, keeps its intent).** An
  `assert git diff --name-only <base> == <allowlist>` test is red for every later commit, so it
  would encode a unit boundary as a permanent gate. Run as a close-time MAIN check instead; §4's
  invariants keep their enforcing predicates (P19 root lock bytes, P2/P3 env names, P1 bounds,
  P4 selector, P5 message bytes, P18 override set).
- **The planned "adapted settings pins" edit to `tests/test_model_backend.py` is DELETED scope.**
  P1 already pins `device`/`model_dir`/`model_name` as literals; adding a twin in the old file
  duplicates without adding a red. Re-derived, not assumed: the full suite passes untouched, so
  every map S3 NO-EDIT row held.
- **Fault classes are FOUR + one addition.** `_walk_files` records an unlistable DIRECTORY under
  `unreadable` rather than raising, so one run still diagnoses the whole tree (E4's "one diagnostic
  surface, never a crash" applied to directories). `--write` REFUSES such a tree outright — a
  manifest built over an unreadable subtree would pin a partial revision. Both pinned by P23.
- **`--write` sources identity from module constants**, `SNAPSHOT_REPO_ID` + `SNAPSHOT_REVISION`,
  not from CLI flags or the manifest it overwrites: re-pinning a revision is a code change, so the
  regeneration command stays argument-free and replayable from a clean base.
- **Lock resolution is fresh, not the probe's bytes.** Three transitive patch versions moved between
  the probe and the shipped lock; the 5 direct pins, the 59-package count, the 14 `nvidia-*` wheels
  and the cu126 registry are identical. The probe validated resolvability, never byte identity.
