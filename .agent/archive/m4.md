## Memory notes — M4 (Open WebUI integration) — contract facts for Open WebUI 0.10.2; reverify on upgrade
- Runtime/standup: `.venv-webui` uses Python 3.12 (3.13 rejected by package metadata); the wheel bundles the frontend. Canonical serve = `open-webui serve --host 127.0.0.1 --port 8080`; readiness = `GET /ready` (not early-200 `/health`). Exact clean-stack/bootstrap/chat/browser recipe = `webui/README.md`.
- Hermetic launch: `webui/settings.py` is source of truth. `launch_env()` reads no ambient env; its five per-instance values are absolute `DATA_DIR`, secret, BOTH singular/plural OpenAI base URLs (plural overrides singular upstream), and `TOOL_SERVER_CONNECTIONS`. `child_env()` retains only PATH/HOME/locale/TERM/tmp/timezone then overlays launch config; launcher uses `os.execve`. Load-bearing pins: persistent config off (env wins each boot), offline/no downloads/version ping, OpenAI backend on + Ollama off, all five background generation toggles off, auth/password/login on + later signup off + auto-admin/trusted-header inputs empty, `ENABLE_API_OUTLET_FILTERS=true`, legacy FC. Endpoint boundary is exact: verifier = canonical http(s) origin with no path; model backend = canonical http(s) endpoint ending exactly `/v1`; clean ASCII authority (bracketed IPv6 allowed), no userinfo/query/fragment/backslash/ambiguous bytes; bind/client host = bare ASCII hostname, no port/path/scheme. This avoids OWUI's silent server drop or api.openai.com fallback.
- Persistent-off split: tool/model/legacy-FC config rides env; admin + repo-owned function rows persist in the DB. `TOOL_SERVER_CONNECTIONS` is one enabled global backend-called OpenAPI server at verifier `schema/openapi.json`, allowlisting only `proposeSpec`, with `info.id=verifier`; OWUI exposes `server:verifier`. `GET /api/v1/tools/` returns a bare array and refetches specs; presence therefore proves the OpenAPI fetch. User-level tools require a browser websocket round trip and remain out of scope/CORS-free.
- OWUI OpenAPI conversion quirks: operations lacking `operationId` disappear; description beats summary; only `application/json` request bodies are read; top-level composition contributes no visible parameters, while property-level nullable unions collapse to the non-null type; extra model args are dropped. Keep request schemas with top-level properties.
- Headless tool execution: native FC returns tool calls but does not execute without the UI event emitter. Legacy prompt-template FC executes inline for one-shot non-streaming `POST /api/chat/completions`; caller-supplied `body.tools` disables server-tool resolution. Tool-selection JSON extraction is lenient, and task model falls back to the chat model when the pinned task-model values are empty.
- Rich embed contract: verified `POST /propose-spec` success returns `[ProposeResult, summary_str]` as JSON plus `Content-Disposition: inline` and absolute chart `Location`; every failure remains the original bare result/problem with no Location. OWUI discards element 0, passes the lean string to the model, and stores Location in message embeds. `GET /chart/{plot_id}` serves HTML under CSP `sandbox allow-scripts`; iframe omits `allow-same-origin`. Cross-origin sandbox height must self-report `parent.postMessage({type:"iframe:height",height:<number>},"*")` using content rect (not scrollHeight). The served page (`render.signed_chart_html`) is a compact chat-native view: transparent `html,body` bg + `@media(prefers-color-scheme)` CSS vars → blends into the OWUI chat in light/dark (the sandboxed iframe can't read the parent theme but shares the OS `prefers-color-scheme`, which OWUI's default `system` theme follows); NO `color-scheme` on `:root` (it would repaint the canvas + defeat transparency). Chart stays on a light card (verified SVG axes/text are dark). Provenance = ONE `badge_html` line: "Verified plot" (inline-SVG check) + `len(checks)` "N check(s) passed" + a "View certificate" link to the signed envelope; hashes/TCB/per-check/filter+sort dump live ONLY in the `/certificate` envelope now (raw DSSE JSON, no pretty HTML page). `signed_chart_html(vega_lite_json, cert, *, certificate_url)` dropped the former `keyid`/`plot_id` display args; removed `render._literal` + stdlib `json` import.
- Provisioning contract: first signup creates/promotes admin; any non-200 signup falls back to signin (same-process closure or post-restart email-taken). Canonical order = readiness → auth → exact-source filter create/update → conditional active/global toggles → mandatory final GET → model/tool readbacks. Function create omits `content`; update/toggle/GET include it. All transport/status/JSON/invalid-UTF-8 failures normalize to `WebUIProvisionError`; no malformed readback may degrade to `ok=False`.
- Filter contract: `Verified Plot Guard` is stdlib-only, global, active, and intentionally has no per-chat `toggle` attribute. It rewrites only final-assistant direct-chart-looking content, warning only canonical signal names + length. It is heuristic/bypassable/false-positive-prone - a usability guardrail, never verification. API outlet return does not rewrite `/api/chat/completions`; test it through `POST /api/chat/completed` or persisted chat.
- Persisted chat: `WebUIClient.run_persisted_chat` (after `authenticate()`) + `python -m webui chat --prompt …` codify OWUI 0.10.2. Create first with `{"chat":{"models":[model_id],"messages":[],"history":{"messages":{},"currentId":null}}}`, then completion with `session_id`/`chat_id`, assistant `id`, and complete `user_message`; deadline-poll using `ready_timeout`. The assistant is exactly `chat.history.messages[assistant_id]`: `done=true`, legacy `content=""`, final text at `output[0].content[0].text`, optional chart at `embeds[0]`.
- Evidence boundary: the deterministic stub proves integration mechanics only (selector → verifier → context → persisted embed → chart). The pre-M8 unconstrained NPU selected 5/10 fixed prompts and verified 0/10 (four fenced decode failures, one missing argument) — an observation, never a reliability bound, and superseded as the default by the guided run (see M8).
- Demo live stack = TWO passes: :8001 serves EITHER `webui stub` (deterministic valid spec → verified chart, `--with-webui`) XOR live `model_backend` NPU (garbage → blocked verdicts, `--with-model`) — one port, mutually exclusive. Live NPU greedy decode of a token-emitting prompt exceeds the 20s hardware-free hang-guard → the model leg carries its own generous timeout (`_MODEL_REQUEST_TIMEOUT_S=180`) while deterministic-case GETs keep 20s. chromiumfish visual capture is BLOCKED in this agent container (SwANGLE/Vulkan EGL init fails, GPU process exits, plus GCM background-network retries → rc=124 hang for BOTH the virtual-time DOM dump and `--headless=new --print-to-pdf`) → keep browser evidence TEXTUAL here (demo webui block = chart_url + verified certificate; persisted-chat DOM = `embeds[0]` chart URL, assistant `done=true`, legacy `content=""`; chart CSP `sandbox allow-scripts`; the server-rendered badge line) and leave the pixel render to the operator's host.
- Interactive instance launcher: `webui/launch.sh` = one-command standup — verifier `/health` (:8000) → model `/v1/models` (:8001) → OWUI `/ready` (:8080) → `webui bootstrap`, then blocks on `wait -n`; model tier = real NPU `model_backend` (default; a subshell sources `INTEL_ACCEL_ENV` + prepends `OPENVINO_GENAI_PYTHON`, then `exec .venv-model/bin/python -m model_backend` DIRECTLY — `uv run`/`-E`/`-I` strip PYTHONPATH) XOR `--stub` (hardware-free); `--fresh` wipes `.webui-data`; every path/device/cred/port/timeout is an env override. Each service starts in its own `setsid` group; `cleanup` group-kills (10s grace → SIGKILL) + `fuser -k` port backstop; `trap cleanup EXIT` + INT→`exit 130` + TERM→`exit 143`. TEARDOWN GOTCHA: an `&`-backgrounded launcher inherits SIGINT=`SIG_IGN` (a non-interactive bash cannot trap a signal ignored on entry) → its INT trap is a silent no-op ONLY when backgrounded; interactive Ctrl-C (real PTY) works and SIGTERM/EXIT always tear down → programmatic teardown uses SIGTERM or the `.launch-logs/launch.pid` pidfile.
- Live walkthrough shape (OpenVINO 2026.2.1 enumerates `['CPU','GPU','NPU']` here — only chromiumfish/GL is blocked — so the real-model standup runs in this container while the browser render stays the operator's step): the unconstrained weak model is the HONEST blocked PoC (the guided default now verifies a minority; see M8) — `/propose-spec` → `verified=False` with `spec.decode`/`schema_validation`/`fail`, distinct `attempt_id`s (CSPRNG nonce even on a repeated prompt), fenced-then-rambling or truncated replies, each committed + diagnosable via `python -m verifier.service audit` (DSSE `valid`, outcome `rejected`, plot_id null, 5 blobs redacted); a persisted chat through it usually IGNORES the tool and returns raw matplotlib → no verified chart, which the `Verified Plot Guard` outlet rewrites to `BLOCKED_NOTICE` (prose passes). `--stub` = the verified happy path: persisted chat → `embeds[0]` chart under CSP `sandbox allow-scripts`, cert DSSE-verified under `/key/{keyid}` (vcert-0.2, 5 hashes, 10 checks incl. 2 `z3_smt`). Browser/pixels stay TCB; the guard is bypassable; observations, never bounds.
- Browser default-tool attachment (OWUI 0.10.2): a global server is merely *available*, never auto-attached by the chat backend, which resolves only request `tool_ids` (`utils/middleware.py`); Chat.svelte pre-selects a model's `info.meta.toolIds`, and `utils/automations.py:_resolve_model_tool_ids` explicitly says the backend never resolves them. Therefore `bootstrap.run_bootstrap` converges the workspace model's `meta.toolIds` to `server:verifier` through `WebUIClient.ensure_model_tool` (create-or-merge preserving `params`/other `meta`, fail-closed final GET, idempotent no-write when present), so browser chats auto-offer the verifier without a manual toggle. Headless `run_persisted_chat` already sends `tool_ids` explicitly and is unchanged; omitting `access_grants` from the model payload is harmless for this single-admin instance.
- Launcher port-coupling: a `VERIFIER_PORT`/`MODEL_BACKEND_PORT` override wires end-to-end ONLY if the launcher DERIVES every child-facing URL from the port vars and EXPORTS it — left to a child's own settings default, the child silently pins to the default port. `webui/launch.sh` derives+exports four (`HEALTH_HOST`+port): `WEBUI_PROVISION_VERIFIER_URL`, `WEBUI_PROVISION_MODEL_BACKEND_URL`, and the easily-missed `VERIFIER_MODEL_BASE_URL` — the verifier is ITSELF a model client (`/propose-spec`→backend; `verifier.service.settings` reads it, default `http://127.0.0.1:8001/v1`), so a remapped `MODEL_BACKEND_PORT` without it 503s the verifier against the moved backend — plus `VERIFIER_PORT` (OWUI provisioning + the verifier's chart `Location`). All byte-identical to the child defaults at the default ports; an explicit URL override still wins. And the refuse-if-bound port preflight (`/dev/tcp` probe) must run BEFORE `trap cleanup` installs, else a refusal `fuser -k`s the very pre-existing listener it was meant to protect.
- Launcher crash-faithfulness + startup liveness: after the READY banner, `wait -n 2>/dev/null || true` MASKS a required-service crash as exit 0 (automation reads a dead stack as a clean launch) → capture the status (`wait -n 2>/dev/null || service_rc=$?`), name the dead child by walking `SERVICE_PIDS`/`SERVICE_NAMES` for the one failing `kill -0`, then exit non-zero. Emit that via a SUBSHELL `(exit "$rc")`, never a bare top-level `exit`: an explicit top-level `exit` makes ShellCheck 0.10 flag SC2317 (unreachable) on the EXIT-trap-only helpers (`cleanup`/`free_port`/`any_service_alive`) — a false positive; the subshell keeps the script falling off the end so the trap graph stays reachable, while `set -e` still propagates the status to the parent whose EXIT trap runs (structural fix beats an SC2317 suppression). Companion rules: keep every advertised knob a REAL override (`MODEL_BACKEND_PYTHON` carries the interpreter through both the precondition and the accel `exec`); gate the `fuser -k` backstop on the port STILL bound after the precise setsid-group kills (else it reaps a stranger); check the child PID before trusting a readiness `curl` 2xx (a foreign listener otherwise reads as the child). Detection caveat (root mechanism UNPROVEN): readiness-phase blocks are bounded (each `wait_http` is a wall-clock loop → `*_READY_S` → `die`), and killing a tracked service LEADER post-READY makes the final `wait -n` return and name it (rc137). UNPROVEN: whether a real inner-service crash always propagates to the tracked `setsid` leader that `wait -n` / `kill -0` observe (relies on `exec` + `uv run` exit-forwarding, untested) — if a leader outlives a crashed descendant, the post-READY final `wait -n` (no wall-clock timeout) could hang indefinitely; worst case is a HANG, not an exit-0 false-clean. Hardening (deferred; see `.agent/polish.md`): first confirm the killed PID is the tracked leader and dead afterward, then validate all tracked PIDs immediately before the final wait and use `wait -n -p VAR pid…` with explicit tracked-leader operands (not any job).
