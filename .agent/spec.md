# figure-verification spec

## Intent

A chat assistant where a model writes the Python that draws a chart, and a separate trusted verifier decides whether that chart may appear: first as a skill for llens, the hospital's Kimi K2.6 system on nucllei, and also in Open WebUI. The model proposes only code, plus an optional note: when the request, taken as written, asks for something the chart rules do not allow, the model says what it asked for and what the chart shows instead. The program runs unchanged in the host's code sandbox (the nucllei sandbox, or Open WebUI's native Pyodide sandbox), so the Python interpreter, not the verifier, catches invalid Python. The verifier inspects the finished matplotlib figure. Every artist must belong to a closed set that the verifier judges. A figure that matplotlib did not draw, or that holds an artist outside the set, is blocked. Every judged artist must obey a comprehensive, closed set of integrity rules: bars from zero, no truncated or inverted axis, honest scales and ticks, no clipped or dropped data, and the per-mark rules of bar, line, scatter, histogram, stacked and grouped bar, pie, area and multi-panel figures. Where the user supplied data, the verifier also checks that the drawn values are that data. The data is an attached CSV's raw values or one group-and-reduce of them, or the numbers typed in the request, with ranges such as `1 through 10` or `1から10まで` expanded, or one admitted computation of that data (a running total, a share or percent of the total, the change from the previous point or the square of one series; the ratio, difference, product or sum of two columns, per row or per group). A value that the verifier cannot find blocks the figure. A figure with no data source is checked for integrity alone, and the reply says so. For CSV figures, column anchoring stays: the request must name the drawn columns. Text on the chart is listed, never judged. Verification uses no inference: every decision is a deterministic rule. Pass ⇒ inline PNG + `Figure verification passed` + the list of checks ("Show checks"; on nucllei, inside the collapsed tool block). Fail ⇒ blocked + `Figure verification failed, no image produced` + the failing rule. When the latest message holds a kana letter, the verifier writes its sentences in Japanese, the verdicts included: `図の検証に合格しました。` and `図の検証に合格しませんでした。画像は表示されません。` Either reply shows the model's note when it gives one, labelled as the model's statement, which the verifier does not check. Acceptance: a committed rule corpus, with at least one misleading program per rule that blocks and one honest twin that passes, 100% both ways. Live runs add to it: honest prompts pass, and prompts that ask for a misleading chart block. The verifier alone decides. Model guidance (on nucllei, the skill text and the tool description; on Open WebUI, the filter inlet's template and the tool description) may state the rules but never moves the boundary. Production artifact: the nucllei skill, two generated files (the skill text and the tool it loads) that an admin copies into a llens checkout and syncs, plus an HTML copy of the checks guide for the server. Open WebUI keeps its two generated files (a tool and a filter) that an admin pastes into an existing instance. The verifier is embedded and needs nothing beyond stdlib + what the host image and its sandbox already carry; its one network call is the host's own sandbox request. The target instance has no outside network, so nothing may require a download or a rebuild. The repo's own stack is the demo harness, not the deliverable. Demo-grade: correctness testing yes; crypto sealing, escrow and tamper-evidence ceremonies no. The claim stays modest: verified = the drawn figure obeys every integrity rule and, where data was supplied, its values are that data. The program is assumed non-adversarial: it runs before any check, in the same interpreter as the figure reader. The renderer, browser, code sandbox, matplotlib and pixels are trusted, not verified. On nucllei, the verifier decides the figures that `draw_figure` shows; the model's own reply and charts drawn by other tools are outside it. Fidelity to intent (the right quantity for the question) is never claimed beyond column anchoring.
