# figure-verification spec

## Intent

A local Open WebUI instance where a local model writes the Python that draws a chart, and a separate trusted verifier decides whether that chart may appear. The model proposes only code. The program runs unchanged in Open WebUI's native Pyodide sandbox, so the Python interpreter, not the verifier, catches invalid Python. The verifier inspects the finished matplotlib figure. Every artist must belong to a closed set that the verifier judges. A figure that matplotlib did not draw, or that holds an artist outside the set, is blocked. Every judged artist must obey a comprehensive, closed set of integrity rules: bars from zero, no truncated or inverted axis, honest scales and ticks, no clipped or dropped data, and the per-mark rules of bar, line, scatter, histogram, stacked and grouped bar, pie, area and multi-panel figures. Where the user supplied data, the verifier also checks that the drawn values are that data. The data is an attached CSV's raw values or one group-and-reduce of them, or the numbers typed in the request, with ranges such as `1 through 10` or `1から10まで` expanded. A value that the verifier cannot find blocks the figure. A figure with no data source is checked for integrity alone, and the reply says so. For CSV figures, column anchoring stays: the request must name the drawn columns. Text on the chart is listed, never judged. Verification uses no inference: every decision is a deterministic rule. Pass ⇒ inline PNG + `Figure verification passed` + the "Show checks" list. Fail ⇒ blocked + `Figure verification failed, no image produced` + the failing rule. Acceptance: a committed rule corpus, with at least one misleading program per rule that blocks and one honest twin that passes, 100% both ways. Live runs add to it: honest prompts pass, and prompts that ask for a misleading chart block. The verifier alone decides. Model guidance (the filter inlet's template and the tool description) may state the rules but never moves the boundary. Production artifact: two generated Python files (a tool and a filter) that an admin pastes into an existing Open WebUI instance. The verifier is embedded, makes zero network calls, and needs nothing beyond stdlib + what the Open WebUI image and its Pyodide bundle already carry. The target instance is a network-less Docker image, so nothing may require a rebuild. The repo's own stack is the demo harness, not the deliverable. Demo-grade: correctness testing yes; crypto sealing, escrow and tamper-evidence ceremonies no. The claim stays modest: verified = the drawn figure obeys every integrity rule and, where data was supplied, its values are that data. The program is assumed non-adversarial: it runs before any check, in the same interpreter as the figure reader. The renderer, browser, Pyodide sandbox, matplotlib and pixels are trusted, not verified. Fidelity to intent (the right quantity for the question) is never claimed beyond column anchoring.
