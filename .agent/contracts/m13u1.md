# M13.1 — `verifier.pysrc` pre-scan: bounding untrusted bytes ahead of `ast.parse` (contract)

Tier: **kernel** — this is the first thing untrusted model bytes touch, and nothing downstream
re-checks it.

Law: `.claude/rules/pysrc.md`. Stdlib-only, no `verifier.*` imports: M14 inlines this package.

## Why a pre-scan exists at all

`ast.parse` runs the CPython parser over adversarial input. It executes nothing, but it recurses,
so deeply nested source is a resource attack the parser answers with a C-stack failure rather than
an exception this project can convert into a verdict. A post-parse depth check is therefore too
late. The pre-scan bounds the input BEFORE the parser sees it.

`tokenize` joins the TCB alongside `ast.parse`, and only for this package. It is chosen over a
hand-rolled character scan because it handles Python string literals correctly: a naive scan would
count the brackets inside `plt.title("f(x) = sin(x)")` and refuse ordinary matplotlib code. It
recurses nowhere and runs behind the byte cap, so its own worst case is bounded.

## Check set (fixed before implementation)

| id | predicate | acceptance check |
|---|---|---|
| P1 | the byte cap precedes every other step | oversized input refuses without decoding or tokenizing (spy on both) |
| P2 | non-UTF-8 bytes refuse | `b"\xff\xfe"` ⇒ `source_not_utf8`, no `UnicodeDecodeError` escapes |
| P3 | a NUL byte refuses | `b"x = 1\x00"` ⇒ `source_has_nul` |
| P4 | over-long lines refuse | one line past the cap ⇒ `line_too_long`; the boundary line passes |
| P5 | untokenizable source refuses | unterminated string ⇒ `source_not_tokenizable`, never a raw `TokenizeError` |
| P6 | the token count is capped | cap+1 tokens ⇒ `too_many_tokens`; cap passes |
| P7 | bracket nesting is capped, from OP tokens ONLY | `"(" * 200` ⇒ `nesting_too_deep`, NOT `RecursionError`; a title string full of parens passes |
| P8 | unbalanced closers refuse | `")"` ⇒ `unbalanced_brackets` |
| P9 | indentation depth is capped | cap+1 nested blocks ⇒ `indent_too_deep` |
| P10 | every refusal is a stable code carrying NO source bytes | each refusal's `code` is a literal from the closed set; `str(exc)` contains no input substring |
| P11 | caller-supplied limits are threaded, not defaults | a stricter-than-default `PysrcLimits` changes the verdict at the public entry |
| P12 | limits are validated fail-closed | a non-positive cap refuses as a CALLER error, distinct from a source refusal |
| P13 | the module reaches `ast.parse` never | `import ast` absent from the module; a committed search test |

P7 is the predicate the unit exists for: the acceptance witness is that 200 nested parens produce a
verdict rather than an interpreter-level failure.
