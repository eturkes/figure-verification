# M13.7b — the demo dataset spells a region code pandas reads as missing

Tier: **data**. Every artifact this unit changes is re-validated at use by the committed gate —
example goldens, canonical reports, ingest expectations — so a defect is re-checked for free by a
rerun. Rigor buys one structural validator (the idempotent re-derivation script plus the digest

Gate identity: `bash tools/gate.sh`, eight stages, green at 8/8 on a clean tree at the closing

## What this unit decides

`data/sales.csv` spells North America `NA`. That is one of the 19 default NA spellings pandas
recognises, so the python-mode CSV profile refuses those cells and every `groupby("region")`
program over `sales.csv` refuses `value_not_in_profile`. The refusal is CORRECT: pandas reads the
cells as missing, `groupby` drops all three rows, and the executed figure really would draw one bar
where the task asked for two. The DATA is what is wrong.

MEASURED exposure, not estimated. The corpus binds `bar_category_sum` and `bar_category_extremum`
to `sales.csv` in BOTH manifests — 3 + 3 rows in design, 3 + 3 in held-out. All six design twins
refuse, 6 of 6. Held-out simple therefore ceilings at 10/20 = 50%: six lost to this cell, four to
the standing multi-series and colour-by-category rulings. `Intent` requires ≥70%. M13.6's recorded
16/20 = 80% ceiling counted the four ruled refusals and not these six, so it was wrong by six rows.

User ruling: rename the region code `NA` → `NAM` in `data/sales.csv`, as its own unit ahead of the
width unit. The adversarial NA case is not discarded — it is already banked twice over, as
`tests/test_pysrc_aggregate.py`'s 19 hand-stated spellings and as a measured end-to-end refusal, and
S2 below makes the end-to-end half a committed test rather than a scratch measurement.

Simulated over the committed `m13-design` captures with the rename applied IN MEMORY, before any
byte changed: simple VERIFIED **0/25 → 2/25**, `value_not_in_profile` **3/25 → 0/25**,
`column_not_numeric` 2 → 3 (one row's true fault was masked by the profile refusal). The width unit
that follows takes it to 8/25; this unit owns the first two.

## Blockers a naive pass walks into

Named because each ships green:

1. **The ingest claim loses its fixture silently.** `src/verifier/ingest.py` documents that `NA`
   stays a string, and the JSON-mode ingest test proves it over `data/sales.csv`. A blind rename
   renames the test's expectation too, so every test stays green while the claim keeps no proof at
   all. S1 is the only thing that catches this, and it has to be decided by READING which
   occurrence is the proof rather than by running the suite.
2. **`g08_na_revenue_by_month.json` filters `region eq "NA"`.** Re-deriving its digest alone leaves
   the filter matching zero rows, so the example's output becomes an EMPTY table. The spec is still
   valid, the pipeline still runs, and the example silently stops demonstrating what it names. This
   is the failure with no red anywhere.
3. **`.secrets.baseline` must be regenerated.** The rename puts a new sha256 literal into tracked
   files, and a new digest is indistinguishable from a leak until it is baselined. The `secrets`
   stage names the file and line; regenerate with
   `uv run --locked detect-secrets scan --slim --exclude-files '^\.secrets\.baseline$'` and
   `git add` it, or the stage fails on an unstaged baseline.
4. **Derived-artifact ordering.** Where one committed artifact is generated from another
   (`examples/index.json` against the spec files, `stats.json` against records, any golden against a
   canonical report), re-deriving in the wrong order writes stale bytes that the gate then blesses.
   The census `## Ordering hazards` section is what fixes the order.
5. **The region code is a SORT KEY, and this rename does not move it.** `EU` < `NA` < `NAM` by code
   point, so every table sorted by region keeps its row order and only the label changes. Stated so
   the next pass does not re-derive it; pinned by D1's `("EU", "NAM")`.
