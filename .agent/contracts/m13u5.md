# M13.5 — verdict + recomputation + certificate: the engine `Intent` already promises

Tier: **kernel**. Judgment-bearing: this unit is where "recomputes every plotted number" stops being
a sentence and becomes a mechanism, and where the certificate starts making claims a reader acts on.
Full adversarial battery — diff-blind red suite, independent oracle + differential, mutation credit.

Predecessors: M13.1 pre-scan, M13.2 admission, M13.3 formula projection, M13.4 dataset projection.
The core today is `prescan → admit → project` and STOPS. There is no public entry, no verdict, no
recomputed table and no certificate, so M10 has nothing to integrate.

## What this unit decides

1. The public entry and the verdict VALUE that M10 consumes.
2. The numeric contract for `sin cos tan exp log sqrt pow` — a RULING, not a port. `expr.py`'s
   exact-rational evaluator is the wrong tool here and is not ported (see § Declared rulings, N).
3. How the user's CSV bytes reach the verifier at all — no such path exists today.
4. The safe CSV profile: what the verifier parses with stdlib `csv` + `float`, and what it refuses
   because the sandbox's `pandas.read_csv` would parse it differently.
5. The plotted table — the static product of recomputation, and the thing the certificate binds.
6. The core certificate, including what it declares OPEN rather than claiming.
7. G7, G8, G9 — three integrity rules that become decidable for the first time because the table
   exists.
8. The work tariff and the resource ceilings that must exist before the verifier reads or evaluates
   anything.

## Surfaces

New, all stdlib-only, all under `src/verifier/pysrc/`:

- `verify.py` — the public entry, arm dispatch, verdict assembly.
- `numeric.py` — the binary64 evaluator over `spec.Expr`, plus the grid materializer.
- `csvread.py` — the safe CSV profile: strict parse, column selection, cell admission.
- `table.py` — `PlottedTable` + its canonical encoding.
- `certificate.py` — `CoreCertificate` + its plain-words interpretation.
- `budget.py` — the work meter, MOVED from `src/verifier/work.py` (see § Declared rulings, W1).

Edited: `spec.py` (targets, provenance), `errors.py` (11 codes), `limits.py` (7 fields), `__init__.py`
(public re-export).

**Named seams (contract-fixed, so the diff-blind suite and the implementation meet).** E1's "only
public entry" is about `verifier.pysrc.__all__`, not about module shape: every stage is an
underscore-free module-level function, which is what makes E3's call-counting bombs patchable and
what M13.1–M13.4 already do (`prescan`, `parse_admitted`, `project`). Fixed here:
`verify.bind_target` · `verify.recompute` · `verify.check_integrity` · `certificate.certify` ·
`numeric.evaluate_expr(expr: Expr, x: float, budget: WorkBudget) -> float` ·
`numeric.materialize_grid(grid: Grid, budget: WorkBudget) -> tuple[float, ...]` ·
`PlottedTable.canonical_bytes() -> bytes`. Nothing else internal is fixed — a predicate whose fault
shape is visible in the returned `Verdict` is exercised through `verify_python_source`, so the
decomposition below these seven stays free.

**Patch namespace = `verifier.pysrc.verify`, for every stage seam.** `verify_python_source` resolves
each stage as a global of its OWN module, so E3's bombs go on the `verify` module object under the
seam's bare name — `monkeypatch.setattr(verify, "certify", bomb)`, and likewise for the three
already-shipped upstream stages `verify.prescan`, `verify.parse_admitted`, `verify.project`.
`certify` is therefore imported as `from verifier.pysrc.certificate import certify`: patching
`certificate.certify` instead rebinds only the definition site while `verify`'s own reference still
points at the real function, so the bomb never fires and the ordering test passes vacuously — the
silent-no-op shape `.claude/rules/assurance.md` names for import-bound function objects.

Tests: `tests/test_pysrc_verify.py` · `tests/test_pysrc_numeric.py` · `tests/test_pysrc_csv.py` ·
`tests/test_pysrc_certificate.py` · G7/G8/G9 into the existing `tests/test_pysrc_integrity.py`.
Mutants: `tools/mutants/verify.toml`, `tools/mutants/numeric.toml`, `tools/mutants/csvread.toml`.

## The N8 ruling — `pow` is 1 ulp, and its stdlib spelling is `math.pow` under C99

Measured over 1,000,000 stratified `(base, exponent)` pairs, nine labelled regions, all operands
finite, seed `0x5337504F57`. Regions: the exact `linspace(0,2π,100)` grid squared · positive base
`1e-300..1e300` with the exponent held inside the finite range · negative base with an integral
exponent · negative base with a non-integral exponent · signed-zero base against both exponent signs
· base within 1e6 ulp of 1 against `|exponent|` up to 1e17 · the overflow/underflow edge · random
finite base with an integral exponent 0..10 · unstructured finite bit patterns for both operands.

**Band.** Host numpy 2.2.5 vs Pyodide-wasm numpy 2.2.5: **238/1,000,000 disagreements, every one
exactly 1 ulp**, byte-identical results on Pyodide 0.28.0 and 0.28.1. `pow` therefore joins
`sin cos tan exp log` at the same published 1-ulp band instead of inheriting it by assumption.

**Category structure never split: 0/1,000,000.** Wherever one side is `±inf` or `nan`, so is the
other. The `value_not_finite` REFUSAL is therefore environment-independent; only a finite value's
last bit is ever in question. This is what lets N4 stay one code.

**The spelling is `math.pow`.** CPython's `**` is unusable as the primitive: on the same corpus it
returned a COMPLEX on 135,034 pairs and raised `ZeroDivisionError` on 49,764 more, so it leaves
`float` entirely. `math.pow` never does, and wherever it SUCCEEDS it is bit-identical to numpy —
639,275 of 639,275, zero disagreements.

**But its exceptions are ambiguous, so the mapping is C99's and not a catch-all.** `ValueError`
alone covers three different numpy answers: `+inf` (45,528), `-inf` (4,236) and `nan` (176,382);
`OverflowError` covers `+inf` (106,790) and `-inf` (27,789). A blanket `exception → nan` — the
reading N3 invited before the data — disagrees with numpy on **184,343/1,000,000**. The operands
resolve it, and the explicit rule in N3p measured **0/1,000,000**, `nan` matched as a category.

Both counter-measurements are recorded on purpose: a rule this specific has to be shown doing work,
and 184,343-vs-0 is that demonstration.

## The C10 ruling — RESTRICT, and the profile is measured

Decided by the rule fixed BEFORE the data ("prefer RESTRICT if a 0-disagreement region covers
non-exponent texts with ≤15 significant digits and ≤6 decimal places"). `spike-m13u5b` found exactly
that region and measured it at **0/4,000,000** bit mismatches against target Pyodide — 1,000,000
fixed decimals and 1,000,000 signed-32-bit integers, each in plain and fully quoted form. The band
is unnecessary inside the region and reimplementing pandas' `xstrtod` is unnecessary unless a later
corpus proves the restriction misses real data.

What forced the restriction: stdlib `float` and the sandbox's DEFAULT `pandas.read_csv` disagree on
326,834 of 1,000,000 adversarial cells (314,781 at 1 ulp, 12,053 at 2–7,262 ulp); only
`float_precision="round_trip"` agrees fully; and no significant-digit cap alone repairs it, since
even `1e-23` disagrees.

**The admitted profile, six clauses. `csvread.py` implements exactly this.**

1. **Bytes and dialect.** Strict UTF-8. Refuse an initial BOM and any NUL. Comma delimiter, `"`
   quote, doubled `""`, `escapechar=None`, `comment=None`; backslash is ordinary text. LF or CRLF
   records, and correctly quoted embedded LF/CRLF. `csv.reader(strict=True)` must consume the bytes
   with no post-quote junk.
2. **Shape and header.** Exactly one header record and ≥1 data record. Every header cell nonempty
   and unique. Every data record exactly the header's width. Selected headers matched by exact
   decoded text.
3. **Selected-column kinds.** `y` numeric for every mark. `x` numeric for `line` and `scatter`. For
   `bar`, `x` is wholly numeric or wholly categorical — a mixed column refuses. A categorical cell
   is nonempty, outside the NA set, fails `float(text)`, and case-folds outside `{true, false}`
   (otherwise pandas infers `bool`, not `object`). Categorical `x` values unique.
4. **Numeric cells.** The whole decoded token matches ASCII `-?(?:0|[1-9][0-9]*)(?:\.[0-9]{1,6})?`;
   ≤15 significant digits counting explicit trailing zeros; value in `[-2147483648, 2147483647]`,
   finite, and NOT a sign-bearing zero. All-integral tokens make pandas infer `int64`; any token
   with a point makes it `float64`.
5. **NA and row semantics.** Refuse an empty selected cell and each of the 19 measured pandas NA
   spellings, quoted or plain: `''` `#N/A` `#N/A N/A` `#NA` `-1.#IND` `-1.#QNAN` `-NaN` `-nan`
   `1.#IND` `1.#QNAN` `<NA>` `N/A` `NA` `NULL` `NaN` `None` `n/a` `nan` `null`. Preserve file order;
   never sort.
6. **Renderer closure — the clause that is not about parsing.** The int32 range excludes Pyodide
   `plt.bar`'s signed-32-bit overflow, which RAISES rather than mis-draws; the negative-zero refusal
   excludes matplotlib bar's only measured bit change (99/1,024 heights: every `-0x0.0p+0` becomes
   `+0x0.0p+0`). Line and scatter preserved every tested bit (0/40,000 each). A categorical bar maps
   unique labels to float64 centers in FIRST-OCCURRENCE order, which is why duplicate categories
   overplot and G8 refuses them.

The refusal set is the exact complement, and every member lands on `value_not_in_profile`,
`csv_not_parsable`, `column_not_numeric`, `column_not_present` or `category_not_unique` — no new
code. Unselected cells stay unrestricted once the structural byte checks pass.

Two consequences to record rather than hide. The int32 range is a SUFFICIENT condition measured as
one profile, not a necessary one: a float column is `float64` and is not bound by matplotlib's
integer-bar path, so the float branch could widen on its own measurement — deferred, not assumed.
And the profile was measured on Pyodide 0.28.1 / pandas 2.3.1 / NumPy 2.2.5, while
`.claude/rules/owui.md` records the demo's sandbox as Pyodide `0.28.0.dev0` with pandas 2.3.1;
released 0.28.0 bundles pandas 2.3.0. M10 must reconcile that identification against the live
sandbox before the profile's measurement is claimed of it.

## The K ruling — the certificate's constants are fixed here, not chosen per arm

K2/K3/K4/K6 each demanded a byte-pinned value the predicate table never supplied. Both arms would
have invented their own, so every K test would go red on a disagreement that is not a defect.
Fixed:

**K2 — digest form.** `"sha256:" + hashlib.sha256(payload).hexdigest()`, for `source_sha256`,
`spec_sha256`, `table_sha256` and `artifact_sha256` alike. `source_sha256`'s payload is the EXACT
bytes the entry encoded from `source` — UTF-8, no normalization, no canonical re-emission. NO hash
prefix: every shipped digest surface (`vcert.hash_vega_lite`, `replay._raw_digest`,
`service/audit._digest`) is this same plain form, and a core that separated domains inside the hash
would read differently from all of them. The M13 binding rule's "new domain tag" is carried by the
ENCODING and the field name instead — each canonical encoder opens with its own domain line, so no
two payloads can collide even though the hash is untagged:

## The remaining suite objections — ruled

The diff-blind suite reported eight predicates whose acceptance demanded a value the predicate never
supplied. Ruled here so neither arm invents one.

**T3 — length prefix = unsigned 64-bit BIG-ENDIAN** over the cell's UTF-8 byte length, ahead of
those bytes. Injective and self-describing; the suite's independent choice, ratified rather than
replaced.

**K3 — the check record is `CertifiedCheck(id, status)`**, the type § Surfaces already names and
`verifier.pysrc` already exports. NOT a new `CoreCheck`.

**W2 — the tariff, stated as arithmetic** so it stops being a reading. Formula arm =
`samples * y_nodes` for evaluation, plus `2 * samples` for the emitted x and y cells. The GRID is
materialized, never evaluated: `materialize_grid` builds samples from the standard-exact
constructors, so there is no tree to walk and no per-node charge — the grid's cost is the table cell
it becomes. Dataset arm = `1 + len(cell_text) // 32` per CSV cell READ, header cells included
because they are read, plus `2 * rows` for the emitted cells. The read term was a flat 1 until W5's
benchmark measured a 7.3× wall-clock spread across cell widths under it; § The W2 tariff is
size-aware carries the sweep and the divisor's derivation.

**W4 — each cap owes its own over-limit WITNESS, and the codes are shared by fault family.** Seven
unique codes would be seven spellings of two facts. The map is exact:
`max_csv_bytes`, `max_csv_rows`, `max_csv_columns`, `max_csv_cell_bytes` → `csv_too_large`;
`max_table_rows`, `max_expr_nodes`, `max_work` → `work_budget_exceeded`. A code names the fault the
AUTHOR must fix, and all four CSV caps say "this file is too big for the verifier" while the other
three say "this program asks for more work than the budget". What must stay per-cap is the witness:
each cap needs a test that trips it ALONE with the other six slack, which is what proves no cap is
dead.

**C7 — a duplicate header refuses `csv_not_parsable`, not `column_not_present`, and no new code is
added.** C10 clause 2 already requires header cells nonempty and UNIQUE, so a repeated header is a
PROFILE violation caught at parse time, before column matching runs. `column_not_present` keeps its
own meaning: a well-formed header that lacks the named column. Conflating them would tell the author
to fix the wrong thing.

**C5 — the non-consumption disclosure**, byte-pinned `declared_open` entries under K6's register:

- formula arm, any target state: `No user artifact was consumed. The plotted values come from the
  submitted program alone.`
- formula arm WITH a `DatasetTarget`, additionally: `The supplied data file was not read by this
  chart.`

**N7 — the class table is exported as `OPERATOR_CLASSES`**, keyed `"standard-exact"` and
`"libm-dependent"`, values the operator-name frozensets. The test hand-states it as a literal.

**C8 vs C10 — the missing piece is a COLUMN CLASSIFICATION rule, not a code change.** C8 sends a
non-numeric cell to `column_not_numeric` while C10's witness list names hex, thousands separators
and underscores as `value_not_in_profile`. Both rows are right about a DIFFERENT fault shape, and
the contract never said which cells make a column non-numeric. The tempting fix — route by "what
dtype would pandas infer" — is barred by the layering: `csvread.py` is stdlib-only and never calls
pandas, so that rule is unavailable without reimplementing the number grammar that § The C10 ruling
exists to avoid. The rule below decides every case from the cell text alone, in three total stages.

*Stage 1 — inadmissible cell text*, per cell over BOTH selected columns in source order, before any
column-level question: empty · any of the 19 NA spellings · a cell case-folding to `true` or
`false` → `value_not_in_profile`. This is C9 widened by exactly one family, and the family belongs:
all three are text the sandbox coerces to a dtype the verifier has no type for (`NaN`, `bool`), so
the fault is identical and no new code is warranted. It also removes bool from C8's prose, where it
sat as a parenthetical rather than a decision.

*Stage 2 — column class*, per selected column over the surviving cells: EVERY cell profile-numeric
⇒ `numeric`; NO cell profile-numeric ⇒ `categorical`; otherwise ⇒ `mixed`.

*Stage 3 — role*, the mark deciding what the column is allowed to be:

| role | numeric | categorical | mixed |
|---|---|---|---|
| `y`, every mark | verify | `column_not_numeric` | `value_not_in_profile` at the FIRST non-profile cell |
| `x`, `line` + `scatter` | verify | `column_not_numeric` | `value_not_in_profile` at the FIRST non-profile cell |
| `x`, `bar` | verify | verify (G8 uniqueness then applies) | `column_not_numeric` |

Both rows come out true at once. `column_not_numeric` is a ROLE fault — the author charted a text
column on an axis that needs numbers, or gave a bar an x that is half of each — and its fix is to
choose a different column. `value_not_in_profile` is a CELL fault — the column is otherwise numeric
and one cell's text is outside the admitted region — and its fix is to repair that cell. Hex,
underscore and thousands separators are cell faults exactly when the rest of the column parses,
which is the case C10's witness list is describing; a column of nothing but hex is a role fault,
which is the case C8 is describing. Precedence is `.claude/rules/pysrc.md`'s LOCAL before GLOBAL one
level down: the cell sweep runs before the column class, and the column class before the mark's
role check.

Two consequences that change what gets written. **A C10 boundary witness needs at least two data
rows, one of them in profile** — a single-row CSV holding only `0x1f` classifies `categorical` and
refuses `column_not_numeric`, so a one-row witness silently tests the neighbouring predicate and
passes for the wrong reason. Each of C10's thirteen witnesses therefore carries an in-profile
companion row. And **zero data rows refuses `csv_not_parsable`**: the strict profile requires at
least one data row. That clause is load-bearing rather than cosmetic — with no rows, stage 2's
`every` and `no` are both vacuously true and the class is ambiguous. Existing code, so the closed
set stays at 50.

**E4/E6/N2 objections are accepted as written and need no ruling.** Labels are model-authored by
design, so E4's identifier scan uses distinctive VARIABLE names projection must erase, never label
text; E6's recursive strategy is evidence of totality over the admitted expression language, not a
proof, and the predicate never claimed more; N2's `Fraction(float)`-vs-decimal distinction is
projection's to pin, not the evaluator's.

## The W2 tariff is size-aware — the per-cell charge did not bound wall clock

W5 asked for a MEASURED rate rather than a guessed `max_work`. Measuring it falsified the premise
the whole budget rests on: **a work unit is a wall-clock bound only if its cost is roughly
constant, and under the per-cell dataset charge it is not.** Work is charged per CSV cell, so cell
WIDTH is free to the meter and not to the clock. Swept over categorical x widths 8 → 512 on the
host of record, the per-cell rate falls from 500,466 to 68,612 work/s — a **7.3× spread**. No
single `max_work` bounds both ends: sized for the wide end it is 7× too loose for ordinary charts,
and sized for the narrow end it refuses them.

That is not a tuning problem, it is a cap inconsistency. Holding one second at the wide-cell rate
needs `max_work` ≈ 68,000, while `max_csv_rows = 100,000` over two columns already costs 400,002
work — so the declared row cap would be unreachable, and the two limits would contradict each
other in the shipped defaults.

**RULED: the dataset read charge becomes `1 + len(cell_text) // 32` per cell read.** Everything
else in W2 is unchanged — expression nodes have no size, and the emitted-cell charge stays flat at
`2 * rows` because those cells are a SUBSET of the cells already surcharged at read, so their width
is counted once rather than twice.

The divisor is measured, not chosen. A two-point fit on the host gives ≈ 1.28 µs per cell plus
≈ 0.051 µs per byte, so a byte costs about a twenty-fifth of a cell and 32 is the power of two
nearest that ratio. Under it the same sweep flattens to a **1.5× spread**, and `max_csv_rows`
becomes reachable again.

| cell width | per-cell work/s | size-aware work/s |
|---|---|---|
| 8 | 500,466 | 500,466 |
| 16 | 482,342 | 482,342 |
| 31 | 416,354 | 416,354 |
| 32 | 396,281 | 594,412 |
| 63 | 311,742 | 467,606 |
| 64 | 308,314 | 616,613 |
| 128 | 180,913 | 542,714 |
| 256 | 122,620 | 613,033 |
| 512 | 68,612 | 617,367 |

Two facts the sweep design turns on. **The floor sits just BELOW a threshold, not at a round
width**: a floor-division surcharge is worst where a cell pays full time for zero extra charge, so
widths 31 and 63 are load-bearing sweep entries and a sweep of round widths alone reported a floor
of 489,496 that the verifier cannot hold. And the FORMULA arm's per-node charge needed the same
test rather than an assumption — it passes: two workloads sharing a node count and differing only
in operator class (`sin`/`exp`/`sqrt` versus pure arithmetic) sit within about ten percent of each
other across runs, because per-node interpreter overhead dominates the libm call. That is also why
the tariff needs no per-operator weighting. The gap is smaller than the run-to-run variance, so the
figure to quote is the bound, not any single run's spread.

Benchmark = `tools/bench_pysrc_work.py`, one command, no arguments; it lands with this unit's
merge, because it imports `numeric.py` and `csvread.py`. It reads the work
back from the production meter rather than re-modelling the tariff, so it reports a wrong rate
only if the meter itself is wrong. It prints both columns permanently: a tariff regression shows up
as the per-cell column fanning back out.
