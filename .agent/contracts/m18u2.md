# M18.2 — "Show checks" rows open: what each check does, the code it read, why it failed, the specification link

Tier **kernel**: `webui/paste_in/checks.py` + `filter.py` are the sole publication path and now quote model-authored bytes into the user's chat; an unescaped byte, a trigger string, a mis-marked line, a dropped verdict or a link to an unvetted target has no downstream re-check.

## Rulings (user, this request)

- **V1 rows.** Each of the 11 rows becomes its own collapsed disclosure; its summary = the M16.1 row (mark + title + `not checked` + covers + the failing row's cause). Opened, it shows, in order: (a) what the check does (fixed text per check, EN/JA); (b) skip rows: that the check did not run; (c) the program lines the check read, the refused span marked; (d) failing row: why it failed; (e) a link to the check's section of the python-mode reference (M18.3).
- **V2 code.** The selected receipt's program bytes enter the embed (supersedes M16.1 C9 for the program alone), escaped, inside the listing alone; whatever the program itself spells (a file path, a copied request word, a literal) shows with it, unredacted. Request text, file names, CSV content, `stdout`/`stderr` are never added from any other source (C9's remainder + M15 ruling 4 hold).
- **V2b marks (consultant-1).** Only a genuine program location (M18.1 `at`) is marked; the related lines of a check whose fault sits in the file, the data, the request or a limit are quoted unmarked.
- **V3 link.** A fixed link to the reference's GitHub page on `main` (user: the instance is network-less, its users' browsers are not), EN or JA by the D5 request language, row link = `<url>#check-<id>`, opened in a new tab. No admin setting.
- **V4 extras = none.** No file facts, recomputed table or traceback.
- **V5 check change (implied by V1-V3; original firing recorded at close).** M16.1 C4 (document shape: one `<details>`, row slot list), C5 (no `href`/`https:`, ≤ 16384 bytes), C9 (no program byte), M15.1 D7's all-event byte ban (`tests/test_paste_in_filter_reasons.py`: narrows to the status event + log record; the embed's program bytes move under E6), the single-`details` parser in `tests/filter_checks_support.py`, the `_translate_outlet` embed parse in `tests/oracle_filter.py` + `tests/test_paste_in_filter_differential.py`; every other conjunct kept.
- Unchanged: `CHECKS`, `CHECK_OF`, `TEXTS`, `STRICT_BINDING`, `SHOW`/`HIDE`/`UNRUN`/`MARKS` bytes, `REASONS`, the status line, the log record, `PASS_TEXT`/`FAIL_TEXT`, `content`/`output`, the embed's place + `replace`, the shared deadline (M16.1 C8), the tool + its model-facing strings, the publication gate.

## API — `webui/paste_in/checks.py`

- `Evidence(program: str | None = None, at: tuple[Span, ...] = (), trace: Trace = ())` frozen slots.
- `EXPLAIN: dict[Check, tuple[str, str]]` (EN, JA). UI words (EN, JA): `WHAT` `CODE` `WHY` `NOT_RUN` `STOPPED` `SPEC` + `ELIDED` (`str.format` with `n`) + `BEYOND` (the scan cap note).
- `CODE_ROLES: dict[Check, tuple[Role, ...] | Literal["all"] | None]` = `program` `readable` `accepted` `chart` `render` → `"all"`; `binding` `recompute` → `("source", "data", "mark")`; `integrity` → `("data", "mark", "title", "xlabel", "ylabel")`; `match` → `("mark",)`; `data` `attach` → `None`.
- `breakdown_html(reason, *, japanese, anchoring, evidence=Evidence())`.
- `SPECIFICATION: Final = ("https://github.com/eturkes/figure-verification/blob/main/docs/verification.md", "https://github.com/eturkes/figure-verification/blob/main/docs/verification.ja.md")` (EN, JA).

## Document (per row; everything else = M16.1)

Row: `<li class="<state>"><details class="row"><summary>` + the M16.1 row slots (mark, `div` holding `.title` [+ `.unrun`], `.covers`, fail: `.cause`) + `</summary><div class="more">` + sections + `</div></details></li>`; a row `details` is never `open`. The outer show/hide rules bind the OUTER summary alone (`#r>details>summary`), so a row's open state never toggles them; row summaries + listings wrap inside the frame (no horizontal scroll). Sections, in this order, each a `div` with its class, each led by a `span.label` holding its label word:
1. `.what` = `WHAT` + `p` = `EXPLAIN[check]`.
2. `.unrun-note` (skip rows alone) = `p` = `NOT_RUN` (no label).
3. `.code` (non-skip rows whose `CODE_ROLES` ≠ `None`, `evidence.program` ≠ `None` and ≥ 1 line selected) = `CODE` + one `pre.listing` [+ one `p.elided`] [+ one `p.beyond`].
4. `.why` (fail row alone) = `WHY` + `p` = `REASONS[reason]` + ` (<reason>)` [+ `p.stopped` = `STOPPED`, exactly when the listing holds a `span.line.at`].
5. `p.link` holding one `a.spec` = `SPEC`, `href` = `SPECIFICATION[language]` + `#check-<id>`, `target="_blank"`, `rel="noopener noreferrer"`.

Listing (pure function of `program`, the selected line set, `at`):
- Scan: `text = program[:65536]`; `p.beyond` = `BEYOND` iff `len(program) > 65536`. Lines = `re.split(r"\r\n|\r|\n", text)`, numbered from 1.
- Selected: `"all"` ⇒ every line; a role tuple ⇒ every line from `step.span.line` to `step.span.end_line` of each `evidence.trace` step whose role is in the tuple; the fail row adds every line from `line` to `end_line` of each `evidence.at` span. Lines beyond the scan are dropped.
- At-lines = selected lines an `at` span touches (fail row alone; pass rows never mark).
- Caps: ≤ 60 lines; ≤ 3000 characters, a line costing `min(len(line), 400)`. Fill order: at-lines ascending, then selected lines within ±2 of an at-line ascending, then the remaining selected lines ascending; a line is taken when it fits both caps, else skipped. `p.elided` = `ELIDED.format(n=<selected lines not taken>)` iff that count > 0.
- Output: taken lines ascending; one `span.gap` (`⋮`) between two taken lines whose numbers differ by > 1; each line = `<span class="line">` (`class="line at"` for an at-line) `<span class="ln">N</span><span class="src">…</span></span>`; `.line`, `.gap` = `display:block`, no newline characters between them.
- Line text: cut to its first 400 characters + `…` when longer. Marks: per at-line, the character set covered by the `at` spans (byte columns → characters within that line; a span's first line from its column to the line end, middle lines whole, last line from 0 to its end column; a point span covers nothing), clipped to the shown characters; each maximal run = one `<mark>`.
- Characters: `\t` stays; a character of category `Cc` `Cf` `Cs` `Co` `Cn` `Zl` `Zp` ⇒ U+2400 + code for U+0000-U+001F, U+2421 for U+007F, else U+FFFD; then `html.escape(quote=True)`; then `-` `.` `(` ⇒ `&#45;` `&#46;` `&#40;`. The `href` value takes the same escaping (keeps C5's trigger ban total over model text + the URL).

## Texts (human-facing; EN = ASD-STE100, ≤ 25 words per sentence; JA = natural polite Japanese, the guide's terms)

UI words (EN / JA): `WHAT` What this check does / このチェックの内容 · `CODE` Code checked / チェックしたコード · `WHY` Why it failed / 不合格の理由 · `NOT_RUN` This check did not run, because an earlier check failed. / 前のチェックが不合格だったため、このチェックは実施していません。 · `STOPPED` The check stopped at the marked code. / 印の付いたコードでチェックが止まりました。 · `SPEC` Read the full specification of this check / このチェックの詳しい仕様を読む · `ELIDED` Lines not shown: {n}. / 表示していない行: {n} 行。 · `BEYOND` The program is too long to show in full. / プログラムが長すぎるため、すべては表示できません。

`EXPLAIN` (EN / JA):
- `program`: The model must send its chart program through the chart tool. The verifier checks the last program sent in this reply. / モデルはグラフのプログラムをグラフ用のツールで送る必要があります。検証器は、この返信で最後に送られたプログラムをチェックします。
- `data`: The verifier needs data that you supplied. This is a CSV file attached to the chat, or one formula and one interval in your request. / 検証器には、あなたが用意したデータが必要です。チャットに添付した CSV ファイル、または依頼文にある 1 つの数式と 1 つの区間です。
- `readable`: The verifier reads the program as Python text before it examines it. It checks the size, text encoding, line length, tokens, brackets and indentation, then parses the syntax. / 検証器は、内容を調べる前にプログラムを Python のテキストとして読み取ります。サイズ、文字コード、行の長さ、トークン、括弧、インデントを確認してから、構文を解析します。
- `accepted`: The verifier accepts only a fixed set of Python statements, imports, function calls and arguments. Anything outside that set stops the check, also when Python could run it. / 検証器が受け入れるのは、決まった範囲の Python の文、import、関数呼び出し、引数だけです。その範囲の外にあるものは、Python で実行できる場合でもチェックを止めます。
- `chart`: The verifier reads which chart the program draws: one data source, one plot call, the labels, and plt.show() at the end. Every statement must contribute to that chart. / 検証器は、プログラムが描くグラフを読み取ります。データの読み込み 1 つ、描画呼び出し 1 つ、ラベル、最後の plt.show() です。すべての文がそのグラフに関係する必要があります。
- `binding`: The verifier checks that the program uses your data: it reads your attached file, or it plots the formula in your request. Column names in your request are compared with the columns that the chart draws. / 検証器は、プログラムがあなたのデータを使うことを確認します。添付ファイルを読み込むこと、または依頼文の数式を描くことです。依頼文にある列名は、グラフが描く列と比べます。
- `recompute`: The verifier computes every plotted value again from your file or formula, with its own code. Then it checks that each result is a finite number within the limits. / 検証器は、描画するすべての値を、ファイルまたは数式から独自のコードで計算し直します。その後、各結果が上限内の有限の数であることを確認します。
- `integrity`: The verifier checks rules that keep the chart honest. Bars start at zero, there is one set of axes with linear scales, and no row is left out. Categories do not repeat, and line x values are in order. A label must not name another file column that the verifier recognizes. / 検証器は、グラフを正しく見せるための規則を確認します。棒はゼロから始まり、軸は 1 組で目盛りは線形、行の欠落はありません。カテゴリは重複せず、折れ線の x の値は順序どおりです。ラベルは、検証器が認識できるファイルの列名のうち、グラフが描かない列名を挙げてはいけません。
- `render`: Your browser runs the model's program, unchanged, in the Open WebUI sandbox. The run must return one PNG image and the values that it drew. / ブラウザは、モデルのプログラムを変更せずに Open WebUI のサンドボックスで実行します。実行結果として、PNG 画像 1 枚と描画した値を返す必要があります。
- `match`: The verifier compares the values that the browser drew with the values that it computed. File values must be equal. Formula values must stay within the checked numerical bounds. / 検証器は、ブラウザが描画した値と、検証器が計算した値を比べます。ファイルの値は完全に一致する必要があります。数式の値は、定めた数値誤差の範囲内である必要があります。
- `attach`: The chart image is stored with this reply. If storing fails, the verifier shows no image. / グラフの画像をこの返信と一緒に保存します。保存できない場合、検証器は画像を表示しません。
