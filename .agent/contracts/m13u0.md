# M13.0 — one gate command + supply-chain scanning (contract)

Tier: **data** — the gate re-validates itself at every run, so rigor concentrates on the static
config invariants nothing else re-checks (G6–G10), not on re-proving tool behaviour.

Closes the `Deferred` row *"IMPLEMENT law gap: no CI, scanners, update automation"*.

## Scope

Wire format · lint · type-check · test · dependency audit · secret scan · workflow static analysis ·
shell lint behind ONE command, run identically by a human, by an agent and by CI. Add update
automation. No verifier behaviour changes; `src/verifier/` is untouched.

## Rulings this unit is implemented under

- Hermetic to `uv.lock`: every scanner resolves through `uv run --locked`. `shellcheck` stays the
  one host binary, matching the existing L9 skip-guard precedent.
- `uv audit` is uv-native and reads the same lock the gate installs from; a second advisory source
  (Dependabot) rides CI so the lock is not a single point of failure.
- The secret baseline is **slim**: `(filename, type, hashed_secret)` with no line numbers and no
  timestamp ⇒ deterministic bytes, stable under edits, still fails on a secret moving to a new file.
- Every `uses:` is SHA-pinned and every workflow declares least-privilege `permissions:` — the
  `trivy-action` supply-chain incident is the reason both are gate-enforced rather than advisory.

G6–G11 are static-config invariants with no downstream re-check ⇒ they get pinning tests
(`tests/test_gate.py`). G1–G5 are re-decided by every gate run ⇒ live spot-check, fix forward.
