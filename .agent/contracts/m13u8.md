## Predicates

### P — the pandas plotting accessor

All four measured rows write `<bound aggregate>.plot(kind='bar'[, color='skyblue'])` with NO
positional arguments; three of the four carry `color='skyblue'`. Nothing else appears.

**P1.** `g = df.groupby("region")["revenue"].sum()` then `g.plot(kind="bar")` then `plt.show()`
VERIFIES, and projects to the SAME `DatasetPlot` as the `plt.bar(g.index, g.values)` spelling of the
same program. Accept: a committed test asserts `project(parse_admitted(accessor_src)) ==
project(parse_admitted(plt_bar_src))` on structural equality, not merely that both verify. Two
spellings of one figure must project equal, exactly as the formula arm's grid identity rule
requires, or the certificate would publish a different figure for a cosmetic rewrite.

**P2.** `kind` is part of the TARGET IDENTITY, not a free keyword. Admitted map
`{"bar": "bar", "barh": "barh"}` and nothing else. A `kind` the map does not carry (`"pie"`,
`"hist"`, `"line"`), a `kind` that is not a string literal, and a MISSING `kind` all refuse
`call_target_not_admitted`. Accept: four committed refusals, one per shape, each asserting that
exact code. Rationale for reusing the code rather than adding an enum member: `<agg>.plot(kind=
"bar")` IS `plt.bar` spelled differently, so the accessor-plus-kind pair is the target, and a pair
the allowlist does not carry is the same fault `plt.pie` would be. `pandas`' own default for a
missing `kind` is a LINE plot; admitting it would be width no measured row asks for, so it refuses.

**P3.** The keyword allowlist on the accessor is exactly `{kind, color}`. Any other keyword refuses
`keyword_not_admitted`; any positional argument refuses `keyword_not_admitted`. Accept: a committed
refusal for `g.plot(kind="bar", figsize=(8, 5))`, one for `g.plot("bar")`, and an exact-set
assertion on the admitted keyword set so a later widening is a visible edit.

**P4.** `color` is validated as a STRING LITERAL and then discarded, identically to `plt.bar`'s.
`color=df["region"]` refuses `label_not_literal` — the colour-by-category channel is a data effect
wearing a cosmetic keyword's name, and the accessor must not become the hole that admits it.
Accept: one committed refusal, plus a test that `g.plot(kind="bar", color="skyblue")` and
`g.plot(kind="bar")` project EQUAL.

**P5.** The accessor is admitted on a REDUCED SERIES alone. `df.plot(kind="bar")` (the frame) and
`df["revenue"].plot(kind="bar")` (a raw column) both refuse `column_not_from_source`. Accept: two
committed refusals. Reason the code is reused rather than new: the receiver does not name a
projected aggregate, which is the same fault `_aggregate_channels` already names when a mark mixes
a reduced channel with a raw column.

**P6.** A SECOND mark still refuses. `g.plot(kind="bar")` followed by `plt.bar(g.index, g.values)`
refuses `multiple_marks`, and so does the reverse order. Accept: two committed refusals. The
accessor must enter the same mark-counting seam as every other mark, not a parallel one.

**P7.** `_admit_call`'s `<alias>.<attr>` shape is NOT loosened to admit the accessor. The accessor
resolves through its own route, keyed on a name the aggregation bound. Accept: `plt.plot_wrong`,
`np.plot`, and `pd.plot` each still refuse `call_target_not_admitted`, and an unbound
`nosuch.plot(kind="bar")` refuses `name_not_bound`. This is the predicate that keeps the alias
allowlist closed while a bound-name route opens beside it.

## Blockers a naive pass walks into

Named because each ships green.

1. **Unwrapping ANY trailing call instead of `reset_index` alone.** `_admit_aggregation` admits one
   trailing no-arg non-underscore call, so `.sort_values()` is already ADMITTED and is refused only
   at projection. A `_aggregate` that unwraps whatever trailing call it finds therefore silently
   admits `.sort_values()` — which REORDERS the rows, so the plotted x-order stops being the group
   key order. G9's monotonic/unique-category reasoning and G8's row-coverage reasoning both assume
   that order. Nothing in the suite fails; the figure just stops matching the ledger. R3 is the only
   thing that catches it, and it has to be written as an exact-set assertion rather than as a single
   `.sort_values()` case, because the next trailing call added would slip through a one-case test.
2. **Projecting the accessor without entering the mark-counting seam.** A parallel route that builds
   a `DatasetPlot` directly leaves `multiple_marks` unfired, so `g.plot(kind="bar")` beside
   `plt.bar(...)` publishes ONE of two figures with no refusal. P6 catches it. The same seam carries
   `_mark_shape`'s keyword routing, which is what keeps `color=` out of the series label.
3. **Reading `kind` at projection instead of admission.** If admission accepts any `kind` string and
   projection maps it, then an unmapped `kind` reaches a `.get(kind, default)` — this repo's
   most-repeated defect class — or an `else:` tail that picks a mark nobody asked for. The kind map
   must be a closed dispatch with refusal as the tail, and P2's four refusals are one per shape
   rather than one representative case.
4. **Re-capturing before the code lands, or after it in a second commit.** The capture is the
   measurement's input and the code is what grades it; M1's number is meaningless if the two come
   from different tips. Land admission + projection first, then re-capture, then measure, then
   commit once. The M13.4 oracle lesson is the same shape: an artifact seeded from a skeleton commit
   proved nothing until it was re-based onto the code it graded.
5. **The mutation catalogues.** A widening silently invalidates anchors in catalogues this unit does
   not touch: M13.6 edited four lines that M13.3 and M13.4 mutants anchored on, and the driver
   reported ANCHOR-MISS rather than a kill. Rerun ALL THREE of `tools/mutants/{project,aggregate,
   csvread}.toml`, not just the one whose module changed, and add mutants for every predicate this
   unit ships — coverage alone credits nothing at kernel tier.
6. **`data/sales.csv`'s region column.** M13.7b's closed law binds here: a demo dataset may never
   spell a group key with a pandas NA spelling. The accessor rows group on `region`, so any fixture
   this unit adds must keep every region value outside `csvread.NA_SPELLINGS`.
