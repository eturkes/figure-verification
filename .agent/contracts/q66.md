# Q66 — the request = the user's messages on the chat branch

Tier **kernel**: the request text decides column anchoring (strict + substitution), the typed-number source (R4 labels, Q45 typed computations) and G10's label read; no downstream check re-reads it.

## Row

User ruling (this request's question, option `Whole chat thread`): a follow-up (`Use orders instead of revenue.` after `Chart the total revenue of each region using bars.`) blocked `column_not_named` under production strict anchoring, because the receipt carried the latest message alone (`tool.py::_request_text` ← `__metadata__["user_message"]["content"]`); a typed-number chart's follow-up (`make them red`) lost its value check. Accepted costs (stated in the question): anchoring loosens as a chat grows; more typed numbers widen chance matches.

## Found at orientation (MAIN, c1ec361)

- Open WebUI 0.11.3 `main.py` upserts the current user message into the chat before the completion runs (`Chats.upsert_message_to_chat_by_id_and_message_id`; a new chat is inserted with it), and `metadata` carries `chat_id` + `user_message_id`; `process_chat_payload` itself reads the branch as `get_message_list(Chats.get_messages_map_by_chat_id(chat_id), user_message_id)`.
- The model-facing `body["messages"]` / `__messages__` are unusable as the source: the inlet rewrote the latest message into the template that lists every CSV column (`Its columns are …`), and `compact_messages_for_request` can replace older turns with a model-written `[CONVERSATION SUMMARY]` — either lets model or template text anchor a column.
- `main.py` lets an admin continue another user's chat (`is_chat_owner(...) and user.role != 'admin'`) ⇒ ownership must be the filter's own check under the requester's id, as for files.
- Temporary chats (`local:` ids) and channels (`channel:`) store no owned chat row ⇒ `is_chat_owner` is false there.

## Predicates

- **R1 thread** — the requester owns the chat (`Chats.is_chat_owner(chat_id, user_id)`), the branch `get_message_list(map, user_message_id)` ends in a `user` message whose `content` equals the latest message's text ⇒ request = the `content` of every `user` message on the branch with `str` content, oldest first, joined by `"\n\n"`.
- **R2 fallback** — anything else ⇒ the latest message alone (today's value, `None` when it has no text content): no or empty user id, chat id or message id; not the owner; no map; an empty branch or one not ending in the current message; `open_webui` absent; any `Exception` while reading. A cancellation propagates.
- **R3 ownership first** — no message is read for a chat the requester does not own (the map read never runs).
- **R4 user text only** — assistant, system and tool messages never enter, whatever they hold.
- **R5 receipt** — `draw_figure` records R1/R2's text as the receipt's `request_text` under `__user__`'s id; program, ids, aliases + the reply string unchanged; JA reply language stays the latest message's (`filter.py::_japanese`).
- **R6 effect** — host reader + judge over `data/sales.csv`: the follow-up chart of region × orders passes strict under the thread text and blocks `column_not_named` under the latest message alone.
