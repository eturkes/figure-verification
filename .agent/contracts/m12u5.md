## 5. Capture prompt v1 — byte-pinned

sha256 `a18162f788cce976a55458545c5761e2fd5b8b924e116ac137ffc4deb004964e`, 189 B.

```
{task}

Use the CSV file at /mnt/uploads/{dataset}. Its columns are {columns}.
Draw the figure with matplotlib.

Return one complete Python program as bare source text, no Markdown fences.
```

Rulings behind these bytes:
- ONE user message, no system message, ZERO few-shots (ruling 6). `capture/corpus.py` owns
  rendering, so the sha means the wire bytes.
- The path is `/mnt/uploads/<dataset>` because that is where OWUI's Pyodide worker writes an
  uploaded file (`res-port`) — captures must be representative of the demo the model will face.
- matplotlib IS named: it is the output MEDIUM, the same class as "no Markdown fences", and an
  unnamed medium pollutes the simple arm with plotly/altair failures that measure nothing.
- The CSV-reading library is NOT named: which of `pandas` / `csv` / `numpy` the model reaches for
  is exactly the idiom evidence M13 needs. Over-constraining destroys the observation.
- `Return one complete Python program as bare source text, no Markdown fences.` is byte-required by
  the roadmap. `res-port` measured unconstrained replies at 0/3 `ast.parse`-able with fences +
  256-token truncation as the cause, so FORMAT is the one thing the prompt may push on.

## 6. Ruling authority

- Ruling 6 (no admission vocabulary) is enforced MECHANICALLY by C6, not by review. The banned list
  is a closed literal in `capture/corpus.py`; adding a term is a MAIN edit.
- A prompt that describes WHAT to plot is admissible however elaborate. A prompt that describes what
  the verifier will do with it is not, in either category.
- Complicated prompts must overreach on SUBSTANCE (layout, composition, derived statistics, styling,
  data outside the bound CSV), never by prompt injection or by naming a policy. The 260-byte
  dashboard sentinel is the reference shape.
- Teammate disagreement with any predicate is a report row for MAIN, never a validator edit.
