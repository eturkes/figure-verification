Tier **kernel** once funded: the value vocabulary decides `value_not_found`, and a widened vocabulary passes figures nothing re-checks.

## Row

A drawn value that is a fixed transform of the CSV's or the request's numbers (squares of `1 to 10`, a cumulative sum, a share of total, a ratio of two columns) blocks, since the value vocabulary is raw values + one group-and-reduce. Accept: a closed transform list, no transform reading the request wording (no inference); each transform ships with its chance-match rate measured over `data/*.csv` + random made-up series of 1-10 points and recorded beside it; a value no listed transform explains still blocks; per transform ≥1 honest twin passes + ≥1 wrong-value program blocks.

## Agent-side evidence (X1, `.agent/measurements/x1_transforms.py`, `expected/X1.json`)

Nine candidates: of one vocabulary series (raw, index, group sum/mean/min/max, count) — `square`, `cumsum`, `share` (v/Σ), `percent` (100·v/Σ), `diff` (consecutive); of two numeric columns per row and per group sum — `ratio`, `difference`, `product`, `total`. The request leg applies the five one-series transforms to `1 to m` (m = 3, 5, 10) and m random integers in [1, 100]. Added chance = made-up series the transform explains and today's vocabulary does not, per 10,000, grids `int` + `dec2` over [0, 2M] (M = the transform's largest value). CSV leg: keyed series, n distinct keys of one key column, both sides matched injectively as the judge matches rows; the CSVs' key columns hold at most 3-4 keys, so the CSV leg measures n = 1-4 alone. Request leg: values alone (R4), membership as the judge matches typed numbers, n = 1-10. Full-series ties with vocabulary series over other columns: 0 for every transform on every CSV.

Reading: on these CSVs (6-9 rows) every transform but `share` adds ≤ 1.11% at one point and ≤ 0.03% at two or more; `share` on an integer grid is the grid's artifact (M = 1), 0.5% / 0.02% / 0 on two-decimal values. Request-number transforms on a short range add up to 10.5% at one point, 3.3% at two and 0.9% at three or more (`cumsum`, `square`). Limits: three small CSVs with ≤ 4 keys per key column; grids scale with each transform's range; exactness = Python binary64, not yet pandas' own summation order for `cumsum`/`share`.
