## Rulings this unit is implemented under

- **R-cap — the token cap must not bind.** A 6-row pilot (2 design simple, 2 design complicated,
  both sentinels) at a 1024 cap measured a natural completion band of **148–470 tokens with 6/6
  `finish_reason == "stop"`**. The run therefore sends `--max-tokens 1024` against a server started
  with `MODEL_BACKEND_MAX_TOKENS=1024`, so the truncation statistic measures the MODEL and not the
  budget. The shipped default 512 is deliberately NOT used: the longest observed natural reply sits
  within 9% of it, so 512 would convert model verbosity into a budget artifact. A non-binding cap
  costs zero wall time — generation stops at the model's own EOS, never at the ceiling.
  The server cap must be ≥ the client cap: the backend clamps silently
  (`max(1, min(requested, settings.max_tokens))`) and the manifest records what was SENT, so a
  client cap above the server's would commit a manifest that misstates the effective ceiling.
- **R-oneshot — the run completes in ONE invocation.** Provenance samples `git_dirty` once, before
  row 1; writing row 1 makes the tree dirty, so a resumed run's freshly built manifest disagrees on
  `git_dirty` and R-resume refuses. That is the contract working, not a defect: a resumed run would
  mix two tree states into one evidence set. A failed run restarts under `--overwrite`.
- **R-complete — completeness is this unit's own claim.** R1–R11 grade what a run CONTAINS, never
  what it OMITS: R5 admits "its own set plus sentinels and nothing else" and R3 only agrees
  `record_count` with the rows present. A run holding 3 of 50 rows passes every committed
  predicate. The prompt-id set is therefore asserted here, against the committed corpus.
- **R-tracked — `bench/reports/` is gitignored and that is why evidence moved to `corpus/`.**
  The negative test passes `--no-index` (memory: `git check-ignore` suppresses TRACKED paths by
  default, so a committed negative ignore-test is otherwise vacuous) and proves tracking separately
  with `git ls-files --error-unmatch`.
- **R-heldout-committed — ruling 7 earns a second mechanical guard.** 6b guards GENERATION
  (`--kind heldout` refuses without `--heldout-acknowledged`); this unit guards the COMMITTED
  STATE — no run under `corpus/python/captures/` may declare `kind == "heldout"`. The held-out set
  stays ungenerated until the M13 config is frozen for the acceptance read.
- **The predicates are called, never restated** (`.claude/rules/python-corpus.md`). The new suite
  invokes `validate_records` + `validate_stats` and adds only the four claims those two cannot
  make: completeness, tracked-ness, held-out absence, and a non-vacuous run count.
