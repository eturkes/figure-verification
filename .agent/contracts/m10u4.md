# M10.4 — the formula arm exposed in OWUI

Tier **kernel**. Gate identity `bash tools/gate.sh`. Dispatch: `test` (diff-blind red suite from
these predicates) + `orc` (independent request-grammar implementation → differential; widens the
M10.0 tool-scan oracle to the formula candidate) + `prod` (implementation); MAIN holds the primary
tree + gate.

## What this unit ships

1. **Core target widening** (`src/verifier/pysrc/{spec,verify,certificate}.py`): a user-stated
   interval without a sample count binds; a formula program never verifies against a CSV target;
   the certificate states truthfully what the request bound.
2. **The request grammar** `pyexpr-0.1` (`src/verifier/pysrc/request.py`, NEW, stdlib-only,
   embedded by generation): the user's request sentence → `FormulaTarget | None`.
3. **The tool's formula candidate** (`webui/paste_in/tool.py`): the request's formula target joins
   the scan, LAST.

## Rulings restated

- User ruling 3: the formula arm is exposed in OWUI; the target is parsed from the USER's request
  sentence, never supplied by the model. No model-authored byte may reach the target.
- Grammar ruling (user, this unit): `expr-0.1` syntax + `sin cos tan exp log sqrt` + `pi e`, versioned
  `pyexpr-0.1`; numeric literals go through binary64 so they MATCH the projection's `Num`; parser
  stdlib-only + embeddable, building `verifier.pysrc.spec.Expr`. `src/verifier/expr.py` (msgspec) is
  NOT ported (M13.5 ruling).
- Carrier ruling (user, this unit): exactly one `y = <expr>` | `f(x) = <expr>`; exactly one interval
  `x ∈ [a, b]` | `x in [a, b]` | `from a to b` | `aからbまで`; optional `n = <count>`; NFKC first;
  zero or several carriers ⇒ no target ⇒ the figure fails.
- Rulings 5 + 6: nothing here moves the pass/fail boundary out of the verifier; the grammar decides
  the TARGET, the core decides the verdict. Admission vocabulary stays out of every model-facing byte.
- T2-1 (M10.0): only `target_mismatch` continues the attachment scan.
- Layering change: the request grammar lives IN the core package so it inherits the 100% branch gate
  + mutation credit; `FormulaTarget`'s "the demo supplies this for no one" docstring is superseded.

## Predicates — request grammar (R), `src/verifier/pysrc/request.py`

| id | predicate | acceptance check |
|---|---|---|
| R1 | `REQUEST_GRAMMAR = "pyexpr-0.1"`; `formula_target(text: str, limits: PysrcLimits = DEFAULT_LIMITS) -> FormulaTarget \| None`. TOTAL: never raises for any `str`. | Hypothesis over `st.text()` + the adversarial bank: no exception, result `None` or `FormulaTarget`. |
| R2 | `unicodedata.normalize("NFKC", text)` first; every later rule reads the normalized text. Normalized UTF-8 length > `limits.max_source_bytes` → `None`. | `ｙ＝ｓｉｎ（ｘ），ｘ ｉｎ ［０，１］` binds like its ASCII twin; a 20,001-byte message → `None`. |
| R3 | Expression grammar: `sum := product (('+'\|'-') product)*` · `product := unary (('*'\|'/') unary)*` (both left-assoc → `Bin`) · `unary := '+' unary \| '-' unary \| power` (`+` dropped, `-` → `Neg`) · `power := primary ['**' exponent]`, `exponent := ['+'\|'-'] INT` (`-` → `Neg(Num)`, no chaining) · `primary := NUMBER \| 'x' \| CONST \| FN '(' sum ')' \| '(' sum ')'`; FN = `sin cos tan exp log sqrt abs` → `Fn`; CONST = `pi e` → `Const`; `x` → `Var()`. NUMBER = `[0-9]+(\.[0-9]+)?([eE][+-]?[0-9]+)?` (ASCII): no `.`/exponent → `Num(Fraction(int(tok)))`, else `Num(Fraction(float(tok)))`, non-finite → invalid. Tokens are ASCII; spaces/tabs between tokens ignored. | Hand-stated trees: `-x**2` = `Neg(Bin(pow, Var, 2))`; `x**-2` = `Bin(pow, Var, Neg(Num 2))`; `2*x*x` left-assoc; `0.1` = `Fraction(0.1)`; `2pi`, `x^2`, `2**x`, `x**2**2`, `sin x`, `1e400` → invalid. |
| R4 | SAME TEXT ⇒ SAME TREE: for every grammar expression `E` whose translated program projects, `formula_target(f"y = {E}, x in [0, 1]").y` equals the `y` the projection gives `E` written as a program (`sin(`→`np.sin(`…, `abs(`→`np.abs(`, `pi`→`np.pi`, `e`→`np.e`); bounds likewise equal the projected `np.linspace(A, B, n)` start/stop. | Hypothesis property over drawn `E`, `A`, `B`. |
| R5 | Carriers (keywords case-sensitive except `from`/`to`/`in`, which are ASCII case-insensitive; every keyword not preceded by `[A-Za-z0-9_]`): FORMULA = every `y` or `f(x)` followed by `[ \t]*=`, each needing a valid expression (x allowed) ending on a prose boundary; INTERVAL = every `x[ \t]*(∈\|in)[ \t]*\[` (each must complete as `A[ \t]*,[ \t]*B[ \t]*\]`), plus every COMPLETE `from A to B` (B ending on a prose boundary) and every COMPLETE `A[ \t]*から[ \t]*B[ \t]*まで` (A preceded by a start boundary); COUNT = every `n[ \t]*=[ \t]*INT` ending on a prose boundary. Bounds A, B = grammar expressions WITHOUT `x`. | Per-form witnesses EN + JA; `data from the file` and `ファイルから` alone are not interval carriers. |
| R6 | Expression span = the MAXIMAL run of grammar tokens (per context: formula admits `x`, bounds do not) separated only by `[ \t]`; an identifier outside the context's set ends the run. Prose boundary after a run = end of text \| `[ \t\r\n]` \| a Japanese-class char (U+3000–U+30FF, U+4E00–U+9FFF) \| one of `, ; : . ?` itself followed by end \| whitespace \| Japanese-class. Start boundary (から form) = start of text \| whitespace \| Japanese-class \| one of `, ; : =`. | `y = x^2 …`, `y = x!`, `y = (x)`, `y = x,x in [0,1]`, `2^3から4まで` → no target; `y = sin(x)を0から2*piまで描いて` binds. |
| R7 | Exactly one FORMULA, exactly one INTERVAL, at most one COUNT, spans pairwise disjoint; a malformed formula/count/bracket carrier counts as a carrier. Result = `FormulaTarget(y, Grid(A, B, n))` with a COUNT, else `FormulaTarget(y, Interval(A, B))`. | Two identical formula carriers → `None`; formula + no interval → `None`; `from` + bracket both present → `None`; overlap (`y = 0から1まで`) → `None`. |
| R8 | Bounded: nodes ≤ `limits.max_expr_nodes`, nesting (parens + calls + unary) ≤ `limits.max_bracket_depth`, else that carrier is invalid; extraction is linear in the text length. | Over-limit witnesses → `None`; the worst adversarial 20,000-byte message completes < 2 s on the host. |

## Amendments

- **A1 (lead ruling on a test-m10u4-1 reading, R6).** The R6 witness `y = (x)` returns `None` because
  the text carries no interval carrier (R7), not because of any span rule: R3 admits `'(' sum ')'`,
  so `y = (x), x in [0, 1]` binds `y = Var()`. `y = x,x in [0,1]` stays `None` for the reason R6
  states: the comma after the run is followed by `x`, which is not a prose boundary, so the formula
  carrier is malformed and still counts (R7).
- **A2 (lead ruling on a reading raised by test-m10u4-1 AND prod-m10u4-1, R2 against R6).** R2's
  positive witness `ｙ＝ｓｉｎ（ｘ），ｘ ｉｎ ［０，１］` folds under NFKC to `y=sin(x),x in [0,1]`, which
  R6 returns `None` for — the same comma-then-`x` shape as R6's own witness `y = x,x in [0,1]`. R6
  wins and R2's witness is re-spelled with an ideographic space (U+3000) after each full-width comma
  and around `ｉｎ`: `ｙ＝ｓｉｎ（ｘ），　ｘ　ｉｎ　［０，　１］` folds to `y=sin(x), x in [0, 1]` and binds
  `y = Fn(sin, Var)` over `Interval(Num 0, Num 1)`, exactly like that ASCII twin. The unspaced
  full-width form stays `None`, like its ASCII twin, so NFKC-first holds in both directions. R6's
  rule itself stands for a reason: a comma that is not followed by a prose boundary may be a
  decimal comma, and `y = x*2,5` must never bind `y = x*2`.
- **A3 (lead ruling on a test-m10u4-1 reading, C7).** C7's acceptance check names
  `get_args(RefusalCode.__value__)`, which exists only for a PEP 695 `type` alias; `RefusalCode` is a
  plain `Literal[...]` assignment (`src/verifier/pysrc/errors.py`), so both the runtime and mypy
  reject `__value__`. The check reads `len(get_args(RefusalCode)) == 52`, the form the shipped suites
  already use; the refusal set itself is unchanged.
- **A4 (lead ruling on a prod-m10u4-1 finding, P12 of the projection suite).**
  `tests/test_pysrc_project.py::test_p12_projection_is_pure` hand-states the import roots the
  pasted core may carry, each answering to a predicate. `request.py` adds ONE: `unicodedata`, which
  answers to R2 (NFKC first, the user's carrier ruling). `itertools` answers to no predicate and is
  not admitted: production drops it. The P12 set widens by `unicodedata` alone, its comment naming
  R2; the widening is test-m10u4-1's edit, and prod's P12 red on its branch is the firing record.
