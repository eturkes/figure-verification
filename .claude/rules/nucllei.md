# nucllei (llens) — the skill target's integration facts (Q82)

Source of truth for nucllei behaviour = its tag `v20261020-01` (`34eb9973c`) `README_API.md` §5–§7 + code; llens = `e6a1b6f`. Contract + rulings + verdicts = `.agent/archive/contracts/q82.md`.

- Shape (rulings 1, 10): skill `figure-verification` (`llens/nucllei/skills/figure-verification.md`, from `nucllei_skill/skill.py`) mounts tool `figure_verification` (`llens/nucllei/tools/figure_verification.py`, root `nucllei_skill.tool`) through frontmatter `tool_ids`; the tool never sits in a preset's `meta.toolIds`. Skill-loaded tools load with `enforce_access_control=False` ⇒ the SKILL's visibility is the authorization unit. Activation = preset `meta.skillIds` ∧ `features.skills` ∧ the caller reads the skill; `load_skill` runs first in a batch, so a same-response `draw_figure` works. Auto-load prefixes `text/csv` + `application/vnd.ms-excel` (Chromium on Windows with Excel names a `.csv` upload that; the stored content type = the browser's multipart header).
- llens `scripts/nucllei/sync.py` = the deployment path: tool id = file stem, name/description = the first docstring's `title:`/`description:` lines (`parse_frontmatter`: ANY docstring line opening `word:` becomes a key ⇒ the nucllei preamble holds no other such line); skill = one-line frontmatter (`parse_md_frontmatter`), body stripped. nucllei rewrites `from utils|apps|main|config` in stored tool content on every load (nucllei `utils/plugin.py` `replace_imports`) ⇒ the bundle's refusal applies here too.
- Model-facing surfaces (Japanese, ruling 7): the skill body, the `draw_figure` docstring, the result's fact + `次の手:` tail (`nucllei_skill/texts.py`). nucllei prepends a `Tools` CLASS docstring to the first function's spec ⇒ `Tools` has none; the description is cut at the first `:param`/`:return`; each `:param` = one line. `spec_overrides` patches deep-merge, a `description` key REPLACES ⇒ base description + this turn's files. Function names share one namespace per turn.
- No outlet hook, no Pyodide: `draw_figure` = one `POST /files/write` per owned attachment (`run.py::write_payload`: `{user_id, path: imports/<name>, b64, nofollow: true}`, 120 s each, nucllei's own import wait) then one stateless `POST /exec` (`{user_id, lang, code, timeout_s: 120}`, HTTP 150 s), each through `nucllei.builtin_tools.sandbox.sandbox_post` (the one exit carrying `SANDBOX_TOKEN`; `SANDBOX_URL` env-only), all inside nucllei's 300 s `TOOL_EXEC_TIMEOUT_S` (its cancellation propagates). An `/exec` body never carries `imports` (M23.1 F1): the sandbox writes those with a plain `write_bytes` + `chown` that follow links, while `nofollow` takes its descriptor-based write (every segment `O_NOFOLLOW`, a link leaf refused), and the user's own runs can plant links in the persistent workspace; nucllei's own tools send no `imports` either. The jail: code written to `/workspace/.exec/<id>.py`, `/opt/venv/bin/python -u`, env `MPLBACKEND=Agg` `MPLCONFIGDIR=/tmp/mpl` `MATPLOTLIBRC` (sans-serif Noto Sans CJK JP first), no network, imports at `/workspace/imports/<basename>` (persistent workspace: never trusted as data), stdout cap 512 KiB default (`SANDBOX_STREAM_LIMIT_BYTES`, configurable ⇒ `reply.py::MAX_REPLY` stays the bound). `reader.py::_prepare` resets rc to matplotlib's internal defaults ⇒ `run.py` hands the reader the first non-DejaVu matplotlibrc sans-serif font file (Latin DejaVu, Japanese by fallback, as on Open WebUI; mathtext CJK still blocks).
- User data (consultant-1 T7, T8): request text + attachments = the HUMAN user messages (role `user`, no `meta.system_notice`) of the caller's stored branch through the pending assistant message (`Chats.get_chat_by_id_and_user_id` + `get_message_list`); the request body only for an unstored (headless) chat. Files owner-checked (`Files.get_file_by_id` + `user_id`), read ≤ `max_csv_bytes + 1`, last file of a name wins. A delegated session (`metadata.agent_session`) refuses.
- Publication: the PNG → `Storage.upload_file` + `Files.insert_new_file` (a `None` record = a fault); everything built first, then ONE `__display__` push (markdown, outside the collapsed block, never sent to the model, appended per push); a refused or missing push ⇒ `publish_failed` with no second push.
