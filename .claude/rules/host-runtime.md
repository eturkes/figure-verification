# Model-tier runtime

- Two tiers, incompatible hosts. ORIGIN (source of all M3–M8 proposer evidence): Debian container on an ostree host, Intel NPU + iGPU, OpenVINO GenAI. CURRENT = the Pascal dGPU tier: NVIDIA MX150 (cc 6.1, ~1.95 GiB usable; device record `model_backend/runtime/README.md` § Measured facts). `.venv-model` = uv py3.15, torch 2.14.1+cu126 + accelerate 1.15.0 + transformers 5.20.2 + tokenizers 0.23.3 (`model_backend/runtime/` lock + snapshot: the served app alone, no dependency group). The host that carries the device (OS, CPU, driver, its GPU + CPU-pool wrappers, its throughput + thermal observations) = gitignored `CLAUDE.local.md`, per machine.
- Runtime GO on CURRENT = FUNCTIONAL (user, upgrade request: tracking upstream outranks speed, a throughput regression is accepted): the GPU + deterministic greedy replies + the tool working end to end. Current = **torch 2.14.1+cu126 + transformers 5.20.2 on CPython 3.15, fp16**: the wheel ships `sm_60` code (Pascal sm_61 runs it), CUDA 12.6; `.agent/measurements/q46_mx150.sh` on the device: the short reply 3/3 `bdee2c42…` (= every earlier stack), the chart prompt 3/3 `e577107d…` (423 tokens; the transformers 5.16.1 stacks wrote `e440fe57…`, 420: 5.18 drops the all-ones mask, 5.19 does Qwen2 RoPE by multiply). Batch-1 decode is CPU-bound ⇒ a token rate depends on the host's CPU load + scheduling class: each rate states both, and GPU work runs at normal class on an idle CPU. Pascal pins: CUDA 13 REMOVED sm_61 and torch ≥2.11+cu128 dropped Pascal; `nvidia-cuda-nvcc-cu12` wheels ship no `nvcc`; upstream llama.cpp Linux CUDA prebuilts do not exist; llama.cpp native CUDA sm_61 works at 3–6 tok/s (disqualified backup). VRAM envelope at ~1.95 GiB: Qwen2-0.5B fp16 = 1134 MiB at the real prompt, 1356 MiB at the 1536-token cap; ~1.5B Q4_K_M is the conservative 4-bit ceiling. Quantization on this stack: NF4 (0.59 tok/s) + LLM.int8 (3.34 tok/s, outside its cc 7.5+ support) both load but run SLOWER than fp16 (5.97 tok/s); GPTQModel/AutoAWQ/torchao fail by import or precondition ⇒ fp16 = the primary path, ~0.9B params the ceiling; Qwen3-0.6B leaves 14.8 MiB margin (unsafe).
- ORIGIN-tuple evidence (M3/M4/M6/M7/M8 live-stack gates) cannot be re-taken on CURRENT; those reviewed verdicts stand on ORIGIN evidence, and every proposer number on CURRENT is a NEW `(device, config)` observation, never a substitute reading. Milestone consequences → the archived roadmap (`.agent/archive/`) § Host change.
- **The BROWSER tier runs on any host.** `.venv-webui` (uv-managed CPython 3.11 + `open-webui==0.12.3` from `webui/runtime/uv.lock`, gitignored) + `webui/launch.sh --stub` bring up stub :8001 + OWUI :8080 with the demo paste-in pair; bare `webui/launch.sh` preflights torch-CUDA through `MODEL_BACKEND_PYTHON` and runs the real dGPU backend as `"$MODEL_BACKEND_PYTHON" -m model_backend`. `--fresh` wipes `.webui-data`; a backgrounded launcher stops on SIGTERM to `.launch-logs/launch.pid`, never SIGINT. Real-arm cold standup measures under 60 s to READY.
- **Request origin (M23.1 F2 + F4).** No model-tier server authenticates its caller (model backend, stub `webui/model_stub.py`, codex bridge) ⇒ each binds loopback alone (`origin.py::loopback`, also the launcher's published-password rule), answers only the `Host` headers `origin.py::hosts` derives from its bind (its name + `127.0.0.1`/`localhost`/`[::1]`, with the port: Litestar's `allowed_hosts` matches the whole header, else 400; a DNS-rebound page names its own domain) and takes a POST body only as `application/json` (`origin.py::json_only`, a `before_request` hook = 415 before the body is read: a cross-site `text/plain` post needs no CORS preflight; Open WebUI 0.12.3 + nucllei send JSON). The backend derives its hosts from `Settings.host` + `port`, the stub + bridge from `model_backend_url`; a test client sets `base_url` to a loopback URL (Litestar's default `testserver.local` gets 400).
- **Browser automation + remote browsing = `.claude/rules/owui.md`** (direct CDP over a scratch profile, never the user's signed-in browser profile; the inline-PNG probe; 8080 alone forwarded, never 8001).
- **Port seam is small + isolated**: `app.py` touches only `Engine.load` / `engine.generate(messages, *, temperature, max_tokens)` / `BackendError`, and `tests/test_model_backend.py` injects a FAKE native module ⇒ the suite is hardware-free and a second engine gates without a GPU. `engine.py` writes NO `import torch` (tensors handled via `.shape`, slicing, `int()`); it imports `transformers` alone.
- **Any replacement engine must reproduce two contracts byte-exactly**: (1) refusal envelope = backend `400` + media essence exactly `application/json` + canonical bytes `{"error":{"message":…,"type":"prompt_too_long"}}` (pinned in `tests/test_model_backend.py`); (2) exact-admitted-token handoff = preflight the tokenized buffer, refuse over-cap BEFORE generation, generate from THAT buffer. A llama-server `/v1/chat/completions` owns templating + exposes no pre-tokenized handoff ⇒ only in-process runtimes hold (2).
- Model IDENTITY is duplicated beyond `model_backend/`: `webui/settings.py` + `webui/README.md`, pinned in `tests/test_webui_settings.py` + `tests/test_model_backend_runtime.py` ⇒ changing the served model touches those files with the backend package.
- The demo proposer is deliberately small; its live arms are observations, never the verifier's acceptance (the committed rule corpus is). A misleading-arm prompt the model ignores draws an honest chart, which passes — the live acceptance counts only runs whose figure carries the requested distortion.
