# Host machines + model-tier runtime

- TWO hosts, incompatible model tiers. ORIGIN (source of all M3–M8 proposer evidence): Debian container on an ostree host, Intel NPU + iGPU, OpenVINO GenAI. CURRENT: CachyOS/Arch, i7-8650U Kaby Lake-R = **NO NPU** (no `/dev/accel*`, no `ivpu`; `/sys/class/accel` EXISTS but is EMPTY ⇒ the class dir is not evidence of a device), Intel UHD 620, NVIDIA MX150 (Pascal cc 6.1, ~1.95 GiB usable), driver 580.178.04 (res-port probe logs recorded 580.173.02 — scope their measurements to that tuple), 62 GiB RAM. `.venv-model` on CURRENT = uv py3.15, torch 2.14.1+cu126 + accelerate 1.15.0 + transformers 5.20.2 + tokenizers 0.23.3 (`model_backend/runtime/` lock + snapshot: the served app alone, no dependency group).
- Runtime GO on CURRENT = FUNCTIONAL (user, session 12: tracking upstream outranks speed, a throughput regression is accepted): the GPU + deterministic greedy replies + the tool working end to end. Current = **torch 2.14.1+cu126 + transformers 5.20.2 on CPython 3.15, fp16**: the wheel ships `sm_60` code (Pascal sm_61 runs it), CUDA 12.6, 2048³ matmul ≈ 1.0 TFLOP/s; `.agent/measurements/q46_mx150.sh` under `gpu-run`: the short reply 3/3 `bdee2c42…` (= every earlier stack), the chart prompt 3/3 `e577107d…` (423 tokens; the transformers 5.16.1 stacks wrote `e440fe57…`, 420: 5.18 drops the all-ones mask, 5.19 does Qwen2 RoPE by multiply), 42.0–42.3 s each (≈ 10 tok/s, no in-run decay), smoke 20.5–20.7 tok/s at 66 °C / 1657 MHz, host load ≈ 3. Earlier tuples, each its own observation: torch 2.13.0 + transformers 5.16.1 cool-start smoke 25.86–26.30 tok/s, chart 25.8 → 18.5 (Q46); torch 2.14.0 decayed 12.252 → 4.019 → 2.408 within one run. Batch-1 decode is CPU-bound: beside a 7-process z3 run (load 15) the 2.13.0 chart reply ran 7.3 tok/s at 20–37 % GPU busy under the agent's SCHED_IDLE, 11.4–12.1 at normal class ⇒ GPU work runs under `gpu-run`; sustained GPU-bound load holds the 70 °C target by SW thermal slowdown (SM 1657 → 847/556 MHz). Disqualified backups: llama.cpp native CUDA sm_61 works at 3–6 tok/s; OpenVINO `GPU` resolves to NVIDIA via NVIDIA OpenCL, NO-GO on speed; llama.cpp Vulkan cannot get `vkCreateInstance` from the NVIDIA GLX loader. Pascal pins: CUDA 13 REMOVED sm_61 and torch ≥2.11+cu128 dropped Pascal; `nvidia-cuda-nvcc-cu12` wheels ship no `nvcc`; upstream llama.cpp Linux CUDA prebuilts do not exist. Intel UHD 620 is unreachable by OpenVINO here even with the compute runtime installed. VRAM envelope at ~1.95 GiB: Qwen2-0.5B fp16 = 1134 MiB at the real prompt, 1356 MiB at the 1536-token cap; ~1.5B Q4_K_M is the conservative 4-bit ceiling. Quantization on this stack: NF4 (0.59 tok/s) + LLM.int8 (3.34 tok/s, outside its cc 7.5+ support) both load but run SLOWER than fp16 (5.97 tok/s); GPTQModel/AutoAWQ/torchao fail by import or precondition ⇒ fp16 = the primary path, ~0.9B params the ceiling; Qwen3-0.6B leaves 14.8 MiB margin (unsafe).

- **Browser automation + remote browsing = `.claude/rules/owui.md`** (direct CDP over a scratch profile, never the user's signed-in browser profile; the inline-PNG probe; 8080 alone forwarded, never 8001).
- **Port seam is small + isolated**: `app.py` touches only `Engine.load` / `engine.generate(messages, *, temperature, max_tokens)` / `BackendError`, and `tests/test_model_backend.py` injects a FAKE native module ⇒ the suite is hardware-free and a second engine gates without a GPU. `engine.py` writes NO `import torch` (tensors handled via `.shape`, slicing, `int()`); it imports `transformers` alone.
- **Any replacement engine must reproduce two contracts byte-exactly**: (1) refusal envelope = backend `400` + media essence exactly `application/json` + canonical bytes `{"error":{"message":…,"type":"prompt_too_long"}}` (pinned in `tests/test_model_backend.py`); (2) exact-admitted-token handoff = preflight the tokenized buffer, refuse over-cap BEFORE generation, generate from THAT buffer. A llama-server `/v1/chat/completions` owns templating + exposes no pre-tokenized handoff ⇒ only in-process runtimes hold (2).
- Model IDENTITY is duplicated beyond `model_backend/`: `webui/settings.py` + `webui/README.md`, pinned in `tests/test_webui_settings.py` + `tests/test_model_backend_runtime.py` ⇒ changing the served model touches those files with the backend package.
- The demo proposer is deliberately small; its live arms are observations, never the verifier's acceptance (the committed rule corpus is).
