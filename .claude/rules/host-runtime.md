# Host machines + model-tier runtime

- TWO hosts, incompatible model tiers. ORIGIN (source of all M3–M8 proposer evidence): Debian container on an ostree host, Intel NPU + iGPU, OpenVINO GenAI. CURRENT: CachyOS/Arch, i7-8650U Kaby Lake-R = **NO NPU** (no `/dev/accel*`, no `ivpu`; `/sys/class/accel` EXISTS but is EMPTY ⇒ the class dir is not evidence of a device), Intel UHD 620, NVIDIA MX150 (Pascal cc 6.1, ~1.95 GiB usable), driver 580.178.04 (res-port probe logs recorded 580.173.02 — scope their measurements to that tuple), 62 GiB RAM. `.venv-model` on CURRENT = uv py3.12, torch 2.13.0+cu126 + accelerate 1.15.0 + transformers 5.16.1 (`model_backend/runtime/` lock + snapshot; the lock still carries xgrammar + a jsonschema dev pin until the queue's dependency-pruning row).
- Measured runtime verdict on CURRENT: **torch 2.13.0+cu126 + transformers (fp16) = the sole GO** — GPU, 3/3 byte-identical greedy with O1/O5 SHA-256 `15a3c50b…`/`cd6f7774…` equal to 2.7.1's, HTTP smoke 24.397 tok/s warm at 52–53 °C / 1480–1683 MHz. torch 2.14.0+cu126 = NO-GO: weighted 4.023 tok/s, decaying 12.252 → 4.019 → 2.408 within one run, against 2.7.1's 23.827 hot. Disqualified backups: llama.cpp native CUDA sm_61 works at 3–6 tok/s; OpenVINO `GPU` resolves to NVIDIA via NVIDIA OpenCL, NO-GO on speed; llama.cpp Vulkan cannot get `vkCreateInstance` from the NVIDIA GLX loader. Pascal pins: CUDA 13 REMOVED sm_61 and torch ≥2.11+cu128 dropped Pascal; `nvidia-cuda-nvcc-cu12` wheels ship no `nvcc`; upstream llama.cpp Linux CUDA prebuilts do not exist. Intel UHD 620 is unreachable by OpenVINO here even with the compute runtime installed. VRAM envelope at ~1.95 GiB: Qwen2-0.5B fp16 = 1134 MiB at the real prompt, 1356 MiB at the 1536-token cap; ~1.5B Q4_K_M is the conservative 4-bit ceiling. Quantization on this stack: NF4 (0.59 tok/s) + LLM.int8 (3.34 tok/s, outside its cc 7.5+ support) both load but run SLOWER than fp16 (5.97 tok/s); GPTQModel/AutoAWQ/torchao fail by import or precondition ⇒ fp16 = the primary path, ~0.9B params the ceiling; Qwen3-0.6B leaves 14.8 MiB margin (unsafe).
- ORIGIN-tuple evidence (M3/M4/M6/M7/M8 live-stack gates) cannot be re-taken on CURRENT; those reviewed verdicts stand on ORIGIN evidence, and every proposer number on CURRENT is a NEW `(device, config)` observation, never a substitute reading. Milestone consequences → the archived roadmap (`.agent/archive/`) § Host change.
- **The BROWSER tier runs fully on CURRENT.** `.venv-webui` (uv-managed CPython 3.12 + `open-webui==0.10.2`, gitignored) + `webui/launch.sh --stub` bring up stub :8001 + OWUI :8080 with the demo paste-in pair; bare `webui/launch.sh` preflights torch-CUDA through `MODEL_BACKEND_PYTHON` and runs the real dGPU backend as `"$MODEL_BACKEND_PYTHON" -m model_backend`. `--fresh` wipes `.webui-data`; a backgrounded launcher stops on SIGTERM to `.launch-logs/launch.pid`, never SIGINT. Real-arm cold standup measures under 60 s to READY.
- **Browser automation + remote browsing = `.claude/rules/owui.md`** (direct CDP over a scratch profile, never the signed-in agent browser; the inline-PNG probe; 8080 alone forwarded, never 8001).
- **Port seam is small + isolated**: `app.py` touches only `Engine.load` / `engine.generate(messages, *, temperature, max_tokens)` / `BackendError`, and `tests/test_model_backend.py` injects a FAKE native module ⇒ the suite is hardware-free and a second engine gates without a GPU. `engine.py` writes NO `import torch` (tensors handled via `.shape`, slicing, `int()`); it imports `transformers` alone.
- **Any replacement engine must reproduce two contracts byte-exactly**: (1) refusal envelope = backend `400` + media essence exactly `application/json` + canonical bytes `{"error":{"message":…,"type":"prompt_too_long"}}` (pinned in `tests/test_model_backend.py`); (2) exact-admitted-token handoff = preflight the tokenized buffer, refuse over-cap BEFORE generation, generate from THAT buffer. A llama-server `/v1/chat/completions` owns templating + exposes no pre-tokenized handoff ⇒ only in-process runtimes hold (2).
- Model IDENTITY is duplicated beyond `model_backend/`: `webui/settings.py` + `webui/README.md`, pinned in `tests/test_webui_settings.py` + `tests/test_model_backend_runtime.py` ⇒ changing the served model touches those files with the backend package.
- The demo proposer is deliberately small; its live arms are observations, never the verifier's acceptance (the committed rule corpus is). A misleading-arm prompt the model ignores draws an honest chart, which passes — the live acceptance counts only runs whose figure carries the requested distortion.
