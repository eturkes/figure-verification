# Claim scope — what the project may say (a loose restatement is a regression)

- Verified = the drawn figure obeys every integrity check (`docs/verification.md`, law `.claude/rules/figure.md`) AND, where data was supplied, every drawn value is that data: an attached CSV's raw values or one group-and-reduce of them, or the numbers typed in the request (ranges expanded), or one admitted computation of these (Q45: square, running total, change, share, percent of one series; ratio, difference, product, sum of two columns per row or per group sum), matched exactly per evaluation variant. A computed reading is existential: the values ARE that computation of the data, never a claim the program computed it. Nothing stronger: never "the chart is correct", "the chart answers the question" or "every misleading chart blocks".
- Trusted, NOT verified: the renderer, browser, pixels, the code sandbox + its packages (Open WebUI: the Pyodide sandbox + its bundled matplotlib, pandas, numpy; nucllei: the nsjail sandbox + its unpinned plotting packages + its Noto Sans CJK JP font), the interpreter, the Japanese font the filter finds on the Open WebUI server + the wrapper registers. The program is assumed NON-ADVERSARIAL: it runs before any check, in the interpreter the reader shares, and can reach the browser's network (the stock Open WebUI code-interpreter posture) ⇒ a stated limit wherever verification is described, never a guarantee.
- Fidelity to INTENT (the right quantity for the question) is never claimed beyond column anchoring: a CSV figure must draw columns the request names (production strict, demo substitution). On-chart text (annotations, value labels, free text) is LISTED, never judged. The model's note (Q78) = the MODEL's statement of what the chart rules overrode, shown under a passing verdict alone: never phrased as the verifier's finding, and its presence never claimed (a model can leave a conflict unstated). No data source ⇒ integrity alone, and the reply says so.
- Model guidance (filter inlet template, `draw_figure` description) MAY state the rules; it never moves the boundary — the verifier alone decides. Nothing from this repo enters the production system prompt.
- nucllei scope (Q82): the verifier decides the figures `draw_figure` shows (its display outside the collapsed tool block); the model's own reply text and charts other tools show (`run_python` + `fetch_from_workspace`) are outside it — a stated limit, never a guarantee.
- Corpus claims are scoped: the rule corpus's both-ways 100% = the committed cases on host matplotlib 3.10.8 + measurement C1 (the same cases through the production wrapper in the installed Open WebUI 0.12.3 bundle, Pyodide 314.0.3, matplotlib 3.10.8); on nucllei, measurement NS (the same cases through the nucllei tool's wrapper in a local build of the sandbox tag `v20261020-01`: CPython 3.12.15, matplotlib 3.11.2, pandas 2.3.3; one expected difference, `missing-glyph` → pass by the jail's Japanese font). A live arm = an observation on one `(device, config)` with its run count + host tuple; a misleading-arm run whose figure lacks the requested distortion counts as such, never as a block.
- Human-facing text at a demo boundary inherits claim discipline: stub outcomes stated flatly, real-model arms conditional (`Expect …`) until measured; an STE rewrite must not upgrade a hedge into an assertion — re-check every rewritten behavioural sentence against this file.
