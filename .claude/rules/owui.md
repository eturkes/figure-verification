# Open WebUI 0.10.2 — sandbox + integration facts (binds M10 + M14)

- Sandbox mechanism (source-confirmed): a trusted async OUTLET Function filter reads the verifier tool-result from backend-owned state → verifies the result is authentic → calls the `execute:python` RPC DIRECTLY (bypassing `sanitize_code`) → Pyodide (sandbox iframe `allow-scripts`, no `allow-same-origin`) runs it; the worker sets `MPLBACKEND=AGG`, rewrites `plt.show()` to `savefig(BytesIO, format="png")` and prints a base64 PNG data URI → the filter emits an inline message file; else it falls through to the block notice. Keep `ENABLE_CODE_INTERPRETER` + `ENABLE_CODE_EXECUTION` OFF (the internal RPC is not gated by them), `ENABLE_PYODIDE_FILE_PERSISTENCE` off, `ENABLE_WEBSOCKET_SUPPORT` on, `WEBSOCKET_EVENT_CALLER_TIMEOUT` bounded.
- Pyodide `0.28.0.dev0` (CPython 3.13.2, wasm32) bundles `matplotlib 3.8.4`, `pandas 2.3.1`, `numpy 2.2.5` — nothing else (sklearn/scipy/seaborn absent). Chat file metadata is forwarded, the browser fetches each file by id, the sandbox writes exact bytes to `/mnt/uploads/<filename>` ⇒ admitted code MAY `pd.read_csv('/mnt/uploads/<verified-name>.csv')` and model-authored numbers never enter the executed bytes. The custom `execute:python` RPC must carry the `files` payload; a code-only RPC has no CSV.
- `execute:python` needs a LIVE browser socket: the headless harness (`webui/client.py`, random session_id) returns "Client session disconnected" ⇒ sandbox render = a browser step; headless tests cover gate logic / provenance / rewrite only.
- Current surface, all pre-python-mode: `webui/settings.py` `function_name_filter_list=[proposeSpec]` exposes ONE operation; `webui/model_stub.py` classifies only the dataset system prompt marker; `enforcement_filter.py` treats matplotlib as an UNVERIFIED signal and blocks it (the user-reported bug) — rework = verify authentic result → execute admitted script → publish PNG + `Figure verification passed`, else block + `Figure verification failed, no image produced`. Provisioned filter/tool sources are import-executed by OWUI in its own environment ⇒ stdlib-only, no repo imports, no `requirements:` frontmatter.
- OWUI output-item reads are positional + type-blind (`client.py` `output[0].content[0].text`; `enforcement_filter.py` concatenates every text) — a reasoning-capable backend breaks both (p15). Provisioning + filter contracts settled against 0.10.2 → `.agent/archive/m4.md`.
- Browser automation = direct CDP, never BrowserOS MCP (refless snapshot on the SPA, swallowed `run` values). Recipe (`.scratch/cdp.py` regenerates): `$(chromiumfish path) --remote-debugging-port=9333 --user-data-dir=<scratch>`, `webSocketDebuggerUrl` from `/json/list` (sole `type=="page"`), drive with `websocket-client` from `.venv-webui/bin/python`. Login: `DOM.querySelector`+`DOM.focus` on `#email`/`#password`, `Input.insertText`, `Input.dispatchKeyEvent` Enter. Composer `#chat-input` (TipTap): `Input.insertText` works, Enter does NOT send — `Input.dispatchMouseEvent` press/release at the centre of `#send-message-button`. Pass/fail probe = `document.querySelectorAll('iframe')` (src = absolute `http://127.0.0.1:8000/chart/<plot_id>`; empty = blocked).
- Remote browsing forwards BOTH 8080 and 8000 (charts ride an absolute :8000 embed); never forward 8001; prefer an SSH tunnel — the launcher's admin password is fixed + printed. `webui/launch.sh`: `--stub` = deterministic hardware-free arm; `--fresh` wipes `.webui-data`; a backgrounded launcher stops on SIGTERM to `.launch-logs/launch.pid`; bare launch preflights torch-CUDA via `MODEL_BACKEND_PYTHON` and runs `"$MODEL_BACKEND_PYTHON" -m model_backend`; real-arm cold standup < 60 s. Launcher suite = `tests/test_webui_launch.py` (L1–L9, strict PATH fakes rc 64 on unknown argv, real loopback listeners + real `setsid`; ZERO `shellcheck disable=` directives).
