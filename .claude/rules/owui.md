# Open WebUI 0.10.2 — sandbox + integration facts (binds M10 + M14)

- Sandbox mechanism (shipped = `webui/paste_in/filter.py`; measured on 0.10.2): the tool + the outlet of ONE completion share one `__request__` under native AND legacy function calling, ONE outlet call per completion ⇒ `draw_figure` writes a tagged RECEIPT to `__request__.state` (program + owned file ids + request text; never a verdict or bytes; `webui/paste_in/receipt.py`; the LAST call decides) → the global active OUTLET filter reads that receipt ALONE, refetches the files under `__user__`'s id + re-derives the verdict through the tool's own `first_verdict` → `Verified` ⇒ `execute:python` RPC DIRECTLY (bypassing `sanitize_code`), `data = {id, code, session_id, files: [{id, filename}]}` → `{stdout, stderr, result}`, CSV at `/mnt/uploads/<filename>` byte-identical → Pyodide (sandbox iframe `allow-scripts`, no `allow-same-origin`) → `stdout` = exactly two lines, the tagged observation line then one PNG data-URI line, the observation matching the recomputed table (`webui/paste_in/observe.py`, `.agent/archive/contracts/m10u2.md`) + empty `stderr` (the handler `Ue` starts `stdout`/`stderr`/`result` at `null` + overwrites each only with a TRUTHY worker value ⇒ a clean run replies `stderr: null`, never `""`; EMPTY = key present with `null` or `""`, A6) ⇒ ONE `files` event + `Figure verification passed` + the certificate interpretation; every other outcome ⇒ `Figure verification failed, no image produced` (F2-F6, `.agent/archive/contracts/m10u1.md`). OWUI's own `patchMatplotlib` fires on the substring `matplotlib` in the RPC source + raises `SyntaxError` before the program runs ⇒ the wrapper assembles that name at run time, carries the program base64 + installs its OWN `plt.show` (the observation line, then one PNG line, then clear; called once if the program never did). OWUI picks the sandbox packages by REGEX over the RPC source (13 `\bimport\s+<module>\b|\bfrom\s+<module>\b` entries, `frontend/_app/immutable/nodes/0.VsCm_E_x.js`) and loads only those ⇒ hiding the name hides the packages too: the wrapper loads numpy, pandas + the plotting library ITSELF (`pyodide_js.loadPackage([...])`, top-level `await`, silent `messageCallback` so no loader line reaches `stdout`) and sets `MPLBACKEND=AGG` before its first plotting import (A5). F7's harness `.agent/measurements/f7_wrapper.mjs` reads the regexes + the prelude from the installed bundle and preloads NOTHING — a preloading harness hid exactly this defect while the live PASS arm died `ModuleNotFoundError`. Rewriting `content` AND `output` persists across reload; a `files` event persists the PNG as a message attachment; `__files__`/`__metadata__['files']` are conversation-scoped, not turn-scoped. RPC wall time 9.2–12.0 s; inbound Engine.IO frame cap = 1,000,000 bytes (bounds one render's `stdout`). Keep `ENABLE_CODE_INTERPRETER` + `ENABLE_CODE_EXECUTION` OFF (the internal RPC is not gated by them), `ENABLE_PYODIDE_FILE_PERSISTENCE` off, `ENABLE_WEBSOCKET_SUPPORT` on, `WEBSOCKET_EVENT_CALLER_TIMEOUT` bounded, `BYPASS_EMBEDDING_AND_RETRIEVAL=true` (else an offline CSV upload calls a remote embedding API).
- Pyodide **`0.28.3`** (CPython 3.13, wasm32) — read the version from `open_webui/frontend/pyodide/package.json`, NEVER from `pyodide-lock.json`, whose `0.28.0.dev0` is stale build metadata. The bundle dir holds **61 entries**, including `matplotlib 3.8.4`, `pandas 2.3.1`, `numpy 2.2.5` AND `scikit_learn 1.7.0` + `scipy 1.14.1`; seaborn alone is absent. Bundled ≠ admitted: the verifier's allowlist is what bounds the executed bytes, and no `Intent` dependency claim may cite an absence the bundle contradicts. Chat file metadata is forwarded, the browser fetches each file by id, the sandbox writes exact bytes to `/mnt/uploads/<filename>` ⇒ admitted code MAY `pd.read_csv('/mnt/uploads/<verified-name>.csv')` and model-authored numbers never enter the executed bytes. The custom `execute:python` RPC must carry the `files` payload; a code-only RPC has no CSV.
- `execute:python` needs a LIVE browser socket: the headless harness (`webui/client.py`, random session_id) returns "Client session disconnected" ⇒ sandbox render = a browser step; headless tests cover gate logic / provenance / rewrite only.
- Current surface: `webui/settings.py` provisions the PASTE-IN tool (`tool_id=figure_verification`, operation `draw_figure`) as the demo's ONE model-visible callable and emits NO `TOOL_SERVER_CONNECTIONS`; bootstrap provisions the generated filter (`FILTER_ID=figure_verification_filter`) as the ONE global active function, `smoke` = eight readbacks incl. `filter_current`/`filter_global_active`/`filter_exclusive`, any drift fails closed; `webui/model_stub.py` answers OWUI's legacy SELECTOR turn only — system message holding `Available Tools:` + a user message equal to `Query: <P>` or ending `\nQuery: <P>` (`utils/middleware.py:1102-1124`): P = the simple banner prompt ⇒ a `draw_figure` call carrying sentinel-simple's committed program, P = the elaborate prompt ⇒ one carrying sentinel-complicated's committed program (refused over `data/sales.csv`, `expression_not_admitted`), every other turn — a bare prompt included — ⇒ prose (A4, `.agent/archive/contracts/m10u1.md`). Provisioned filter/tool sources are import-executed by OWUI in its own environment ⇒ stdlib + `open_webui` only, no repo imports, no `requirements:` frontmatter.
- **`function_name_filter_list` cannot narrow a tool server and must never be relied on to.** It is a case-sensitive `str.endswith` over the operation name, not equality (`utils/misc.py:35-70`), so `["python"]` also admits `evilpython`, and an EMPTY list allows ALL. A tool server is therefore removed, never filtered: the JSON-spec `proposeSpec` operation is unreachable because no `TOOL_SERVER_CONNECTIONS` entry exists at all, and `bootstrap.smoke`'s `no_tool_servers` flag re-checks that every gate run by refusing any `server:`-prefixed id in `GET /api/v1/tools/`.
- **Paste-in law (M10.0 onward).** The pasted artifact is GENERATED — `uv run --locked python tools/generate_paste_in.py`, `--check` in the gate — and a hand edit to `paste-in/*.py` is lost at the next run. Two paste targets, one per artifact, sharing one generator (`webui/paste_in/bundle.py`). What the generator refuses to embed: a source holding `'''`, ending in a backslash, holding no `"""` (`ruff format` would flip the delimiter and break `--check`), exceeding 100 columns on any line, or holding `from utils`/`from apps`/`from main`/`from config` — OWUI's `replace_imports` (`utils/plugin.py:186-200`) rewrites those four prefixes in tool content on EVERY create and update, so stored bytes would stop equalling generated ones. `extract_frontmatter` (`utils/plugin.py:150-183`) returns `{}` unless `lines[0].strip() == '"""'`; the artifact opens on its SPDX comment, so `install_frontmatter_requirements` is a no-op by construction. `load_tool_module_by_id` returns `module.Tools()` — an INSTANCE — and `get_functions_from_tool` discovers non-`_`-prefixed non-class callables on it, so a helper method needs only a leading underscore to stay invisible. Reserved `__metadata__`/`__user__` params never reach the model: pydantic's `create_model` warns-and-ignores leading-underscore field names before `get_tools()` strips `__`-prefixed properties again (`utils/tools.py:306-317`).
- **Demo transport (M10.6; lever ruling 6 + L1).** The paste-in filter's INLET renders `corpus/python/capture_prompt_v1.txt` (embedded BY GENERATION, `--check` covers it) around the LAST user message when the LAST owned attachment's header passes the core CSV reader, returning a NEW body holding a NEW message dict; `__metadata__` stays untouched, because the formula arm parses its target from `__metadata__["user_message"]["content"]`; no attachment, a refused header or non-text content ⇒ the body returns unchanged. The demo-only adapter in `model_backend/app.py` recognizes ONLY the legacy selector turn (a system message holding `Available Tools:` + ONE user message `Query: <P>` or `History:…\nQuery: <P>`), generates from the text after the LAST `Query: ` at the capture parameters (512 tokens, temperature 0.0, no schema) and answers ONE `draw_figure` call carrying `capture.harness.defence(<output>)[1]`; every other turn passes through unchanged, and the reply is never empty (an empty non-stream reply makes OWUI skip the outlet). The production proposer needs no adapter: the admin prompt tells it to deliver the program through `draw_figure` (L1, user-confirmed).
- Tool provisioning REST shapes (0.10.2): `ToolForm` = `{id, name, content, meta: ToolMeta, access_grants}`, `id` must satisfy `.isidentifier()` and is lower-cased (`routers/tools.py:360-366`). A MISSING tool is **404** where a missing FUNCTION is 401 ⇒ the two convergence helpers cannot share a code path. `ToolResponse` (create reply) declares no `content`; `ToolModel` (update reply) does; `GET /id/{id}` returns `ToolAccessResponse`, whose `extra='allow'` preserves `content` ⇒ that GET is the byte-equality readback.
- CSV bytes in-process (CSV ruling): `await Files.get_file_by_id_and_user_id(id, user_id, db=None)` (`models/files.py:169-181`) is async, ownership-checked by SQL filter, opens its own session (so no `__request__` is needed) and returns `None` for missing OR foreign OR exception — one arm covers all three. Then `Storage.get_file(path) -> str` (`storage/provider.py:66-70`, bound at `:348`) returns the path unchanged for local storage, and the bytes come off disk. Trust only the attachment item's top-level `id`.
- OWUI's OWN narration path cannot carry the verdict: under `function_calling: legacy` (`webui/settings.py` `DEFAULT_MODEL_PARAMS`) a tool result becomes a `<source>` citation (`middleware.py` `get_citation_source_from_tool_result`, generic branch `document=[str(tool_result)]`) → `apply_source_context_to_messages` wraps it in `DEFAULT_RAG_TEMPLATE` (`config.py`) → a 0.5B proposer emits that template's own example sentence (`According to the study, the proposed method increases efficiency by 20% [1].`) verbatim ⇒ the outlet filter MUST author every user-visible verdict string, and no surface may depend on the model narrating a verifier result.
- Verdict totality (F4): the filter rewrites the LAST assistant message alone — `content` = the verdict, `output` = exactly one completed message item holding the same text — and leaves every earlier message untouched; model prose never survives, a no-receipt prose reply included. Pins = `tests/test_paste_in_filter_outlet.py` (the multi-turn `test_f4_multiturn_rewrites_only_last_assistant_on_fail_and_pass` holds the earlier-message conjunct, which every single-message test left open) + differential oracle `tests/oracle_filter.py` + `tools/mutants/{filter,receipt,selection}.toml`.
- **Failure reasons (M15.1, `.agent/archive/contracts/m15u1.md`).** Every FAIL outlet call = ONE `INFO` record `figure verification failed reason=<reason>` on logger `webui.paste_in.filter` (OWUI routes stdlib logging through loguru to stdout → `webui.log`) + ONE `status` event `{description: "<sentence> (<reason>)", done: true}` through `__event_emitter__` → persisted in the message's `statusHistory` (`socket/main.py` `status` arm), rendered as the LAST status above the reply on ONE line (`StatusItem.svelte` `line-clamp-1`, so a narrow column truncates it — the M16.1 embed carries the full sentence), reload included; PASS emits neither. Reason = a `RefusalCode` or one of 14 outlet causes; text = `webui/paste_in/reasons.py` `REASONS` (EN, JA), JA iff `__metadata__["user_message"]["content"]` holds a kana LETTER (Unicode name `HIRAGANA LETTER`/`KATAKANA LETTER`/`HALFWIDTH KATAKANA LETTER`). `content`/`output` stay the fixed verdict, and OWUI's chat flows build model messages from `output` (`process_messages_with_output`) or `role`/`content`/`output`/`files` (`load_messages_from_db`), so `statusHistory` never reaches a model through them. Neither channel carries stderr, stdout, program or request bytes; both are best-effort — a raising or stalled (> `STATUS_TIMEOUT_SECONDS`) emit or a raising log handler never costs the verdict, `CancelledError` propagates. Sandbox split: non-traceback stderr naming `loadPyodide` = `sandbox_unavailable` (the content-blocker signature below, carrying the ad-blocker fix), any other stderr = `sandbox_error`; `{'error': …}` without `stderr` = `browser_no_answer` (OWUI's caller on a gone or timed-out tab). Pins = `tests/test_paste_in_filter_reasons.py` + the differential's status expectation + `tools/mutants/filter.toml` `d*` mutants; live = `.agent/measurements/m15u1_status.mjs` (M15 row in its README).
- **Check breakdown (M16.1, `.agent/archive/contracts/m16u1.md`).** Every FAIL (after its status event) + every PASS (after its `files` event) emits ONE `{type: "embeds", data: {embeds: [<html>], replace: True}}` → `webui/paste_in/checks.py` `breakdown_html(reason | None, japanese=…)`: a collapsed `<details>` "Show checks" over the 11 `CHECKS`, rows before `CHECK_OF[reason]` ✓, that row ✗ + its `REASONS` sentence, the rest `not checked`. `replace` is load-bearing: the `socket/main.py` `embeds` arm APPENDS the message's earlier embeds otherwise. OWUI renders `message.embeds` after status + files, before content (`ResponseMessage.svelte`), in `FullHeightIframe` = `srcdoc` + `sandbox="allow-scripts allow-forms allow-popups allow-downloads"` (+ `allow-same-origin` only under the user setting `iframeSandboxAllowSameOrigin`, which also runs its Alpine/Chart.js injection on trigger strings the document avoids); the frame sizes itself only through its own `postMessage({type: "iframe:height"})` (a `ResizeObserver` in the document) ⇒ a restrictive `IFRAME_CSP` (default empty, injected as a meta tag) can stop it. The frame cannot see OWUI's theme class ⇒ mid-tone colours, read on light + dark. Arrival scrolls the embed to centre (`Chat.svelte`, unconditional). The outlet write-back + `chat:outlet` merge never touch `embeds`; `load_messages_from_db` + temporary-chat flows never send them to a model. Status + embed share ONE `STATUS_TIMEOUT_SECONDS` deadline; an emit not started in time is skipped. `CHECK_OF` = the EARLIEST check among a code's raise sites, re-derived by an AST scan in `tests/test_paste_in_checks.py` C2 ⇒ a new raise site in `src/verifier/pysrc/` forces a ruling there. Pins = `tests/test_paste_in_checks.py` + `tests/test_paste_in_filter_checks.py` + the differential's embed expectation + `tools/mutants/{checks,filter}.toml`; live = `.agent/measurements/m16u1_checks.mjs` (M16 row in its README).
