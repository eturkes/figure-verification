# Open WebUI 0.10.2 — sandbox + integration facts (binds M10 + M14)

- Sandbox mechanism (shipped = `webui/paste_in/filter.py`, M19.5; measured on 0.10.2): the tool + the outlet of ONE completion share one `__request__` under native AND legacy function calling, ONE outlet call per completion ⇒ `draw_figure` writes a tagged RECEIPT to `__request__.state` (program + the chat's attachment ids + request text + the admin's column aliases, tag `/2`; `webui/paste_in/receipt.py`; the LAST call decides) and returns the one fixed string `webui/paste_in/verdicts.py` `CHART_SENT` — it runs and decides nothing → the global active OUTLET filter reads that receipt ALONE, re-resolves each id under `__user__`'s id (`owui_files.py::owned_files`), then sends ONE `execute:python` RPC DIRECTLY (bypassing `sanitize_code`), `data = {id, code, session_id, files: [{id, filename}] per owned file}` → `{stdout, stderr, result}`, each CSV at `/mnt/uploads/<filename>` byte-identical → Pyodide runs `webui/paste_in/sandbox.py::wrapper_code`: the trusted reader (`src/verifier/figure/reader.py`, its exact text base64, `.claude/rules/figure.md` § Trust + flow) runs the program unchanged → `stdout` = the tagged description line + at most one PNG line → `parse_description` (else `no_description`) → `judge(description, Sources(owned files by filename, request text, the artifact's anchoring, receipt aliases))` → `Passed` + exactly one PNG data-URI line outside the description line (stripped; else `no_image`) + empty `stderr` (the handler `Ue` starts `stdout`/`stderr`/`result` at `null` + overwrites each only with a TRUTHY worker value ⇒ a clean run replies `stderr: null`, never `""`; EMPTY = key present with `null` or `""`, A6) ⇒ ONE `files` event + `Figure verification passed` + the interpretation; every other outcome ⇒ `Figure verification failed, no image produced`. OWUI's own `patchMatplotlib` fires on the substring `matplotlib` in the RPC source + raises `SyntaxError` before the program runs ⇒ the wrapper assembles that name at run time and carries reader + program as base64 split around it. OWUI picks the sandbox packages by REGEX over the RPC source (13 `\bimport\s+<module>\b|\bfrom\s+<module>\b` entries, `frontend/_app/immutable/nodes/0.VsCm_E_x.js`) and loads only those ⇒ hiding the name hides the packages too: the wrapper loads numpy, pandas + the plotting library ITSELF (`pyodide_js.loadPackage([...])`, top-level `await`, silent `messageCallback` so no loader line reaches `stdout`) and sets `MPLBACKEND=AGG` before the reader imports it (A5). F7's harness `.agent/measurements/f7_wrapper.mjs` reads the regexes + the prelude from the installed bundle and preloads NOTHING — a preloading harness hid exactly this defect while the live PASS arm died `ModuleNotFoundError`. Rewriting `content` AND `output` persists across reload; a `files` event persists the PNG as a message attachment; `__files__`/`__metadata__['files']` are conversation-scoped, not turn-scoped. RPC wall time 9.2–12.0 s (M10 wrapper; the reader's own cost unmeasured live until M19.9); inbound Engine.IO frame cap = 1,000,000 bytes (bounds one render's `stdout`; the reader caps description + PNG below it). Keep `ENABLE_CODE_INTERPRETER` + `ENABLE_CODE_EXECUTION` OFF (the internal RPC is not gated by them), `ENABLE_PYODIDE_FILE_PERSISTENCE` off, `ENABLE_WEBSOCKET_SUPPORT` on, `WEBSOCKET_EVENT_CALLER_TIMEOUT` bounded, `BYPASS_EMBEDDING_AND_RETRIEVAL=true` (else an offline CSV upload calls a remote embedding API).
- Pyodide **`0.28.3`** (CPython 3.13, wasm32) — read the version from `open_webui/frontend/pyodide/package.json`, NEVER from `pyodide-lock.json`, whose `0.28.0.dev0` is stale build metadata. The bundle dir holds **61 entries**, including `matplotlib 3.8.4`, `pandas 2.3.1`, `numpy 2.2.5` AND `scikit_learn 1.7.0` + `scipy 1.14.1`; seaborn alone is absent. The bundle is what a program may import (a module it lacks ⇒ `module_not_available`), and no `Intent` dependency claim may cite an absence the bundle contradicts. Chat file metadata is forwarded, the browser fetches each file by id, the sandbox writes exact bytes to `/mnt/uploads/<filename>` ⇒ a program reads `pd.read_csv('/mnt/uploads/<name>.csv')`; the judge compares every drawn value with those bytes (`.claude/rules/figure.md` § Values). - Current surface: `webui/settings.py` provisions the PASTE-IN tool (`tool_id=figure_verification`, operation `draw_figure`) as the demo's ONE model-visible callable and emits NO `TOOL_SERVER_CONNECTIONS`; bootstrap provisions the demo pair's generated filter (`FILTER_ID=figure_verification_filter`) as the ONE global active function, `smoke` = eight readbacks incl. `filter_current`/`filter_global_active`/`filter_exclusive`, any drift fails closed; `webui/model_stub.py` answers OWUI's legacy SELECTOR turn only — system message holding `Available Tools:` + a user message equal to `Query: <P>` or ending `\nQuery: <P>` (`utils/middleware.py:1102-1124`): P = a banner arm's request rendered by the demo inlet over its own CSV (`webui/banner.py::rendered`) ⇒ a `draw_figure` call carrying that arm's scripted program (`webui/banner.json`, six arms: EN + JA, honest + misleading), every other turn — a bare prompt included — ⇒ prose. - **`function_name_filter_list` cannot narrow a tool server and must never be relied on to.** It is a case-sensitive `str.endswith` over the operation name, not equality (`utils/misc.py:35-70`), so `["python"]` also admits `evilpython`, and an EMPTY list allows ALL. A tool server is therefore removed, never filtered: no `TOOL_SERVER_CONNECTIONS` entry exists at all, and `bootstrap.smoke`'s `no_tool_servers` flag re-checks that every gate run by refusing any `server:`-prefixed id in `GET /api/v1/tools/`.
- **Paste-in law (M10.0 onward).** The pasted artifact is GENERATED — `uv run --locked python tools/generate_paste_in.py`, `--check` in the gate — and a hand edit to `paste-in/*.py` is lost at the next run. Two paste targets per pair, sharing one generator (`webui/paste_in/bundle.py`); two pairs (Q37): production `paste-in/` (strict anchoring) + the demo's `webui/demo-paste-in/` (roots `webui/paste_in/demo_tool.py` = the production tool, `demo_filter.py` = a subclass setting `_ANCHORING = "substitution"` + `_TEMPLATES = DEMO_TEMPLATES`), which `webui/bootstrap.py` provisions. What the generator refuses to embed: a source holding `'''`, ending in a backslash, holding no `"""` (`ruff format` would flip the delimiter and break `--check`), exceeding 100 columns on any line, or holding `from utils`/`from apps`/`from main`/`from config` — OWUI's `replace_imports` (`utils/plugin.py:186-200`) rewrites those four prefixes in tool content on EVERY create and update, so stored bytes would stop equalling generated ones. `extract_frontmatter` (`utils/plugin.py:150-183`) returns `{}` unless `lines[0].strip() == '"""'`; the artifact opens on its SPDX comment, so `install_frontmatter_requirements` is a no-op by construction. `load_tool_module_by_id` returns `module.Tools()` — an INSTANCE — and `get_functions_from_tool` discovers non-`_`-prefixed non-class callables on it, so a helper method needs only a leading underscore to stay invisible. Admin settings = the tool's nested pydantic `Valves` (Q43: `column_aliases`): OWUI builds `Valves(**form)` on every save (`routers/tools.py:774-825`; a raising validator refuses the save) — allowed for the tool's owner, a user with a `write` access grant on it, or role `admin` (`routers/tools.py:788-798`), so the admin guide makes an administrator the owner and keeps write access away from chat users — and sets `module.valves = module.Valves(**stored)` at every tool resolution ONLY on an instance already holding `valves` (`utils/tools.py:298-300`) ⇒ `Tools.__init__` sets `self.valves`; `get_functions_from_tool` skips classes, so `Valves` is no operation; the Workspace → Tools row's **Valves** button opens it (`Tools.svelte` `ValvesModal`), a plain `str` field rendering as a textarea. Reserved `__metadata__`/`__user__` params never reach the model: pydantic's `create_model` warns-and-ignores leading-underscore field names before `get_tools()` strips `__`-prefixed properties again (`utils/tools.py:306-317`).
- **Demo transport (M10.6; Q40; ruling 8).** The paste-in filter's INLET renders its class's `_TEMPLATES` (`webui/paste_in/templates.py`, hand-authored: the task, the attached file's sandbox path + header, the chart rules) around the LAST user message: `file` over the LAST owned attachment when its header passes the core CSV reader, else `no_file`; production's end in the `draw_figure` transport paragraph (no system prompt from this repository reaches production: user, session 8), the demo's in the bare-source format paragraph (Q40) its adapter wraps as that call; a NEW body holding a NEW message dict; `__metadata__` stays untouched; non-text content ⇒ the body returns unchanged. - Tool provisioning REST shapes (0.10.2): `ToolForm` = `{id, name, content, meta: ToolMeta, access_grants}`, `id` must satisfy `.isidentifier()` and is lower-cased (`routers/tools.py:360-366`).
