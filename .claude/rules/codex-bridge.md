# `--codex` arm — the codex app-server bridge (`webui/codex_bridge.py`)

- Shape: OpenAI `/v1` (`GET /models`, `POST /chat/completions`, stream or not) → ONE `codex app-server` child over stdio JSON-RPC (codex-cli 0.163.0), one ephemeral thread per completion: system/developer text → `baseInstructions`, `tools` → `dynamicTools`, every other message → raw Responses items via `thread/inject_items`, then `turn/start` with `input: []`. Stateless replay = the model reads the OpenAI messages verbatim, multi-turn chats + the tool round included; the reply is buffered whole, so any failure is an HTTP 502 naming the cause (never a prose reply the outlet would read as `no_tool_call`).
- Clean context is MEASURED, never assumed: point the child at a mock Responses provider (`-c model_provider="capture" -c 'model_providers.capture={name="capture",base_url="http://127.0.0.1:<port>/v1",wire_api="responses"}'`) and read the request body — `codex_bridge.py::_CONFIG` + `_CATALOG` + `_THREAD` were each derived that way (stock Codex adds environment + permissions text, a skills catalogue, multi-agent role text + tools, `request_user_input`, a `sleep` tool, and wraps every tool in a JavaScript `exec` tool for `gpt-6-luna`'s `tool_mode: code_mode_only`). The mock provider HIDES provider-gated tools: the ChatGPT provider added `image_gen` (`features.image_generation=false` removes it), visible only in the backend's `response.created` echo under `RUST_LOG=trace` (request bodies are compressed). Re-run both probes after a codex-cli upgrade; a new tool or context block = a new `_CONFIG` line + its pin in `tests/test_webui_codex_bridge.py`.
- Isolation: own `CODEX_HOME` + `HOME` (`.codex-bridge/`, gitignored) ⇒ the operator's `~/.codex` (AGENTS.md, MCP servers, plugins, skills, memories) never loads. Auth = `account/login/start` `chatgptAuthTokens` (marked unstable/internal by the protocol) with `access_token` + `account_id` read from `~/.codex/auth.json`, held in memory; `account/chatgptAuthTokens/refresh` re-reads the file. The bridge never writes that file and never sends `refresh_token`: a copied auth file's refresh would rotate the token family under the operator's own Codex login.
- Tool call: `item/tool/call` ⇒ `turn/interrupt` goes on the wire BEFORE the call's answer (`Codex.send` writes synchronously: an `ensure_future` interrupt lets the answer go first, and the model samples on) ⇒ one OpenAI `tool_calls` reply, `finish_reason: tool_calls`; the stream opens with an empty content delta.
- Provisioning: `--codex` = `WEBUI_PROVISION_MODEL_ID=gpt-6-luna` + `WEBUI_PROVISION_PASTE_IN=production` (`paste-in/` pair, strict anchoring, transport template) + `WEBUI_PROVISION_FUNCTION_CALLING=native` (Open WebUI's default + production's) ⇒ a browser drives it; `python -m webui chat` (headless) cannot. The bridge serves the slugs `_CATALOG` holds alone.
- Live record = `.agent/measurements/luna/` (`luna_live.mjs` drives, `luna_classify.py` re-judges each relayed program on the host + decides distortion presence from `luna_facts.py`'s plain-matplotlib facts, never the reader's description). A run's program = the LAST `draw_figure` call in `CODEX_BRIDGE_DUMP_DIR` inside its time window (the embed listing elides past 60 lines / 3,000 characters); an unreadable figure = `distorted: null`, never `false`.
- Live batches need the CPU: the browser's Pyodide run answers inside Open WebUI's 60 s caller timeout or fails `browser_timeout` (beside an 8-worker job, load ≈ 17 on 4 cores, every run did) ⇒ start a batch with no `heavy --status` holder running a worker pool; a run the host starved moves to `luna/excluded/` with its cause, never into the tallies.
