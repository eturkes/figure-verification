# `--codex` arm — the codex app-server bridge (`webui/codex_bridge.py`)

- Shape: OpenAI `/v1` (`GET /models`, `POST /chat/completions`, stream or not) → ONE `codex app-server` child over stdio JSON-RPC (codex-cli 0.164.0; 0.163.0 measures clean too), one ephemeral thread per completion: system/developer text → `baseInstructions`, `tools` → `dynamicTools`, every other message → raw Responses items via `thread/inject_items`, then `turn/start` with `input: []`. Stateless replay = the model reads the OpenAI messages verbatim, multi-turn chats + the tool round included; the reply is buffered whole, so any failure is an HTTP 502 naming the cause (never a prose reply the outlet would read as `no_tool_call`).
- Clean context is MEASURED, never assumed: `uv run --locked python .agent/measurements/codex_context.py <codex-bin> [--chatgpt]` = one completion through the shipped bridge (one system text, one user text, one tool). Default = a loopback mock Responses provider recording the request body; `--chatgpt` = the ChatGPT backend under `RUST_LOG=trace` (one completion on the subscription), read from its `response.created` echo — the turn's echo is the LAST (a tool-less warm-up comes first) — since the mock provider HIDES provider-gated tools (`image_gen`, removed by `features.image_generation=false`) and request bodies on the wire are compressed. Exit 0 = the request's tool alone, no instructions, (mock) the system + user messages alone; 1 prints the surplus. `codex_bridge.py::_CONFIG` + `_CATALOG` + `_THREAD` were each derived that way: stock Codex adds environment + permissions text, a skills catalogue, multi-agent role text + tools, `request_user_input`, a `sleep` tool, and wraps every tool in a JavaScript `exec` tool for `gpt-6-luna`'s `tool_mode: code_mode_only`; 0.164.0 added `view_image` (`features.view_image=false`) + a freeform `apply_patch` for a catalog entry naming `apply_patch_tool_type` (`_CATALOG` names none). Rerun both modes after a codex-cli upgrade, positive control = the previous bridge on the new binary (exit 1); a new tool or context block = a new `_CONFIG` line or catalog change + its pin in `tests/test_webui_codex_bridge.py`.
- Isolation: own `CODEX_HOME` + `HOME` (`.codex-bridge/`, gitignored) ⇒ the operator's `~/.codex` (AGENTS.md, MCP servers, plugins, skills, memories) never loads. Auth = `account/login/start` `chatgptAuthTokens` (marked unstable/internal by the protocol) with `access_token` + `account_id` read from `~/.codex/auth.json`, held in memory; `account/chatgptAuthTokens/refresh` re-reads the file. The bridge never writes that file and never sends `refresh_token`: a copied auth file's refresh would rotate the token family under the operator's own Codex login.
- Request origin (M23.1 F2): the bridge authenticates no caller and spends the operator's subscription ⇒ it binds loopback alone (`codex_bridge.py::serve`), answers only the `Host` headers `codex_bridge.py::hosts` derives from `model_backend_url` (its name + `127.0.0.1`/`localhost`/`[::1]`, with the port: Litestar's `allowed_hosts` matches the whole header; a DNS-rebound page names its own domain) and only an `application/json` body (a cross-site `text/plain` post needs no CORS preflight; Open WebUI 0.12.3 + nucllei send JSON). A test client sets `base_url` to a loopback URL.
- Tool call: `item/tool/call` ⇒ `turn/interrupt` goes on the wire BEFORE the call's answer (`Codex.send` writes synchronously: an `ensure_future` interrupt lets the answer go first, and the model samples on) ⇒ one OpenAI `tool_calls` reply, `finish_reason: tool_calls`; the stream opens with an empty content delta.
- Provisioning: `--codex` = `WEBUI_PROVISION_MODEL_ID=gpt-6-luna` + `WEBUI_PROVISION_PASTE_IN=production` (`paste-in/` pair, strict anchoring, transport template) + `WEBUI_PROVISION_FUNCTION_CALLING=native` (Open WebUI's default + production's) ⇒ a browser drives it; `python -m webui chat` (headless) cannot. The bridge serves the slugs `_CATALOG` holds alone. Reasoning effort = `CODEX_BRIDGE_EFFORT`, default `low` (user); empty = the model's own `medium`; a request's `reasoning_effort` wins.
- Live record = `.agent/measurements/luna/` (`luna_live.mjs` drives, `luna_classify.py` re-judges each relayed program on the host + decides distortion presence from `luna_facts.py`'s plain-matplotlib facts, never the reader's description). A run's program = the LAST `draw_figure` call in `CODEX_BRIDGE_DUMP_DIR` inside its time window (the embed listing elides past 60 lines / 3,000 characters); an unreadable figure = `distorted: null`, never `false`.
- Live batches need the CPU: the browser's Pyodide run answers inside Open WebUI's 60 s caller timeout or fails `browser_timeout` (beside an 8-worker job at load ≈ 17 on 4 cores, every run did) ⇒ start a batch on an idle CPU, the browser at normal scheduling class; a run the host starved moves to `luna/excluded/` with its cause, never into the tallies.
