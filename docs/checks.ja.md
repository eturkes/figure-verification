# 図のチェック: 簡単なガイド

このガイドでは、図の検証器の各チェックの意味と、チェックが不合格になったときの対処を説明します。
グラフの返信の下にある **チェック項目を表示** の各行は、ここにある対応する節にリンクしています。
すべての規則、理由のコード、上限の詳細は、リファレンス [verification.ja.md](verification.ja.md)
をお読みください。英語版は [checks.md](checks.md) をお読みください。

## 合格したグラフの意味

言語モデルが、グラフを描く Python のプログラムを書きます。ブラウザがそのプログラムを実行し、
その後、検証器が完成した図をチェックします。すべてのチェックに合格した場合に限り、返信に
グラフと `Figure verification passed` が表示されます。それ以外の場合、返信には
`Figure verification failed, no image produced` とその理由が表示されます。

合格したグラフからは、次の 2 つがわかります。

- グラフのすべての部品は検証器がチェックする種類で、すべての部品が完全性の規則に従っています。
  たとえば、棒はゼロから始まり、逆向きの軸はありません。
- データを用意した場合、描画したすべての値はそのデータから来ています。

合格は、グラフが質問に答えていることを示すものではありません。たとえば、平均が必要なときに、
正しい合計を示すグラフもあり得ます。グラフの下の文章を読んでください。描画した各値の出所が
書かれています。

## 値の出所

- **添付した CSV ファイル。** 描画した値は、1 つの列の値でもかまいません。グループごとの合計、
  平均、最小値、最大値、行数のいずれか 1 つでもかまいません。
- **依頼文の数値。** 描画した値は、入力した数値でもかまいません。`1 to 10` や `1から10まで`
  のような範囲は、1 から 10 までのすべての整数になります。カテゴリのラベルも依頼文にある必要が
  あります。
- **そのデータの 1 つの計算。** 検証器は、累計、合計に対する割合または百分率、前の点からの変化、
  2 乗も認めます。CSV ファイルの 2 つの列については、比率、差、積、和を認めます。
- **データなし。** ファイルを添付せず、数値も書かない場合、検証器はグラフの完全性だけを
  チェックします。返信にもそのことが示されます。

依頼文には、このチャットで前に書いたメッセージも含まれます。そのため、`棒を赤にして` のような
続きの依頼でも、前のメッセージの数値と列名が使われます。一時チャットでは、最後のメッセージだけが
対象です。

## 「チェック項目を表示」の見方

**チェック項目を表示** は、9 つのチェックを実行する順に一覧にします。各行は次の 3 つの状態の
いずれかを示します。

- ✓ **合格**: チェックが完了しました。
- ✗ **不合格**: このチェックでグラフが止まりました。行に理由が表示されます。
- – **未実施**: 前のチェックが不合格だったため、このチェックは実施していません。

行をクリックすると開きます。開いた行には、チェックの内容と、関連するプログラムの行または注記が
表示されます。不合格の行には、不合格の理由も表示されます。不合格になった部分を描いた行、または
その呼び出しを行った行が 1 つある場合、不合格の行ではその行に印が付きます。不合格の後は、返信の
上のステータス行と開いた行に、`(zero_not_in_limits)` のようなかっこ付きのコードも表示されます。
各コードの説明は [リファレンス](verification.ja.md) にあります。

## チェック

<a id="check-program"></a>

### 1. モデルからグラフのプログラムを受信

モデルは、グラフのプログラムをグラフ用のツールで送る必要があります。返信の文章に書いた
プログラムは対象になりません。グラフを作れるのはツールだけだからです。

このチェックが不合格の場合は、もう一度依頼してください。グラフ用のツールを使うように、モデルに
依頼することもできます。

[このチェックの詳しい規則を読む](verification.ja.md#check-program)

<a id="check-run"></a>

### 2. ブラウザでプログラムを実行

ブラウザは、モデルのプログラムを変更せずに Open WebUI のサンドボックス (Pyodide) で実行します。
プログラムが使えるのは、numpy、pandas、matplotlib と Python の標準ライブラリです。返信が完了する
まで、チャットのタブを開いたままにしてください。

このチェックが不合格の場合:

- プログラムにエラーがある場合は、もう一度依頼するか、より簡単なグラフを依頼してください。
- seaborn のように、サンドボックスにないモジュールをプログラムが読み込む場合は、matplotlib か
  pandas でグラフを描くように依頼してください。
- ブラウザがサンドボックスを読み込めない場合は、このサイトの広告ブロッカーをオフにしてください。
- ブラウザが応答しない場合は、タブを開いたままにして、もう一度試してください。

[このチェックの詳しい規則を読む](verification.ja.md#check-run)

<a id="check-figure"></a>

### 3. 図を 1 つ描画

プログラムは matplotlib の図をちょうど 1 つ描く必要があります。pandas のグラフも matplotlib の
図です。1 つの図には、`plt.subplots` などで作った複数のパネルを入れられます。使用できる
フォントで、グラフのすべての文字を描ける必要があります。

このチェックが不合格の場合は、グラフを 1 つだけ依頼してください。複数のグラフを比べるには、
1 つの図の中のパネルとして依頼してください。

[このチェックの詳しい規則を読む](verification.ja.md#check-figure)

<a id="check-parts"></a>

### 4. 検証器がチェックできる部品だけを使用

グラフの各部品は、検証器がチェックできる種類である必要があります。

- 折れ線、点、棒 (グループ化した棒と積み上げた棒を含む)、円、面
- 塗りつぶした棒と 1 つのデータセットのヒストグラム
- `axhline`、`axvline`、`axhspan`、`axvspan` で描いた基準線と帯
- テキスト: タイトル、軸ラベル、凡例、目盛りのラベル、グラフ上の注記

それ以外の部品があると、グラフは止まります。たとえば、エラーバー、箱ひげ図、等高線、画像、
極座標や 3D の軸、挿入図、2 つ目の y 軸、重なるパネルです。カラーバーを使えるのは、散布図の色を
示す場合だけです。

このチェックが不合格の場合は、上のいずれかの種類のグラフを依頼してください。2 つ目の量を示す
には、2 つ目の y 軸ではなく、2 つ目のパネルを依頼してください。

[このチェックの詳しい規則を読む](verification.ja.md#check-parts)

<a id="check-axes"></a>

### 5. 正しい軸

各軸はデータを正しく示す必要があります。

- 棒、ヒストグラム、面の値の軸はゼロを含みます。折れ線と散布図は、データに合わせて拡大できます。
- 逆向きの軸はありません。
- 各軸は線形です。対数軸は、軸ラベルかパネルのタイトルに `log`、`logarithmic`、`対数` の
  いずれかがある場合に限り合格します。
- 各目盛りのラベルは、その位置の正しい値を示します。
- すべてのデータ点は、軸の範囲の中にあります。
- 各部品は、軸上のデータの値の位置にあります。

このチェックが不合格の場合は、軸の範囲の指定や軸の反転をなくしたグラフを依頼してください。
ゼロを含まない値の軸が必要な場合は、折れ線グラフか散布図を依頼してください。対数の目盛りが
必要な場合は、ラベルに `対数` と書いた対数軸を依頼してください。

[このチェックの詳しい規則を読む](verification.ja.md#check-axes)

<a id="check-marks"></a>

### 6. 正しいグラフ要素

各部品は値を正しく示す必要があります。

- 棒と面はゼロから始まるか、積み上げの中で別の棒や面の上から始まります。
- グループ化した棒は横に並び、重なりません。
- ヒストグラムの棒は、データの正しい度数または密度を示します。
- 円グラフの扇形は円を満たし、各扇形は正しい割合を示します。
- 折れ線の点は、x 軸に沿って一方向に進みます。
- マーカーの大きさや色が異なる場合、それを説明する凡例かカラーバーがあります。
- 系列が 2 つ以上あるパネルに凡例がある場合、凡例はすべての系列を示します。
- すべての部品は表示されており、描画したすべての値は有限の数値です。

このチェックが不合格の場合は、標準的な形のグラフを依頼してください。たとえば、ゼロから始まる
棒と、系列ごとの凡例の項目を依頼してください。

[このチェックの詳しい規則を読む](verification.ja.md#check-marks)

<a id="check-values"></a>

### 7. 描画した値があなたのデータにある

[値の出所](#値の出所) のとおり、描画した各値はあなたのデータから来ている必要があります。1 つの
系列で同じカテゴリを 2 回示すことはできません。

このチェックが不合格の場合:

- 値を含む CSV ファイルを添付するか、依頼文に各値と各ラベルを書いてください。
- 丸めた値や拡大・縮小した値は、同じ数値がデータにあるか、上の計算のいずれかから来る場合を除き、
  不合格になります。データにあるとおりの値を依頼してください。

[このチェックの詳しい規則を読む](verification.ja.md#check-values)

<a id="check-columns"></a>

### 8. 描いた列が依頼と一致

CSV ファイルを添付した場合、検証器は、グラフが描く列を依頼文の列名と比べます。

- **本番環境。** 依頼文が列名を含む場合、グラフが描く列をすべて含む必要があります。
- **デモ。** グラフは、依頼文にある列を別の列に置き換えてはいけません。
- 値が 2 つの列に同じように当てはまる場合、依頼文はそのどちらかの名前を含む必要があります。
- タイトル、軸ラベル、凡例は、グラフが描いていない列を挙げてはいけません。別の種類の集計を
  挙げてもいけません。たとえば、合計のグラフに `平均` と書くことです。

検証器は、管理者が列に登録した別名と、`年月` に対する `月` のような日本語の短い形も認識します。

このチェックが不合格の場合は、グラフに描く各列の名前を、ファイルの表記のとおりに依頼文に
書いてください。

[このチェックの詳しい規則を読む](verification.ja.md#check-columns)

<a id="check-attach"></a>

### 9. 返信に画像を添付

ブラウザでの実行で PNG 画像が 1 枚返り、Open WebUI がそれを返信と一緒に保存します。

このチェックが不合格の場合は、もう一度試してください。

[このチェックの詳しい規則を読む](verification.ja.md#check-attach)

## 検証器がチェックしない内容

- **プログラムの誠実さ。** 検証器はプログラムを信頼しています。プログラムはすべてのチェックの
  前に、検証器の読み取り処理と同じサンドボックスで実行されます。そのため、検証器を欺こうとする
  プログラムは、それができます。プログラムは、Open WebUI の他のコード実行と同じく、添付ファイル
  を読み取り、ブラウザのネットワークにアクセスすることもできます。
- **グラフ上の文字。** 検証器は、注記や値のラベルをグラフの下に一覧にしますが、その内容は
  判断しません。
- **意図。** 検証器は、グラフが意図した量を示していることはチェックしません。依頼文の列名が、
  意図との唯一のつながりです。
- **画像そのもの。** 検証器は、ブラウザ、matplotlib、画像のピクセルを信頼しています。
