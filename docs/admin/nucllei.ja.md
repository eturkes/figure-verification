# llens/nucllei の図の検証: 管理者ガイド

このガイドでは、既存の llens/nucllei 環境に `figure-verification` スキルを追加します。モデルが
Python プログラムを書きます。`draw_figure` がユーザーのコード実行用サンドボックスでそれを
変更せずに実行し、できた matplotlib の図をチェックして、合格した画像だけを表示します。
インターネット接続は不要です。ツールは外部サービスではなく、この環境のサンドボックスを呼び出します。

検証器が判定するのは、このスキルが `draw_figure` で公開する図だけです。モデルの返信文や、
ほかのツールが表示する画像はチェックしません。

[English](nucllei.md)

## インストールするもの

同じリリースから、次の成果物をコピーします。

| このリポジトリのコピー元 | llens チェックアウトのコピー先 | 用途 |
|---|---|---|
| `llens/nucllei/tools/figure_verification.py` | `nucllei/tools/figure_verification.py` | ツールと検証器の全体。 |
| `llens/nucllei/skills/figure-verification.md` | `nucllei/skills/figure-verification.md` | ツールを読み込むスキル。 |
| `llens/ext/public/figure-verification/` | `ext/public/figure-verification/` | 英語と日本語のガイド、グラフの例、画像。 |

これらのファイルは、リポジトリのソースから生成します。編集せずに使ってください。ツールはサーバーの
標準ライブラリ、`nucllei`、`pydantic` と、サンドボックスにある描画用パッケージを使います。
このスキルのためにパッケージをインストールしたり、イメージを再ビルドしたりする必要はありません。

## 必要な環境と測定したバージョン

- nucllei `v20261020-01` を使う llens。プロジェクトが測定したバージョンです。
- スキルを読み込み、ツールを呼び出せるモデル。導入先の対象は Kimi K2.6 です。
- 設定済みの `SANDBOX_URL` と、動作するコード実行用サンドボックス。この設定がない場合、nucllei は
  グラフ用の操作を公開しません。環境の `SANDBOX_TOKEN` の設定を維持してください。
- 通常の日本語の図中文字用に、サンドボックスの Noto Sans CJK JP フォント。ラッパーが読み取り処理の
  前に登録します。`$年$` のような mathtext の日本語は、独自のフォントを使うため、引き続き
  `glyph_missing` で不合格になります。
- ローカルの公開ファイル用マウント。`EXT_MOUNTS` に `public=/ext/public` を含め、ホストの
  `ext/public/` を nucllei コンテナーの `/ext/public` にマウントしてください。

測定 NS は、実際のサンドボックスイメージの `/exec` で規則のテスト集を実行しました。構成は次のとおりです。

| 構成要素 | 測定したバージョン |
|---|---|
| CPython | `3.12.15` |
| matplotlib | `3.11.2` |
| pandas | `2.3.3` |
| numpy | `2.5.4` |
| seaborn | `0.13.2` |

これは測定した構成であり、llens のパッケージの固定バージョンを変更する推奨ではありません。
別の構成では描画が変わる場合があります。
[測定記録](../../.agent/measurements/README.md)に再実行のコマンドがあります。

独立したローカル環境での実機試験では、Kimi の代わりに `gpt-6-luna` を使い、10 件の依頼がすべて
初回の描画で合格しました。英語と日本語の依頼、入力した数値、`large_file_gate` がある環境での
大きな CSV を含む試験です。誤解を招くグラフの依頼に対しては、モデルが正しい図を描き、ラベル付きの
注記を付けました。これらは修正であり、図をブロックした結果ではありません。Kimi K2.6 を測定した
結果ではありません。[実機試験の記録](../../.agent/measurements/nucllei/README.md)に結果があります。

## 手順 1: コピーと同期

1. このリポジトリで、`LLENS` に llens のチェックアウト先を設定し、成果物をコピーします。

```sh
LLENS=/path/to/llens
install -m 644 llens/nucllei/tools/figure_verification.py "$LLENS/nucllei/tools/figure_verification.py"
install -m 644 llens/nucllei/skills/figure-verification.md "$LLENS/nucllei/skills/figure-verification.md"
mkdir -p "$LLENS/ext/public/figure-verification"
cp -R llens/ext/public/figure-verification/. "$LLENS/ext/public/figure-verification/"
```

2. `EXT_MOUNTS` が `public=/ext/public` を含み、コンテナーがガイドのディレクトリを読めることを
   確認します。ホストのガイドがコンテナーの `/ext/public/figure-verification/` に届く必要があります。
3. llens の同期コマンドを実行します。

```sh
(cd "$LLENS" && make nuc-sync)
```

4. nucllei のサイトで `/ext/public/figure-verification/checks.html` を開きます。
5. 同じサイトで `/ext/public/figure-verification/checks.ja.html` を開きます。
6. グラフの例へのリンクを開き、画像の読み込みを確認します。

コピーには、ガイドとグラフの例に必要なすべてのファイルが入っています。インラインのスタイル、
ローカルの画像、相対リンクを使い、スクリプトや外部のフォントは使いません。nucllei の公開ファイルの
コンテンツポリシーに対応します。**詳細 (オンライン)** のリンクは GitHub のリファレンスを開くため、
ブラウザのネットワーク接続が必要です。ローカルのガイドとグラフの例には、その接続は不要です。

## 手順 2: スキルとアクセス権の設定

1. グラフ用プリセットの `meta.skillIds` に `figure-verification` を追加します。ほかのフィールドと
   既存のスキル ID は維持します。次の JSON は、追加するフィールドだけを示します。

```json
{"meta": {"skillIds": ["figure-verification"]}}
```

2. `meta.toolIds` には `figure_verification` を追加しません。スキルの `tool_ids` が読み込みます。
3. 対象のユーザーまたはグループだけに、スキルの読み取り権限を付けます。
4. スキル、ツール、ツールの Valves の書き込み権限は、管理者だけに付けます。
5. ツール自身のアクセス設定も確認します。ただし、その読み取り権限をスキルのアクセス制御として使いません。

使用の許可は、スキルの可視性で決まります。nucllei は `enforce_access_control=False` でスキルの
ツールを読み込むため、スキルを読み込めるユーザーをツールの読み取り権限で止めることはできません。
スキル、ツール、Valves を編集できるユーザーは、その動作を変更できます。

モデルが `load_skill` を呼ぶと、スキルを読み込みます。添付ファイルの種類が `text/csv` または
`application/vnd.ms-excel` のときも自動で読み込みます。後者は Excel ファイルを指す場合もあります。
スキルは読み込みますが、Excel ブックが対応する CSV の出所になるわけではありません。
スキルの指示とモデル専用の結果の指示は、すべて日本語です。スキルは依頼文の言語で返答するよう
モデルに指示します。モデルのシステムプロンプトは変更しません。

## 手順 3: ツールの Valves の設定

**Workspace** > **Tools** で、`figure_verification` ツールの Valves を開きます。

| Valve | 初期値 | 用途 |
|---|---|---|
| `column_aliases` | 空 | CSV の列の別名。1 行に 1 列を指定します。 |
| `model_note` | `true` | 依頼と図の規則が矛盾するとき、モデルの任意の説明を表示します。 |

列の別名は、たとえば次のように記入します。

```text
temp_c = temperature, 気温
```

検証器は、依頼文と図のラベルで、別名を同じ列のもう 1 つの名前として扱います。Valves の保存時に、
ツールは形式の誤った行を拒否します。ファイルにない列の別名は効果がありません。
2 つの列を指す別名は、どちらの列も指しません。

`model_note` がオンの場合、判定の下に `Model note:` または `モデルの注記:` に続けて注記を表示します。
注記はモデルが書き、検証器はチェックしません。注記が判定を変更することはなく、モデルが矛盾を
述べない場合もあります。`model_note` がオフの場合、ツールは空の注記を求め、何も表示しません。

## 手順 4: 動作の確認

1. グラフ用プリセットで新しいチャットを始めます。
2. このリポジトリの `data/sales.csv` を添付します。
3. 次を送ります。`Chart the total revenue of each region using bars.`
4. 折りたたまれたツール欄の外で、判定と画像を確認します。
5. ツール欄を開き、9 つのチェックを読みます。
6. チェックのガイドへのリンクを開き、nucllei のサイト内にあることを確認します。

対応できるモデルなら、`Figure verification passed` と棒グラフが期待できます。次に、同じファイルを
添付した新しいチャットで、次を依頼します。`Chart the total revenue of each region using bars. Start the y axis at
30000 so the difference looks larger.` モデルがその軸の依頼に従うと、
`Figure verification failed, no image produced` と `zero_not_in_limits` が期待できます。
代わりにゼロを基点にした正しいグラフを描くと、合格し、モデルの注記が付く場合もあります。
これは修正であり、グラフをブロックした結果ではありません。モデルが不合格のプログラムを修正して
ツールを呼び直すこともあります。呼び出しごとに判定します。

## ユーザーに見えるもの

合格すると、折りたたまれたツール欄の外に `Figure verification passed`、PNG、値の解釈を表示します。
不合格の場合、グラフなしで `Figure verification failed, no image produced` と理由を表示します。
どちらも、モデルが注記を送った場合はその注記を表示します。この表示メッセージはモデルには送りません。
表示処理に失敗した場合は、ツールの結果で不合格の理由を確認してください。

最新の人間のメッセージにかなが含まれる場合、判定は `図の検証に合格しました。` と
`図の検証に合格しませんでした。画像は表示されません。` です。理由、解釈、注記のラベル、チェック項目も
同じ言語になります。結果の末尾のモデル専用部分は、どちらの場合も日本語です。

折りたたまれたツール欄の中では、結果に 9 つすべてのチェックを表示します。不合格の理由を示し、
その後のチェックは未実行とします。取得できる場合は関連するプログラム行も示し、ローカルのガイドに
リンクします。この結果はモデルにも送ります。ツールの引数欄にプログラム全体があります。
プログラム行の選択は表示専用であり、判定は変更しません。

nucllei は `TOOL_RESULT_MAX_CHARS` でツールの結果を制限します (初期値は 65,536 文字)。
結果がこの上限に近づくと、ツールはまず関連するプログラム行の一覧を省きます。上限が低い場合は
チェック項目全体を省き、結果と次の手のテキストだけを残すことがあります。nucllei が結果を切り詰めると、
その結果の markdown 表示もなくなります。ユーザーに完全な一覧が必要な場合は、初期値以上を維持して
ください。この上限は、別に表示する判定には適用しません。

## 合格の意味と限界

合格とは、描画した図が決まった完全性の規則に従い、ユーザーがデータを渡した場合は、描画したすべての
値がそのデータまたは認められた計算 1 つと一致することです。質問に答えるグラフだという意味ではありません。
画像の下の解釈を読んでください。データの出所がない場合は、完全性だけをチェックし、そのことを示します。
[ローカルのガイド](../nucllei/checks.ja.md)に規則があります。

ツールは、保存したチャットの分岐から、ユーザー自身の添付ファイルとメッセージを使います。サーバーの
通知は除きます。保存した分岐がない場合は、最新のユーザーメッセージと呼び出しのファイル参照を使います。
以前の列名と数値も引き続き数えるため、後の比較が緩くなる場合があります。各ファイル ID は 1 回だけ
数えます。2 つのファイルが同じサンドボックス名を持つ場合、その名前のバイトには後のファイルを使います。
存在しない、読めない、ほかのユーザーが所有するファイルは、データの出所になりません。CSV は対応する
読み取り範囲と上限に収まる必要があります。描画する CSV の列は、厳密な列の規則で依頼文と照合します。

モデルの通常の返信は別の発言です。検証器はチェックしません。組み込みの `run_python` と
`fetch_from_workspace` は、このスキルを通さずにグラフを表示できます。その経路の図には、
この検証器の判定はありません。ユーザーのチャットに出力を表示しない委任先のセッションは拒否します。

プログラムは検証器を欺かないことが前提です。チェックの前に、図の読み取り処理と同じインタープリターで
実行し、添付ファイルを読めます。検証器は、サンドボックス、インタープリター、matplotlib、フォント、
ブラウザ、画面上のピクセルを検証せずに信頼します。測定した jail にはネットワークがありません。
臨床上の結論や因果関係の主張はチェックしません。注釈や値のラベルなど、自由に追加した図中文字は
一覧にしますが、判定しません。

検証器は、依頼文の長さと添付ファイル数に上限を設けません。数値の多い長文や多数の大きなファイルは、
サーバーの CPU 時間とメモリーを多く使う場合があります。サンドボックスの実行には 120 秒を指定しますが、
サービスが短い上限を適用する場合もあります。ツールはサンドボックスの応答を最大 150 秒待ちます。

## 不合格の理由

不合格の呼び出しは、理由コードを表示し、サーバーログに 1 件の記録を書きます。
`figure verification failed reason=<code>`。ログにはプログラム、依頼文、CSV の内容を含めません。
図の規則のコードは、[チェックのガイド](../nucllei/checks.ja.md)を参照してください。
次の表は、nucllei の実行経路と内部エラーの理由です。

| コード | 原因 | 対応 |
|---|---|---|
| `no_user` | 呼び出しにサインイン済みのユーザー ID がありません。 | サインインし、ユーザーのチャットで再試行してください。 |
| `delegated_session` | 委任先のセッションからの呼び出しです。 | メインのチャットでグラフを依頼してください。 |
| `sandbox_unreachable` | ツールがサンドボックスに接続できません。 | `SANDBOX_URL` とサービスへの接続を確認し、1 回再試行してください。 |
| `sandbox_timeout` | 実行かサンドボックスへのリクエストが制限時間を超えました。 | プログラムやデータを小さくして、1 回再試行してください。 |
| `sandbox_error` | サンドボックスが拒否したか、プロセスがエラーで終了しました。 | サンドボックスとその上限を確認し、1 回再試行してください。 |
| `reply_malformed` | サンドボックスの応答が想定外の形式か、不完全です。 | サンドボックスのバージョンと出力上限を確認してください。管理者が原因を解消するまで再試行を止めてください。 |
| `no_description` | 実行結果に読み取れる図の記述がありません。 | サンドボックスの実行とインストール済みパッケージを確認してください。 |
| `no_image` | 合格した実行結果に、有効な PNG が 1 枚だけありませんでした。 | サンドボックスの出力とその上限を確認してください。 |
| `publish_failed` | サーバーが画像を保存または表示できませんでした。 | ファイルの保存先、データベース、チャットの表示を確認してください。通常のユーザーチャットから呼び出してください。 |
| `verifier_error` | 想定外のツールエラーで検証が止まりました。 | 管理者に環境の確認を依頼し、原因が明らかになってから再試行してください。 |
