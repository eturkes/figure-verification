# Open WebUI 用の図の検証機能：管理者ガイド

このガイドは、既存の Open WebUI インスタンスに図の検証機能を追加する手順を説明します。
設定後、チャットモデルはグラフを描く Python プログラムを書きます。利用者のブラウザがそのプログラムを
実行し、グラフがチャットに表示される前に、独立した検証器が完成した図を確認します。

- 図がすべてのチェックに合格すると、チャットにグラフと `Figure verification passed` が表示されます。
- チェックが不合格になると、チャットに `Figure verification failed, no image produced` が表示されます。
  このメッセージの上のステータス行に、理由が表示されます。

判定メッセージは英語のままです。この 2 つの文字列は変更しないでください。

## インストールするもの

Open WebUI に 2 つのファイルを貼り付けます。ファイルはこのリポジトリの `paste-in/` ディレクトリにあります。

| ファイル | Open WebUI の項目 | 項目 ID |
|---|---|---|
| `paste-in/figure_verification_tool.py` | ツール | `figure_verification` |
| `paste-in/figure_verification_filter.py` | 関数（フィルター） | `figure_verification_filter` |

2 つのファイルに検証器全体が含まれています。ファイルが使うのは Python 標準ライブラリと、Open WebUI
に含まれる `open_webui` と `pydantic` のパッケージだけです。ネットワークには接続しません。パッケージのインストール
やコンテナイメージの再ビルドは不要です。

2 つのファイルは同じリリースのものを組み合わせて使ってください。ファイルは編集しないでください。
リポジトリがソースコードからこれらのファイルを生成します。

## 前提条件

- Open WebUI 0.10.2。本プロジェクトはこのバージョンで測定しました。他のバージョンは測定していません。
- Open WebUI 0.10.2 に含まれる Pyodide コード実行環境（Pyodide 0.28.3、matplotlib、pandas、
  numpy を含む）。グラフのプログラムは、利用者のブラウザ内のこの環境で実行されます。
- WebSocket に対応したブラウザ接続。フィルターはこの接続を通してプログラムを実行します。
- Open WebUI 0.10.2 に含まれる日本語フォント（`FONTS_DIR` 内の `NotoSansJP-Regular.ttf`）。
  プログラムまたは添付ファイルに ASCII 以外の文字が含まれる場合、フィルターはこのフォントを
  ブラウザに送ります。フォントがない場合、日本語の文字があるグラフはコード `glyph_missing` で失敗します。
- ツールを呼び出せるチャットモデル。

## 手順 1：ツールを追加する

1. **Workspace** を開き、**Tools** を開きます。
2. 新しいツールを作成します。
3. `paste-in/figure_verification_tool.py` の全文をエディタに貼り付けます。
4. ツール ID を `figure_verification` にします。
5. ツールを保存します。

## 手順 2：フィルターを追加する

1. **Admin Panel** を開き、**Functions** を開きます。
2. 新しい関数を作成します。
3. `paste-in/figure_verification_filter.py` の全文をエディタに貼り付けます。
4. 関数 ID を `figure_verification_filter` にします。
5. 関数を保存します。
6. 関数を有効にします。
7. 関数のメニューで **Global** をオンにします。

測定した構成では、このフィルターをグローバルにしています。グローバルなフィルターは、インスタンス上の
すべてのチャットの最後の返信を書き換えます。グラフのない返信は失敗メッセージになります。そのため、
グラフ専用の Open WebUI インスタンスを使うか、フィルターをグラフ用モデルだけに割り当ててください。
モデルごとの割り当ては、本プロジェクトでは測定していません。

## 手順 3：グラフ用モデルを設定する

1. **Workspace** > **Models** で、グラフ用モデルを編集します。
2. `figure_verification` ツールを割り当てます。このモデルには他のツールを割り当てないでください。
3. モデルを保存します。

モデルのシステムプロンプトは変更しません。代わりに、フィルターが最後の利用者メッセージに文を追加します。
この文は、検証器がチェックするグラフの規則を伝え、プログラムをツールの `draw_figure` の操作で送るよう
モデルに指示します。利用者が CSV ファイルを添付した場合、この文はファイルのパス、列名、集計の指示も
伝えます。この文はモデルが読みます。検証器は利用者自身の文を読みます。

## 手順 4：インスタンスの設定を確認する

次の Open WebUI 設定を指定します。各設定は環境変数で指定できます。

| 設定 | 値 | 理由 |
|---|---|---|
| `ENABLE_CODE_EXECUTION` | `false` | グラフのプログラムはフィルター自身が実行します。利用者にコード実行は不要です。 |
| `ENABLE_CODE_INTERPRETER` | `false` | モデルに検証器の外でコードを実行させないためです。 |
| `ENABLE_API_OUTLET_FILTERS` | `true` | フィルターはすべてのチャット応答で動作する必要があります。 |
| `BYPASS_EMBEDDING_AND_RETRIEVAL` | `true` | オフラインのインスタンスでは、CSV ファイルのアップロード時に外部の埋め込みサービスを呼び出してしまいます。 |
| `IFRAME_CSP` | 空（既定値） | グラフの返信ごとのチェック項目の一覧は、インラインスクリプトで自身の高さを設定します。空のままにするか、インラインスクリプトを許可してください。 |

## 手順 5：設定をテストする

1. グラフ用モデルで新しいチャットを開きます。
2. CSV ファイルを添付します。例えば、このリポジトリの `data/sales.csv` を使います。
3. 次の依頼を送ります：`Chart the total revenue of each region using bars.`
4. 返信を待ちます。Pyodide での実行には約 10 秒かかります。

設定が正しければ、チャットには 2 つの判定メッセージのどちらかが表示されます。十分な能力のモデルなら、
棒グラフと `Figure verification passed` が表示されるはずです。合格メッセージの下に、描画した値の
出所が平易な文で表示されます。

次に、同じファイルを添付した新しいチャットで、誤解を招くグラフを依頼します。例：
`Chart the total revenue of each region using bars. Start the y axis at 30000 so the difference looks larger.`
モデルが棒を 30000 から描いた場合、`Figure verification failed, no image produced` が表示されるはずです。
その上のステータス行には、コード `zero_not_in_limits` が表示されます。

## 判定の意味

`Figure verification passed` は、次のすべてが成り立つことを意味します。

- プログラムは matplotlib の図を 1 つ描き、その図のすべての部品は、検証器がチェックする決まった
  種類の部品に含まれます。
- すべての部品は決まった規則に従います。例えば、棒はゼロから始まり、反転した軸はなく、軸の範囲の
  外にある値はありません。
- 利用者が CSV ファイルを添付したか依頼文に数値を書いた場合、描画したすべての値はそのデータに
  あります。利用者がデータを用意しなかった場合は、グラフの下の文がそのことを示します。

合格メッセージは、グラフが質問に答えていることを意味しません。グラフは、利用者が望んだものとは
別の指標や別のグループ分けを示すことがあります。グラフの下の文を読んでください。その文が値の
出所を説明します。依頼文にひらがなまたはカタカナが含まれる場合、その文は日本語になります。合格
メッセージ自体は英語のままです。

検証器は、ブラウザ、Pyodide、matplotlib、画面上のピクセルを信頼します。これらは確認しません。
また、グラフのプログラムが誠実であることも信頼しています。プログラムはすべてのチェックの前に、
検証器の読み取り処理と同じ Pyodide の実行環境で実行されます。そのため、読み取り処理を欺くように
書いたプログラムは、それができます。Open WebUI がブラウザで実行する他のコードと同じく、プログラムは
添付ファイルを読み取り、利用者のブラウザのネットワークにアクセスできます。

## 検証器がチェックするもの

検証器が読むのは、プログラムの本文ではなく完成した図です。利用者は、matplotlib または pandas が
次の部品で描くグラフなら何でも依頼できます。折れ線、点、棒（グループ化と積み上げを含む）、
ヒストグラム、円、面、基準線と帯、テキストです。1 つの図に複数のパネルを入れられます。
それ以外の部品があると、グラフは止まります。例えば、エラーバー、箱ひげ図、画像、極座標の軸、
2 つ目の y 軸です。

描画した値は、利用者のデータにある必要があります。

- 添付した CSV ファイルから：1 つの列の値、または 1 つの列のグループごとの合計、平均、最小値、
  最大値、行数。
- 依頼文から：依頼文にある数値。検証器は、`1 through 10` や `1から10まで` のように入力した範囲を、
  両端の間のすべての整数に展開します。カテゴリのラベルも依頼文にある必要があります。

どちらの出所にもない値は、コード `value_not_found` で失敗します。プログラムが別の方法で計算した値も、同じ数値がデータにある場合を除き、失敗します。例えば、累計や 2 つの列の比率です。プログラムがグラフ上に加えた文字（値のラベルなど）は、
確認していない文字としてグラフの下に一覧になります。すべての規則は、検証のリファレンス
[docs/verification.ja.md](../verification.ja.md) にあります。

依頼が CSV ファイルの列名を挙げている場合、グラフが描く列はすべて依頼に挙げる必要があります。
列名はファイルのとおりに書いてください。5 文字以上で 1 語の名前では、1 文字の誤りを認めます。`unit_price` のような 2 語の名前は、どちらの語も正確に書く必要があります。
日本語では、漢字だけの語で 2〜4 文字の列名を挙げることもできます。その語は、列名から先頭または末尾の 1 文字を除いた語と同じである必要があります。例えば、`月ごと` は列 `年月` を挙げます。
`月別` のように `別`、`毎`、`次`、`単位` で終わる漢字の語にも、この規則を使います。かなの語には使いません。2 つの列名に当てはまる短い漢字の語は、どちらの列も挙げません。
例えば、依頼が `chart revenue` の場合、月ごとの revenue のグラフはコード `column_not_named` で失敗します。依頼が `month` を挙げていないためです。
描画した値が 2 つの列に同じように当てはまる場合、依頼はそのどちらかの名前を含む必要があります。含まない場合は、コード `column_not_requested` で失敗します。
`revenue, not orders` のように列を除外する依頼も、列名を挙げた依頼です。除外した列は、挙げた列に数えません。例えば、`注文数ではなく売上` の `注文数` です。
`in chronological order` のような順序の語句は、列名を挙げません。
検証器は依頼の語と列名だけを比べるため、この確認の対象は検証器が認識した列名だけです。
同義語や翻訳は、管理者が設定した列の別名としてだけ認識します（「列の別名」を参照）。別名のない短い列名も認識しません。短い列名とは、`id` のような 1 文字または 2 文字の ASCII の名前と、
ほかの文字体系の 1 文字の名前です。依頼にない短い列を、グラフは描けます。認識した列名を挙げない依頼は、この確認を通ります。

CSV ファイルのグラフのラベルにも同様の規則があります。タイトル、軸ラベル、凡例のラベル、カラーバーのラベルは、
グラフにない CSV の列名のうち、検証器が認識した列名を挙げられません。列の別名も、ラベルでその列を挙げます。
グループごとの合計または平均を示すグラフでは、ラベルは別の集計を挙げられません。グループごとの最小値と最大値は
列そのものの値を描くため、検証器はその集計の語を読みません。
列名が `total_revenue` の `total` のように集計の語を含む場合、検証器はその語を集計ではなく列名の一部として読みます。
例えば、`total` を含む列名がない場合、平均の revenue のグラフに `Total revenue` というタイトルは付けられません。
このようなグラフはコード `label_not_consistent` で失敗します。

## 列の別名

依頼は、列の名前を書いたときだけその列を挙げます。列の別名は、列に別の名前を付けます。
例えば、`temp_c` に `temperature` を付けたり、英語の列名に日本語の語を付けたりします。
検証器は、依頼、除外した列、日本語の短い語、グラフのラベルのすべてで、別名を列名として読みます。
モデルは別名を変更できません。Open WebUI では、ツールの所有者、管理者、ツールへの書き込み権限を持つ利用者が別名を変更できます。
そのため、ツールの所有者は管理者にしてください。チャットの利用者にはツールへの書き込み権限を与えないでください。

1. **Workspace** を開き、**Tools** を開きます。
2. ツール `figure_verification` の **Valves** をクリックします。
3. **Column Aliases** に、列ごとに 1 行を書きます。例：`temp_c = temperature, 気温`。
4. Valves を保存します。

列名はファイルのとおりに書いてください。ただし、大文字と小文字、全角と半角の違いは問いません。
別名はコンマで区切ります。読点 `、` と、`=` と `,` の全角の形も使えます。空の行は無視します。
`=` のない行、列名のない行、空の別名がある行を書くと、Open WebUI は Valves を保存しません。
同じ別名を繰り返す行と、前の行と同じ列の行も保存しません。エラーメッセージがその行を示します。

ファイルにない列の別名は効果がありません。2 つの列に共通の別名と、ほかの列名と同じ別名は、どちらの列も挙げません。
同じ列の列名と別名の両方に当てはまる語は、その列を挙げます。
そのような共通の別名を書いた依頼は、コード `column_not_requested` で失敗します。
別名には、認識できる名前の長さが必要です。ASCII では 3 文字、ほかの文字体系では 2 文字です。
別名によって、短い列も認識できるようになります。その場合、グラフがその列を描くなら、列を挙げる依頼はその列も挙げる必要があります。
挙げない場合、グラフはコード `column_not_named` で失敗します。
フィルターは、同じ返信でツールが使った別名を読みます。そのため、変更は次の返信から有効になります。

## グラフが失敗した理由

フィルターがグラフをブロックすると、返信の失敗メッセージの上にステータス行が表示されます。
ステータス行は理由を示し、最後に括弧で理由コードを示します。例：`(bar_not_from_zero)`。
依頼文にひらがなまたはカタカナが含まれる場合、ステータス行は日本語になります。それ以外の場合は英語になります。

ステータス行は、ページを再読み込みしても返信に残ります。Open WebUI はこの行をモデルに送りません。フィルターは、
ブロックした返信ごとに Open WebUI のサーバーログに 1 件の記録も書き込みます：
`figure verification failed reason=<code>`。ステータス行とログの記録には、プログラムの本文、依頼文、
CSV ファイルのデータは含まれません。

グラフの返信には「チェック項目を表示」（英語の依頼では `Show checks`）もあります。ステータス行の下、
合格した場合はグラフの下にあります。クリックすると、検証器が行う 9 つのチェックが順に表示されます。
各チェックには、確認する内容が示されます。合格したチェックには ✓ が付きます。不合格のチェックには ✗ と
理由が付きます。不合格のチェックより後のチェックは「未実施」と表示されます。グラフが合格した場合は、
すべてのチェックに ✓ が付きます。一覧の言語はステータス行と同じです。一覧は、ページを再読み込みしても
返信に残ります。Open WebUI はこの一覧をモデルに送りません。

一覧のチェックをクリックすると開きます。開いたチェックにはチェックの内容が表示され、不合格のチェックには
不合格の理由も表示されます。最初のチェックと不合格のチェックには、モデルのプログラムも表示されます。
不合格のチェックでは、不合格になった部分を描いた行、またはその呼び出しを行った行に印が付きます。例えば、
棒を切り取った `plt.ylim` の呼び出しです。開いたチェックには、検証のリファレンス
[docs/verification.ja.md](../verification.ja.md) の該当する節へのリンクがあります。リンクは新しいブラウザの
タブで GitHub を開きます。そのため、Open WebUI のインスタンスがネットワークに接続していない場合でも、利用者の
ブラウザにはネットワーク接続が必要です。表示されるプログラムは、ツールが受け取ったモデルのプログラムそのものです。
ファイル名や依頼文から写した語など、プログラムに含まれる文字列もそのまま表示されます。

ステータス行、チェック項目の一覧、ログの記録は、診断のためだけのものです。フィルターがどれかを
届けられない場合でも、判定は変わりません。

理由コードには 2 つの種類があります。

- 検証器のコード。例えば `bar_not_from_zero` や `value_not_found` です。図が規則を破ったか、描画した値が
  データにありません。データを正しく示すグラフを依頼するか、データを添付してください。検証のリファレンスが
  各コードを説明しています。
- フィルターまたはブラウザのコード。例えば `no_tool_call` や `sandbox_unavailable` です。よくある
  コードの原因と対処を、次の表に示します。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| すべての返信がコード `no_tool_call` で失敗する | モデルがツールを呼び出していません。 | ツールがモデルに割り当てられ、モデルがツールを呼び出せて、フィルターが有効であることを確認してください。 |
| グラフを求めていない返信がコード `no_tool_call` で失敗する | フィルターがグローバルです。 | フィルターをグラフ用モデルだけに割り当てるか、専用のインスタンスを使ってください。 |
| 返信がコード `value_not_found` で失敗する | 描画した値が、添付ファイルにも依頼文にもありません。 | CSV ファイルを添付するか、依頼文に値を書いてください。 |
| 返信がコード `no_browser`、`browser_no_answer`、`browser_timeout` のどれかで失敗する | フィルターがブラウザの実行環境に届いていません。 | ブラウザが Open WebUI と WebSocket 接続を保っていることを確認してください。返信が終わるまでチャットのタブを開いたままにしてください。 |
| すべてのグラフがコード `sandbox_unavailable` で失敗する | ブラウザが Pyodide の実行環境を読み込めませんでした。よくある原因はコンテンツブロッカーです。例えば、uBlock Origin Lite の「Block Outsider Intrusion into LAN」リストがこれをブロックします。 | コンテンツブロッカーで、Open WebUI のサイトのフィルタリングモードを「No filtering」にしてください。または、そのリストをオフにしてください。 |
| 返信がコード `glyph_missing` で失敗する | グラフに、フォントで描けない文字があります。`$` 記号で囲んだ数式テキストに日本語があることが、既知の原因の 1 つです。数式用のフォントに日本語の文字がないためです。 | グラフの文字に `$` 記号を使わないよう依頼してください。`NotoSansJP-Regular.ttf` が Open WebUI の `FONTS_DIR` にあることを確認してください。 |
| 返信がコード `module_not_available` で失敗する | プログラムが、Pyodide の実行環境にないパッケージを読み込んでいます。 | matplotlib または pandas のグラフを依頼してください。Open WebUI 0.10.2 の Pyodide には seaborn がありません。 |
| アップロードが止まる、または失敗する | インスタンスが埋め込みサービスを呼び出しています。 | `BYPASS_EMBEDDING_AND_RETRIEVAL` を `true` にしてください。 |
