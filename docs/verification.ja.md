# 図の検証: 検証器がチェックする内容

このリファレンスでは、図の検証器が Open WebUI で実行するチェックについて詳しく説明します。`main`
ブランチの現在のリリースが対象です。概要は、簡単なガイド [checks.ja.md](checks.ja.md) をお読み
ください。グラフの返信の下にある **チェック項目を表示** の各行はそのガイドの対応する節にリンクし、
ガイドの各節はここにある対応する節にリンクしています。英語版は [verification.md](verification.md)
をお読みください。

## 検証済みの図の意味

言語モデルが、matplotlib でグラフを描く Python のプログラムを書きます。ブラウザは、そのプログラムを
変更せずに Open WebUI の Python サンドボックス (Pyodide) で実行します。その後、検証器が完成した
図を読み取り、グラフを表示してよいかを判断します。すべてのチェックに合格した場合に限り、返信に
グラフと `Figure verification passed` が表示されます。それ以外の場合、返信には
`Figure verification failed, no image produced` とその理由が表示されます。最後のメッセージに
ひらがなまたはカタカナが含まれる場合、これらのメッセージは日本語の `図の検証に合格しました。` と
`図の検証に合格しませんでした。画像は表示されません。` になります。

検証器は、次の 3 種類の保証を提供します。

1. **完全性。** 図のすべての部品は、検証器がチェックする決まった種類の部品に含まれます。すべての
   部品は決まった規則に従います。たとえば、棒はゼロから始まり、数値と日付の軸は反転していません。
2. **出所。** CSV ファイルを添付するか依頼文に数値を書いた場合、描画したすべての値はそのデータ、
   またはその認められた計算結果です。見つからない値があると、グラフは表示されません。
3. **解釈。** 合格した返信では、描画した各値の出所を平易な言葉で示します。ファイル、列、
   グループごとの集計、行数です。名前、セルの値、ファイル名、グラフ上の文字は、書かれたとおりに
   コードとして表示されます。そのため、それらの文字が返信にリンク、画像、書式を加えることは
   ありません。

検証器は、グラフが質問に答えていることは保証しません。グラフが正しい値を示していても、意図とは
別の量である場合があります。たとえば、平均が必要なのに合計を示している場合です。グラフの下の
解釈を読んで、検証器がチェックした内容を確認してください。

すべての判断は決まった規則に従います。検証器はモデルも推測も使いません。ブラウザ、Pyodide の
サンドボックス、matplotlib、画像のピクセルは信頼しており、検証はしません。

## 値の出所

依頼文とは、この会話であなたが書いたすべてのメッセージです。このグラフを依頼したメッセージまでを
含みます。そのため、`棒を赤にして` のような続きの依頼でも、前のメッセージの列名と数値が使われます。
メッセージを編集すると、Open WebUI は会話の新しい分岐を作ります。他の分岐のメッセージは数えません。
検証器が保存された会話を読み取れない場合、依頼文は最後のメッセージだけです。たとえば、一時チャット
では Open WebUI がメッセージを保存しません。

検証器は、描画した値をあなたが用意したデータと比べます。

- **添付した CSV ファイル。** 描画した各値は、1 つの列の値、または 1 つの列のグループごとの集計
  である必要があります。集計は合計、平均、最小値、最大値、行数のいずれかです。グラフは一部の行
  だけを描くこともできます。その場合、返信は描いた件数を示します (たとえば `6 件中 2 件を描画`)。
- **依頼文の数値。** 描画した各値は、依頼文にある数値である必要があります。検証器は、入力した
  範囲を両端の間のすべての整数に展開します。`1 through 10`、`1 to 10`、`1–10`、`1〜10`、
  `1から10まで` は、いずれも 1 から 10 までの数値になります。`1-10` のような通常のハイフンは
  範囲になりません。日付や負の数がハイフンを使うためです。1 つの依頼文の範囲から得る数値は合計
  10,000 個までで、それを超える範囲は両端の 2 つの数値だけになります。カテゴリのラベルも依頼文に
  ある必要があります。
- **データの計算結果。** 描画した値は、CSV の系列、2 つの列、または依頼文の数値の 1 つの計算結果で
  あってもかまいません。次の節に一覧があります。
- **データなし。** ファイルを添付せず、数値も書かない場合、検証器はグラフの完全性だけを
  チェックします。返信にもそのことが示されます。

両方の出所がある場合、各値はどちらの出所から来てもかまいません。たとえば、ファイルの合計を描き、
入力した数値の位置に目標線を引くことができます。

検証器は、`pandas.read_csv` と同じ方式で CSV ファイルを読み取ります。値は数値誤差を認めずに
完全に一致するかを比べます。ファイルの 1 行は、描画した値の 1 つだけを裏付けます。

### 計算した値

描画した値は、データの 1 つの計算結果であってもかまいません。検証器が認める計算は、この表の
計算だけです。それぞれ、CSV ファイルの 1 つの系列、2 つの数値の列、または依頼文の数値に使えます。

| 計算 | 例 | 偶然の一致、CSV ファイル | 偶然の一致、依頼文の数値 |
|---|---|---|---|
| 2 乗 | `df["x"] ** 2` | 0 / 0 / 0 | 1,055 / 239 / 25 |
| 累計 | `s.cumsum()` | 52 / 0 / 0 | 971 / 321 / 91 |
| 前の点からの変化 | `s.diff()` | 99 / 1 / 0 | 296 / 8 / 0 |
| 合計に対する割合 | `s / s.sum()` | 416 / 284 / 262 | 495 / 29 / 0 |
| 合計に対する百分率 | `100 * s / s.sum()` | 65 / 0 / 0 | 253 / 19 / 1 |
| 2 つの列の比率 | `df["a"] / df["b"]` | 13 / 0 / 0 | なし |
| 2 つの列の差 | `df["a"] - df["b"]` | 54 / 0 / 0 | なし |
| 2 つの列の積 | `df["a"] * df["b"]` | 2 / 0 / 0 | なし |
| 2 つの列の和 | `df["a"] + df["b"]` | 31 / 0 / 0 | なし |

偶然の一致の列は、測定 X1 の結果です。作った系列 10,000 件のうち、その計算だけを通って合格する
件数を、1 点、2 点、3 点以上の系列について示します。CSV ファイルの値はデモのファイルによるもので、
そのキーの列には最大 4 つのカテゴリしかありません。割合の行は、0 から 2 までの整数で高くなります。
小数 2 桁の値では 43 / 1 / 0 です。

計算した値には、次の規則があります。

- 系列は、上に挙げた 1 つの列、グループごとの集計 1 つ、またはグループごとの行数です。
- 2 つの列の計算は、各行、または各グループの列の合計に対して行います。
- 検証器は、numpy、pandas、Python が計算する方法で、各計算を完全に再現します。たとえば、合計は
  `s.sum()`、`sum()`、`groupby().sum()` のいずれから来てもかまいません。
- プログラムが丸めた値、拡大した値、別の方法で計算した値は、グラフを止めます。同じ数値がデータ、
  またはその認められた計算結果にある場合は除きます。
- 検証器は、計算なしでグラフが失敗する場合にだけ計算を使います。そのままの値で合格するグラフは、
  その読み方のままです。
- 計算した値の探索には、`MAX_WORK` と同じ大きさの専用の作業上限があります。上限を超えた場合、
  グラフは最初の探索の結果のままです。
- 基準線と帯には計算を使いません。
- 検証器は、依頼文の数値を入力した順に使います。年などを含むすべての数値が対象です。一覧について
  計算する場合は、その一覧か 1 つの範囲だけを入力してください。

特別な場合:

- **凡例が名前を付けた系列。** 凡例が列の値で系列に名前を付けた場合 (たとえば `city` 列の
  `London`)、その系列はその値を持つ行から作られている必要があります。
- **基準線と帯。** `axhline`、`axvline`、`axhspan`、`axvspan` の各値は、ゼロ、依頼文の数値、
  数値の列の値、または列全体の集計のいずれかである必要があります。
- **マーカーの色と大きさ。** カラーバーや凡例が散布図のマーカーの色や大きさを示す場合、その値も
  描画した値として扱います。各値は、そのマーカーと同じ行またはグループから来ている必要があります。
- **円グラフのラベル。** 検証器は、各扇形のラベルをグラフに表示されたとおりに読み取ります。

## 「チェック項目を表示」の見方

**チェック項目を表示** は、9 つのチェックを実行する順に一覧にします。各行は次の 3 つの状態の
いずれかを示します。

- ✓ **合格**: チェックが完了しました。
- ✗ **不合格**: このチェックで図が止まりました。行に理由が表示されます。
- – **未実施**: 前のチェックが不合格だったため、このチェックは実施していません。

行をクリックすると開きます。開いた行には、チェックの内容、不合格の理由、簡単なガイドへの
リンクが表示されます。チェックに関連するプログラムの行も表示されます。

- **モデルからグラフのプログラムを受信**: プログラム全体。
- **ブラウザでプログラムを実行**: プログラムが最後まで実行されたという注記。実行が不合格の場合は、
  エラーを起こした行、またはプログラム全体が表示されます。
- **図を 1 つ描画**: 図を作った行と、図の文字列または目盛りの見た目を設定した行。
- **検証器がチェックできる部品だけを使用**: 図の部品を描いた各行。
- **正しい軸**: 軸を作った行、軸のタイトルとラベルを設定した行、範囲・目盛りの種類・反転・目盛りを
  設定した呼び出し。`plt.xticks(rotation=45)` や `ax.tick_params` など、目盛りの見た目を設定する
  呼び出しも含みます。検証器は、`plt.setp` や `fig.autofmt_xdate()` など、目盛りラベルを変えるほかの
  呼び出しを表示しません。
- **正しいグラフ要素**: グラフ要素と凡例を描いた行。
- **描画した値があなたのデータにある**: グラフ要素を描いた行と、そのデータを準備できる前の行
  (`pd.read_csv` や `groupby` など)。
- **描いた列が依頼と一致**: 値の行に表示される行と、タイトル、軸ラベル、凡例を設定した行。
- **返信に画像を添付**: このチェックに関わるプログラムの行はないという注記。

表示される各行は、文全体と、その周りの `for`、`if`、`with`、`try`、`match` の行を含みます。
これは、プログラムが 65,536 文字以内で、Python として読み取れる場合です。それ以外の場合、行には
記録された行だけが表示されます。一覧に表示されるのは最大 60 行、3,000 文字までで、1 行は 400 文字で
切り詰められ、表示していない行の数が示されます。実施していない行には、プログラムの行は表示されません。不合格の行では、不合格になった部分を描いた行、またはその
呼び出しを行った行に印が付きます。たとえば、棒を切り取った `plt.ylim` の呼び出しです。関連する行が
ない不合格の行には、プログラム全体が表示されます。不合格の原因となった行がない場合、印は付きません。

検証器は、データを準備した行をプログラムの文字列だけから見つけます。描画した行が使う名前を、
その名前を設定または変更できる前のすべての行までさかのぼります。別の経路で値を設定する行
(`except` の代替処理など) は、実行されなかった場合も表示されます。行を見落とす場合もあります。
たとえば、関数が呼び出し元から受け取る引数です。非常に長いプログラムでは、途中で探索を止める場合が
あります。これらの行は表示のためだけのもので、結果を変えることはありません。

一覧には、モデルが送ったとおりのプログラムが表示されます。プログラムが持つ任意の文字列が含まれる
場合があります。たとえば、ファイル名や依頼文から写した語です。制御文字のように見えない文字は、
見える記号で表示されます。

## チェック

<a id="check-program"></a>

### 1. モデルからグラフのプログラムを受信

モデルは、グラフ用のツールを呼び出して 1 つの Python のプログラムを送る必要があります。返信の
文章として書いたプログラムはグラフになりません。図を作れるのは、ツールで送ったプログラムだけです。
1 つの返信でモデルがツールを複数回呼び出した場合、検証器は最後のプログラムをチェックします。

| 理由 | 意味 |
|---|---|
| `no_tool_call` | モデルからグラフのプログラムが届きませんでした。 |
| `no_user` | サインインしているユーザーがいません。 |

<a id="check-run"></a>

### 2. ブラウザでプログラムを実行

ブラウザは、モデルのプログラムを変更せずに Open WebUI のサンドボックス (Pyodide) で実行します。
検証器が加えるのは外側の処理だけです。完成した図を記録し、PNG 画像を 1 枚保存します。正しい Python ではないプログラムは、Python 自体が拒否します。プログラムが読み込めるのは、numpy、pandas、
matplotlib、seaborn と Python の標準ライブラリです。検証器は、プログラムの実行前に numpy、pandas、matplotlib を読み込みます。プログラムが seaborn の名前を含む場合は、seaborn も読み込みます。プログラムまたは添付ファイルに日本語が
含まれる場合、検証器は Open WebUI サーバーの日本語フォントもプログラムと一緒に送ります。プログラムの
実行中は、チャットのタブを開いたままにしてください。検証器は、Open WebUI の分離されたサンドボックスにだけ
プログラムを送ります。Pyodide のファイル保存がオンの場合、Open WebUI はサインインしているユーザーの
権限でプログラムを実行します。その場合、実行は `sandbox_not_isolated` で失敗します。

| 理由 | 意味 |
|---|---|
| `no_browser` | プログラムを実行できるブラウザのセッションがありません。 |
| `sandbox_not_isolated` | あなたの権限で動きます。管理者が Pyodide のファイル保存をオフにする必要があります。 |
| `browser_timeout` | ブラウザが 60 秒以内に応答しませんでした。タブを前面に表示して、もう一度送ってください。 |
| `browser_error` | ブラウザの呼び出しに失敗しました。 |
| `browser_no_answer` | チャットのタブが応答しませんでした。タブを開いたままにして、もう一度試してください。 |
| `reply_malformed` | ブラウザの応答の形式が不明です。 |
| `sandbox_unavailable` | Pyodide を読み込めません。このサイトの広告ブロッカーをオフにしてください。 |
| `sandbox_error` | ブラウザの実行環境がエラーを報告しました。 |
| `no_description` | ブラウザが描画した図を報告しませんでした。 |
| `program_syntax_error` | プログラムが正しい Python ではありません。 |
| `program_error` | プログラムがエラーで停止しました。 |
| `module_not_available` | プログラムが、サンドボックスにないモジュールを読み込んでいます。 |
| `figure_too_large` | 図が大きすぎるため、チェックできません。 |

<a id="check-figure"></a>

### 3. 図を 1 つ描画

プログラムは matplotlib の図をちょうど 1 つ描く必要があります。pandas と seaborn のグラフも matplotlib の図で、その部品には同じチェックが適用されます。seaborn の棒グラフと折れ線グラフは、既定ではエラーバーまたは信頼区間の帯も描きます。検証器はこれらを独立したマークとしてチェックするため、図は不合格になります。これらを含まないグラフ (`errorbar=None`) を依頼してください。検証器は `sns.histplot` の度数を説明しないため、このような図も不合格になります。`plt.hist` は同じヒストグラムを描き、検証器はその度数をチェックします。モデルが受け取るグラフのルールは、この両方を求めます。1 つの図には、`plt.subplots` で作った複数のパネルを入れられます。使用できる
フォントで、図のすべての文字を描ける必要があります。検証器が送るのは
日本語フォントの一部だけです。この一部には、ASCII、マイナス記号、プログラムのテキストと
添付ファイルの文字が含まれます。フォントファイルを切り出せない場合（可変フォントや、埋め込み
ビットマップのあるフォントなど）、検証器はフォント全体を送ります。
使用できるどのフォントにもない文字を描くと、図は `glyph_missing` で失敗します。たとえば、
検証器がフォントの一部を送り、プログラムのテキストにも添付ファイルにもない日本語の文字を、プログラムが `chr(0x6708)` で作る場合です。
検証器自体が、実行結果の報告を読む途中や図のチェック中にエラーで停止した場合、図は `verifier_error` で失敗します。

| 理由 | 意味 |
|---|---|
| `no_figure` | プログラムが matplotlib の図を描いていません。 |
| `multiple_figures` | プログラムが複数の図を描きました。 |
| `glyph_missing` | 図に、使用できるフォントで描けない文字があります。 |
| `verifier_error` | 検証器が内部エラーで停止したため、チェックを完了できませんでした。 |

<a id="check-parts"></a>

### 4. 検証器がチェックできる部品だけを使用

図の各部品は、検証器がチェックできる種類である必要があります。各パネルは通常の軸を使う必要が
あります。検証器は各パネルを個別にチェックします。チェックできる部品は次のとおりです。

| 部品 | 作り方 |
|---|---|
| 折れ線 | `plot`、`step` |
| 点 | `scatter` |
| 棒 | `bar`、`barh`、グループ化した棒と積み上げた棒 |
| ヒストグラム | 塗りつぶした棒と 1 つのデータセットの `hist` |
| 円 | `pie` とそのラベル |
| 面 | `fill_between`、`stackplot` |
| 基準線と帯 | `axhline`、`axvline`、`axhspan`、`axvspan` |
| テキスト | タイトル、軸ラベル、凡例、目盛りのラベル、`text`、`annotate`、`bar_label` |
| インクのない凡例のキー | 幅と高さが 0 の `Rectangle`、または点のない `Line2D` で、プログラムがパネルに自分で追加し、そのパネル自身の凡例が使うもの（seaborn は `hue` の値ごとに 1 つ加えます）。何も描かず、系列ではありません |

それ以外の部品があると、図は止まります。たとえば、エラーバー、箱ひげ図、等高線、プログラムが
自分で追加したほかの図形です。画像、極座標や 3D の軸、挿入図、2 つ目の y 軸、重なるパネルでも図は
止まります。カラーバーを使えるのは、散布図の色を示す場合だけです。

| 理由 | 意味 |
|---|---|
| `raster_image` | 図に画像が含まれています。検証器は画像をチェックできません。 |
| `axes_not_judged` | 図に、検証器がチェックできない軸 (極座標、3D、挿入図など) があります。 |
| `axes_twin` | 1 つのパネルに 2 つの軸があります (2 つ目の y 軸など)。 |
| `axes_overlap` | 2 つのパネルが重なっています。 |
| `artist_not_judged` | 図に、検証器がチェックできないグラフ要素があります。 |
| `no_data` | データを表示していないパネルがあります。 |

<a id="check-axes"></a>

### 5. 正しい軸

各軸はデータを正しく示す必要があります。

- **データ座標。** 各部品は、軸上のデータの値の位置にあります。
- **線形の目盛り。** 軸は線形です。対数軸は、軸ラベルかパネルのタイトルに `log`、
  `logarithmic`、`対数` のいずれかがある場合に限り認めます。それ以外の目盛りでは図は止まります。
- **反転した目盛りなし。** 値は y 軸では上へ、x 軸では右へ増えます。テキストのカテゴリの軸は、
  たとえば最も大きい棒を上に表示するために反転できます。これはデータを並べ替えた場合と同じく
  カテゴリを逆の順に並べるだけで、値は動きません。数値または日付の軸が反転していると、図は止まります。
- **棒、ヒストグラム、面の値の軸にゼロ。** これらのグラフの値の軸はゼロを含みます。棒の長さが
  値を示すためです。折れ線と散布図は、データに合わせて拡大できます。
- **正しい目盛りラベル。** 表示されている各目盛りのラベルは、その位置の値を示します。カテゴリの
  軸はカテゴリを、日付の軸は日付を示します。
- **範囲外のデータ点なし。** 描画したすべての点、棒の端、基準線は、軸の範囲の中にあります。
  移動平均の最初の点のような欠損値があるパネルは、代わりに次のチェックで失敗します。
  matplotlib はその点を除いて軸の範囲を決めるためです。

| 理由 | 意味 |
|---|---|
| `mark_not_in_data` | データの値の位置にない部品があります。 |
| `scale_not_linear` | 線形でない軸があり、対数と示すラベルがありません。 |
| `axis_inverted` | 反転している軸があります。 |
| `zero_not_in_limits` | 棒グラフ、ヒストグラム、面グラフの値の軸にゼロが含まれていません。 |
| `tick_label_mismatch` | 目盛りのラベルが、その位置の値を示していません。 |
| `point_clipped` | 軸の範囲の外にあるデータ点があります。 |

<a id="check-marks"></a>

### 6. 正しいグラフ要素

各部品は値を正しく示す必要があります。

- **見える値。** すべての部品とパネルは表示されており、描画した値に欠損値や無限大はありません。
  部品が受け取ったのに表示しない点があると、図は止まります。
- **ゼロから始まる棒。** 各棒はゼロから始まるか、積み上げの中で別の棒の上から始まります。
- **重ならない棒。** グループ化した棒は横に並びます。
- **正しいヒストグラム。** ヒストグラムの棒は、ビンごとのデータの度数または密度を示します。
- **全体がそろった円。** 円グラフの扇形は円を満たし、各扇形は合計に対する割合を示します。
- **ゼロから始まる面。** 各面はゼロから始まるか、積み上げの中で別の面の上から始まります。
- **順序どおりの折れ線。** 折れ線の x の値は一方向に進みます。
- **説明のある大きさと色。** マーカーの大きさや色が異なる場合、大きさの凡例、色の凡例、または
  カラーバーが必要です。大きさの凡例には、`ax.scatter([], [], s=80, label="80")` のように
  プログラムが点のない散布図として描いたキーも使えます。各キーの大きさはグラフが描く大きさで
  ある必要があり、ラベルはその大きさを数値で示す必要があります。凡例は大きさのキーを点と同じ
  大きさで描く必要があります。`markerscale` が 1 以外の凡例では、図は止まります。
- **正しい凡例。** 凡例の各項目は、グラフの系列を示します。凡例のあるパネルに系列が 2 つ以上
  ある場合、凡例はすべての系列を示します。プログラムがパネルに加えた、インクのない凡例のキー
  （seaborn は `hue` の値ごとに 1 つ加えます）は、自分のラベルを表示しない、その色の 1 つの系列を
  示します。プログラムが 1 つの塗りつぶした面の、ゼロではない側の縁に描いた線は、その面の一部です。
  そのため、その線の凡例の項目は、その面を示します。2 つの面が共有する縁の線は、どちらの面も
  示しません。

| 理由 | 意味 |
|---|---|
| `mark_hidden` | 非表示のグラフ要素やパネル、または何も見えないグラフ要素があります。 |
| `value_not_finite` | 描画する値に欠損値や有限でない値があるか、点が欠落しています。 |
| `bar_not_from_zero` | ゼロから始まっていない棒があります。 |
| `bars_overlap` | 重なっている棒があります。 |
| `x_not_ordered` | 折れ線の x の値が順序どおりではありません。 |
| `hist_counts` | ヒストグラムの棒が、データの度数を示していません。 |
| `pie_not_whole` | 円グラフの扇形が、値の割合を示していません。 |
| `area_not_from_zero` | ゼロからも他の面からも始まっていない面があります。 |
| `marker_size_varies` | マーカーの大きさが異なりますが、大きさの凡例がありません。 |
| `marker_color_varies` | マーカーの色が異なりますが、カラーバーも色の凡例もありません。 |
| `legend_mismatch` | 凡例がグラフの系列を正しく示していません。 |

<a id="check-values"></a>

### 7. 描画した値があなたのデータにある

検証器は、[値の出所](#値の出所) のとおりに、描画した各値をあなたのデータと比べます。1 つの系列で
同じカテゴリを 2 回示すことはできません。一方の値がもう一方を隠すためです。

| 理由 | 意味 |
|---|---|
| `csv_too_large` | CSV ファイルが大きすぎます。 |
| `csv_not_parsable` | CSV ファイルを読み取れません。 |
| `work_budget_exceeded` | 値のチェックに必要な計算量が上限を超えています。 |
| `category_not_unique` | 1 つの系列に同じカテゴリが複数あります。 |
| `value_not_found` | 描画した値がデータにありません。CSV ファイルを添付するか、依頼文に値を書いてください。 |
| `label_not_in_request` | カテゴリのラベルが依頼文にありません。依頼文に各ラベルを書いてください。 |

<a id="check-columns"></a>

### 8. 描いた列が依頼と一致

描いた列とは、描画した値の出所である列です。検証器は、それを依頼文の列名と比べます。各列は、
その名前と管理者が登録した別名で認識します。本番環境では、日本語の短い形 (`年月` に対する `月`、
`月別` のような接尾辞付きも含む) も認識します。

- **本番環境。** 依頼文が列名を含む場合、描いた列をすべて含む必要があります。
- **デモ。** グラフは、依頼文にある列を別の列に置き換えてはいけません。

値が 2 つの列に同じように当てはまる場合、依頼文はそのどちらかの名前を含む必要があります。
タイトル、軸ラベル、凡例、カラーバーのラベルは、グラフが描いていない列を挙げてはいけません。
凡例が系列名として示す値の列は挙げてもかまいません。たとえば、各線が 1 つの地域を示す場合の
`Revenue by month and region` の `region` です。
グループごとの合計または平均では、別の種類の集計を挙げてもいけません。たとえば、合計のグラフに
`平均` と書くことです。グループごとの最小値と最大値は列そのものの値を描くため、この規則はそのラベルを
読みません。

| 理由 | 意味 |
|---|---|
| `column_not_requested` | グラフが依頼の列を置き換えたか、値が 2 つの列に当てはまります。 |
| `column_not_named` | 描いた列の名前が依頼にありません。 |
| `label_not_consistent` | ラベルが、グラフにない列または集計を挙げています。 |

<a id="check-attach"></a>

### 9. 返信に画像を添付

ブラウザでの実行で PNG 画像が 1 枚返り、Open WebUI がそれを返信と一緒に保存します。どちらかに
失敗した場合、検証器は画像を表示しません。

| 理由 | 意味 |
|---|---|
| `no_image` | ブラウザでの実行で PNG 画像が 1 枚だけ作られませんでした。 |
| `publish_failed` | Open WebUI が画像を添付できませんでした。 |

<a id="limits"></a>

## 上限

検証器は、次の上限を超える処理を行いません。

| 上限 | 値 | 対象 |
|---|---|---|
| `MAX_AXES` | 24 | 図の軸の数 |
| `MAX_CHILDREN` | 2,000 | 図のすべての軸にある部品の数 |
| `MAX_COORDINATES` | 20,000 | 図で描画した座標の数 |
| `MAX_TEXT` | 1,000 | 1 つのテキストの文字数 |
| `MAX_DESCRIPTION_BYTES` | 400,000 | 図の記述のバイト数 |
| `MAX_PNG_CHARACTERS` | 500,000 | PNG 画像の行の文字数 |
| `max_csv_bytes` | 8,000,000 | CSV ファイルのバイト数 |
| `max_csv_rows` | 100,000 | CSV ファイルのデータ行の数 |
| `max_csv_columns` | 128 | CSV ファイルの列の数 |
| `max_csv_cell_bytes` | 512 | CSV の 1 つのセルのバイト数 |
| `MAX_GROUPS` | 1,000 | グループごとの集計 1 つのグループ数 |
| `MAX_WORK` | 5,000,000 | 値の照合の作業量 |
| `MAX_RANGE` | 10,000 | 1 つの依頼文の範囲から得る数値の合計数 |
| `RPC_TIMEOUT_SECONDS` | 60 | ブラウザでの実行の秒数 |

## 検証器がチェックしない内容

- **プログラムは誠実であると信頼しています。** プログラムはすべてのチェックの前に、検証器の
  読み取り処理と同じ Python のサンドボックスで実行されます。読み取り処理を欺くように書いた
  プログラムは、それができます。サンドボックスは、Open WebUI の他のコード実行と同じく、
  添付ファイルを読み取り、ブラウザのネットワークにアクセスできます。
- **グラフ上の文字。** 検証器は、`text`、`annotate`、`bar_label` のラベルのような自由な文字を
  グラフの下に一覧にします。その文字の内容は判断しません。
- **モデルの注記。** 依頼がグラフのルールに反する内容を求めた場合、フィルターはモデルに、ルールに従い、
  その食い違いを注記で述べるよう求めます。返信では、判定の下の `モデルの注記:` に続けて注記が表示されます。検証器は注記を確認せず、注記によって判定が
  変わることはありません。モデルが食い違いを述べないこともあります。管理者は注記を無効にできます。
- **意図。** 検証器は、値がデータから来ていることをチェックします。グラフが意図した量を示して
  いることはチェックしません。依頼文の列名が、意図との唯一のつながりです。
- **前のメッセージ。** 前のメッセージにある列名は、後のメッセージで別の列を依頼した後も数えます。
  そのため、前の列を使い続けるグラフも列のチェックに合格することがあります。
- **その他の計算。** 検証器が認める計算は、上の表の計算だけです。プログラムが値をどう計算したかは
  確認しません。丸めた値、移動平均、対数、拡大したマーカーの大きさは、同じ数値がデータ、またはその
  認められた計算結果にある場合を除き、グラフを止めます。
- **画像そのもの。** 検証器は、ブラウザ、matplotlib、画像のピクセルを信頼しています。
