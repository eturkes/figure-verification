# 図の検証: 検証器がチェックする内容

このリファレンスでは、図の検証器が Open WebUI で実行するチェックについて説明します。`main`
ブランチの現在のリリースが対象です。グラフの返信の下にある **チェック項目を表示** の各行は、
ここにある対応する節にリンクしています。英語版は [verification.md](verification.md) をお読みください。

## 検証済みの図の意味

言語モデルが、matplotlib でグラフを描く Python のプログラムを書きます。ブラウザは、そのプログラムを
変更せずに Open WebUI の Python サンドボックス (Pyodide) で実行します。その後、検証器が完成した
図を読み取り、グラフを表示してよいかを判断します。すべてのチェックに合格した場合に限り、返信に
グラフと `Figure verification passed` が表示されます。それ以外の場合、返信には
`Figure verification failed, no image produced` とその理由が表示されます。

検証器は、次の 3 種類の保証を提供します。

1. **完全性。** 図のすべての部品は、検証器がチェックする決まった種類の部品に含まれます。すべての
   部品は決まった規則に従います。たとえば、棒はゼロから始まり、反転した軸はありません。
2. **出所。** CSV ファイルを添付するか依頼文に数値を書いた場合、描画したすべての値はそのデータに
   あります。データに見つからない値があると、グラフは表示されません。
3. **解釈。** 合格した返信では、描画した各値の出所を平易な言葉で示します。ファイル、列、
   グループごとの集計、行数です。

検証器は、グラフが質問に答えていることは保証しません。グラフが正しい値を示していても、意図とは
別の量である場合があります。たとえば、平均が必要なのに合計を示している場合です。グラフの下の
解釈を読んで、検証器がチェックした内容を確認してください。

すべての判断は決まった規則に従います。検証器はモデルも推測も使いません。ブラウザ、Pyodide の
サンドボックス、matplotlib、画像のピクセルは信頼しており、検証はしません。

## 値の出所

検証器は、描画した値をあなたが用意したデータと比べます。

- **添付した CSV ファイル。** 描画した各値は、1 つの列の値、または 1 つの列のグループごとの集計
  である必要があります。集計は合計、平均、最小値、最大値、行数のいずれかです。グラフは一部の行
  だけを描くこともできます。その場合、返信は描いた件数を示します (たとえば `6 件中 2 件を描画`)。
- **依頼文の数値。** 描画した各値は、依頼文にある数値である必要があります。検証器は、入力した
  範囲を両端の間のすべての整数に展開します。`1 through 10`、`1 to 10`、`1–10`、`1〜10`、
  `1から10まで` は、いずれも 1 から 10 までの数値になります。`1-10` のような通常のハイフンは
  範囲になりません。日付や負の数がハイフンを使うためです。カテゴリのラベルも依頼文にある必要が
  あります。
- **データなし。** ファイルを添付せず、数値も書かない場合、検証器はグラフの完全性だけを
  チェックします。返信にもそのことが示されます。

両方の出所がある場合、各値はどちらの出所から来てもかまいません。たとえば、ファイルの合計を描き、
入力した数値の位置に目標線を引くことができます。

検証器は、`pandas.read_csv` と同じ方式で CSV ファイルを読み取ります。値は数値誤差を認めずに
完全に一致するかを比べます。ファイルの 1 行は、描画した値の 1 つだけを裏付けます。

特別な場合:

- **凡例が名前を付けた系列。** 凡例が列の値で系列に名前を付けた場合 (たとえば `city` 列の
  `London`)、その系列はその値を持つ行から作られている必要があります。
- **基準線と帯。** `axhline`、`axvline`、`axhspan`、`axvspan` の各値は、ゼロ、依頼文の数値、
  数値の列の値、または列全体の集計のいずれかである必要があります。
- **マーカーの色と大きさ。** カラーバーや凡例が散布図のマーカーの色や大きさを示す場合、その値も
  描画した値として扱います。各値は、そのマーカーと同じ行またはグループから来ている必要があります。
- **円グラフのラベル。** 検証器は、各扇形のラベルをグラフに表示されたとおりに読み取ります。

## 「チェック項目を表示」の見方

**チェック項目を表示** は、9 つのチェックを実行する順に一覧にします。各行は次の 3 つの状態の
いずれかを示します。

- ✓ **合格**: チェックが完了しました。
- ✗ **不合格**: このチェックで図が止まりました。行に理由が表示されます。
- – **未実施**: 前のチェックが不合格だったため、このチェックは実施していません。

行をクリックすると開きます。開いた行には、チェックの内容、不合格の理由、このリファレンスへの
リンクが表示されます。最初の行と不合格の行には、モデルのプログラムも表示されます。不合格の行では、
不合格になった部分を描いた行、またはその呼び出しを行った行に印が付きます。たとえば、棒を切り取った
`plt.ylim` の呼び出しです。そのような行がない不合格では、印のないプログラムが表示されます。

一覧には、モデルが送ったとおりのプログラムが表示されます。プログラムが持つ任意の文字列が含まれる
場合があります。たとえば、ファイル名や依頼文から写した語です。制御文字のように見えない文字は、
見える記号で表示されます。

## チェック

<a id="check-program"></a>

### 1. モデルからグラフのプログラムを受信

モデルは、グラフ用のツールを呼び出して 1 つの Python のプログラムを送る必要があります。返信の
文章として書いたプログラムはグラフになりません。図を作れるのは、ツールで送ったプログラムだけです。
1 つの返信でモデルがツールを複数回呼び出した場合、検証器は最後のプログラムをチェックします。

| 理由 | 意味 |
|---|---|
| `no_tool_call` | モデルからグラフのプログラムが届きませんでした。 |
| `no_user` | サインインしているユーザーがいません。 |

<a id="check-run"></a>

### 2. ブラウザでプログラムを実行

ブラウザは、モデルのプログラムを変更せずに Open WebUI のサンドボックス (Pyodide) で実行します。
検証器が加えるのは外側の処理だけです。完成した図を記録し、PNG 画像を 1 枚保存します。正しい Python ではないプログラムは、Python 自体が拒否します。プログラムが読み込めるのは、numpy、pandas、
matplotlib と Python の標準ライブラリです。検証器は、プログラムの実行前にこの 3 つのパッケージを読み込みます。プログラムまたは添付ファイルに日本語が
含まれる場合、検証器は Open WebUI の日本語フォントもプログラムと一緒に送ります。プログラムの
実行中は、チャットのタブを開いたままにしてください。

| 理由 | 意味 |
|---|---|
| `no_browser` | プログラムを実行できるブラウザのセッションがありません。 |
| `browser_timeout` | ブラウザが 60 秒以内に応答しませんでした。 |
| `browser_error` | ブラウザの呼び出しに失敗しました。 |
| `browser_no_answer` | チャットのタブが応答しませんでした。タブを開いたままにして、もう一度試してください。 |
| `reply_malformed` | ブラウザの応答の形式が不明です。 |
| `sandbox_unavailable` | Pyodide を読み込めません。このサイトの広告ブロッカーをオフにしてください。 |
| `sandbox_error` | ブラウザの実行環境がエラーを報告しました。 |
| `no_description` | ブラウザが描画した図を報告しませんでした。 |
| `program_syntax_error` | プログラムが正しい Python ではありません。 |
| `program_error` | プログラムがエラーで停止しました。 |
| `module_not_available` | プログラムが、サンドボックスにないモジュールを読み込んでいます。 |
| `figure_too_large` | 図が大きすぎるため、チェックできません。 |

<a id="check-figure"></a>

### 3. 図を 1 つ描画

プログラムは matplotlib の図をちょうど 1 つ描く必要があります。pandas のグラフも matplotlib の図です。Open WebUI 0.10.2 の Pyodide には seaborn がないため、seaborn を使うプログラムは読み込みの時点で止まります。1 つの図には、`plt.subplots` で作った複数のパネルを入れられます。使用できる
フォントで、図のすべての文字を描ける必要があります。

| 理由 | 意味 |
|---|---|
| `no_figure` | プログラムが matplotlib の図を描いていません。 |
| `multiple_figures` | プログラムが複数の図を描きました。 |
| `glyph_missing` | 図に、使用できるフォントで描けない文字があります。 |

<a id="check-parts"></a>

### 4. 検証器がチェックできる部品だけを使用

図の各部品は、検証器がチェックできる種類である必要があります。各パネルは通常の軸を使う必要が
あります。検証器は各パネルを個別にチェックします。チェックできる部品は次のとおりです。

| 部品 | 作り方 |
|---|---|
| 折れ線 | `plot`、`step` |
| 点 | `scatter` |
| 棒 | `bar`、`barh`、グループ化した棒と積み上げた棒 |
| ヒストグラム | 塗りつぶした棒と 1 つのデータセットの `hist` |
| 円 | `pie` とそのラベル |
| 面 | `fill_between`、`stackplot` |
| 基準線と帯 | `axhline`、`axvline`、`axhspan`、`axvspan` |
| テキスト | タイトル、軸ラベル、凡例、目盛りのラベル、`text`、`annotate`、`bar_label` |

それ以外の部品があると、図は止まります。たとえば、エラーバー、箱ひげ図、等高線、プログラムが
自分で追加した図形です。画像、極座標や 3D の軸、挿入図、2 つ目の y 軸、重なるパネルでも図は
止まります。カラーバーを使えるのは、散布図の色を示す場合だけです。

| 理由 | 意味 |
|---|---|
| `raster_image` | 図に画像が含まれています。検証器は画像をチェックできません。 |
| `axes_not_judged` | 図に、検証器がチェックできない軸 (極座標、3D、挿入図など) があります。 |
| `axes_twin` | 1 つのパネルに 2 つの軸があります (2 つ目の y 軸など)。 |
| `axes_overlap` | 2 つのパネルが重なっています。 |
| `artist_not_judged` | 図に、検証器がチェックできないグラフ要素があります。 |
| `no_data` | データを表示していないパネルがあります。 |

<a id="check-axes"></a>

### 5. 正しい軸

各軸はデータを正しく示す必要があります。

- **データ座標。** 各部品は、軸上のデータの値の位置にあります。
- **線形の目盛り。** 軸は線形です。対数軸は、軸ラベルかパネルのタイトルに `log`、
  `logarithmic`、`対数` のいずれかがある場合に限り認めます。それ以外の目盛りでは図は止まります。
- **反転した軸なし。** 値は y 軸では上へ、x 軸では右へ増えます。
- **棒、ヒストグラム、面の値の軸にゼロ。** これらのグラフの値の軸はゼロを含みます。棒の長さが
  値を示すためです。折れ線と散布図は、データに合わせて拡大できます。
- **正しい目盛りラベル。** 表示されている各目盛りのラベルは、その位置の値を示します。カテゴリの
  軸はカテゴリを、日付の軸は日付を示します。
- **範囲外のデータ点なし。** 描画したすべての点、棒の端、基準線は、軸の範囲の中にあります。

| 理由 | 意味 |
|---|---|
| `mark_not_in_data` | データの値の位置にない部品があります。 |
| `scale_not_linear` | 線形でない軸があり、対数と示すラベルがありません。 |
| `axis_inverted` | 反転している軸があります。 |
| `zero_not_in_limits` | 棒グラフ、ヒストグラム、面グラフの値の軸にゼロが含まれていません。 |
| `tick_label_mismatch` | 目盛りのラベルが、その位置の値を示していません。 |
| `point_clipped` | 軸の範囲の外にあるデータ点があります。 |

<a id="check-marks"></a>

### 6. 正しいグラフ要素

各部品は値を正しく示す必要があります。

- **見える値。** すべての部品とパネルは表示されており、描画した値に欠損値や無限大はありません。
  部品が受け取ったのに表示しない点があると、図は止まります。
- **ゼロから始まる棒。** 各棒はゼロから始まるか、積み上げの中で別の棒の上から始まります。
- **重ならない棒。** グループ化した棒は横に並びます。
- **正しいヒストグラム。** ヒストグラムの棒は、ビンごとのデータの度数または密度を示します。
- **全体がそろった円。** 円グラフの扇形は円を満たし、各扇形は合計に対する割合を示します。
- **ゼロから始まる面。** 各面はゼロから始まるか、積み上げの中で別の面の上から始まります。
- **順序どおりの折れ線。** 折れ線の x の値は一方向に進みます。
- **説明のある大きさと色。** マーカーの大きさや色が異なる場合、大きさの凡例、色の凡例、または
  カラーバーが必要です。
- **正しい凡例。** 凡例の各項目は、グラフの系列を示します。凡例のあるパネルに系列が 2 つ以上
  ある場合、凡例はすべての系列を示します。

| 理由 | 意味 |
|---|---|
| `mark_hidden` | 非表示のグラフ要素やパネル、または何も見えないグラフ要素があります。 |
| `value_not_finite` | 描画する値に欠損値や有限でない値があるか、点が欠落しています。 |
| `bar_not_from_zero` | ゼロから始まっていない棒があります。 |
| `bars_overlap` | 重なっている棒があります。 |
| `x_not_ordered` | 折れ線の x の値が順序どおりではありません。 |
| `hist_counts` | ヒストグラムの棒が、データの度数を示していません。 |
| `pie_not_whole` | 円グラフの扇形が、値の割合を示していません。 |
| `area_not_from_zero` | ゼロからも他の面からも始まっていない面があります。 |
| `marker_size_varies` | マーカーの大きさが異なりますが、大きさの凡例がありません。 |
| `marker_color_varies` | マーカーの色が異なりますが、カラーバーも色の凡例もありません。 |
| `legend_mismatch` | 凡例がグラフの系列を正しく示していません。 |

<a id="check-values"></a>

### 7. 描画した値があなたのデータにある

検証器は、[値の出所](#値の出所) のとおりに、描画した各値をあなたのデータと比べます。1 つの系列で
同じカテゴリを 2 回示すことはできません。一方の値がもう一方を隠すためです。

| 理由 | 意味 |
|---|---|
| `csv_too_large` | CSV ファイルが大きすぎます。 |
| `csv_not_parsable` | CSV ファイルを読み取れません。 |
| `work_budget_exceeded` | 値のチェックに必要な計算量が上限を超えています。 |
| `category_not_unique` | 1 つの系列に同じカテゴリが複数あります。 |
| `value_not_found` | 描画した値がデータにありません。CSV ファイルを添付するか、依頼文に値を書いてください。 |
| `label_not_in_request` | カテゴリのラベルが依頼文にありません。依頼文に各ラベルを書いてください。 |

<a id="check-columns"></a>

### 8. 描いた列が依頼と一致

描いた列とは、描画した値の出所である列です。検証器は、それを依頼文の列名と比べます。各列は、
その名前、日本語の短い形 (`年月` に対する `月`、`月別` のような接尾辞付きも含む)、管理者が
登録した別名で認識します。

- **本番環境。** 依頼文が列名を含む場合、描いた列をすべて含む必要があります。
- **デモ。** グラフは、依頼文にある列を別の列に置き換えてはいけません。

値が 2 つの列に同じように当てはまる場合、依頼文はそのどちらかの名前を含む必要があります。
タイトル、軸ラベル、凡例、カラーバーのラベルは、グラフが描いていない列を挙げてはいけません。
グループごとの集計では、別の種類の集計を挙げてもいけません。たとえば、合計のグラフに `平均` と
書くことです。

| 理由 | 意味 |
|---|---|
| `column_not_requested` | グラフが依頼の列を別の列に置き換えたか、値が 2 つの列に当てはまります。 |
| `column_not_named` | 描いた列の名前が依頼にありません。 |
| `label_not_consistent` | ラベルが、グラフにない列または集計を挙げています。 |

<a id="check-attach"></a>

### 9. 返信に画像を添付

ブラウザでの実行で PNG 画像が 1 枚返り、Open WebUI がそれを返信と一緒に保存します。どちらかに
失敗した場合、検証器は画像を表示しません。

| 理由 | 意味 |
|---|---|
| `no_image` | ブラウザでの実行で PNG 画像が 1 枚だけ作られませんでした。 |
| `publish_failed` | Open WebUI が画像を添付できませんでした。 |

<a id="limits"></a>

## 上限

検証器は、次の上限を超える処理を行いません。

| 上限 | 値 | 対象 |
|---|---|---|
| `MAX_AXES` | 24 | 図の軸の数 |
| `MAX_CHILDREN` | 2,000 | 図のすべての軸にある部品の数 |
| `MAX_COORDINATES` | 20,000 | 図で描画した座標の数 |
| `MAX_TEXT` | 1,000 | 1 つのテキストの文字数 |
| `MAX_DESCRIPTION_BYTES` | 400,000 | 図の記述のバイト数 |
| `MAX_PNG_CHARACTERS` | 500,000 | PNG 画像の行の文字数 |
| `max_csv_bytes` | 8,000,000 | CSV ファイルのバイト数 |
| `max_csv_rows` | 100,000 | CSV ファイルのデータ行の数 |
| `max_csv_columns` | 128 | CSV ファイルの列の数 |
| `max_csv_cell_bytes` | 512 | CSV の 1 つのセルのバイト数 |
| `MAX_GROUPS` | 1,000 | グループごとの集計 1 つのグループ数 |
| `MAX_WORK` | 5,000,000 | 値の照合の作業量 |
| `MAX_RANGE` | 10,000 | 入力した範囲 1 つの数値の数 |
| `RPC_TIMEOUT_SECONDS` | 60 | ブラウザでの実行の秒数 |

## 検証器がチェックしない内容

- **プログラムは誠実であると信頼しています。** プログラムはすべてのチェックの前に、検証器の
  読み取り処理と同じ Python のサンドボックスで実行されます。読み取り処理を欺くように書いた
  プログラムは、それができます。サンドボックスは、Open WebUI の他のコード実行と同じく、
  添付ファイルを読み取り、ブラウザのネットワークにアクセスできます。
- **グラフ上の文字。** 検証器は、`text`、`annotate`、`bar_label` のラベルのような自由な文字を
  グラフの下に一覧にします。その文字の内容は判断しません。
- **意図。** 検証器は、値がデータから来ていることをチェックします。グラフが意図した量を示して
  いることはチェックしません。依頼文の列名が、意図との唯一のつながりです。
- **計算した値。** 検証器は、描画した各値をデータの中で探します。プログラムがその値をどう計算したかは
  確認しません。プログラムが別の方法で計算した値は、同じ数値がデータにもある場合を除き、グラフを止めます。
  たとえば、累計、2 つの列の比率、拡大したマーカーの大きさです。
